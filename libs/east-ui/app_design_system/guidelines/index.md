# Guidelines

East is a visual, design-first system: no components ship as code from this
project. The prescription is the tokens (`tokens/`), these guidelines, and
the spec cards in `guidelines/cards/`.

- [component-rules](./guidelines/component-rules.md) — the compliance checklist
- [app-layout](./guidelines/app-layout.md) — shell, frame, app bar, sidebar, main, rail, commit bar, breakpoints
- [base-components](./guidelines/base-components.md) — buttons, keys, forms, collection density, chips, tags, the toolbar and slice rail, avatars, tables, absent values, status, overlays, grids and time, canvases, icons
- [charts](./guidelines/charts.md) — chrome, series colour, canonical shapes
- [component-review](./guidelines/component-review.md) — the protocol for reviewing one component from screenshots

## Spec cards

`guidelines/cards/` — token-only mocks at 1:1 (Shell anatomy and Main
layouts are schematic and say so), each ending in a mono annotation line
that starts with the production tag. Foundation cards: Colors, Type,
Foundations, App layout, then the foundation parts as each is specified.
Component spec cards (`Components · <Category>`) are written here by
component reviews.
