§2.6 Frame & trust

Patterns that frame a screen and earn the user's trust: navigation chrome, freshness indicators, provenance footers, audit timelines, permissioning, multi-party approvals, error surfaces, and the keyboard shortcut overlay. Status colour is always paired with an icon (§0.3).

2.6.1Header

Breadcrumb + title + meta + actions. level: "section" | "subsection" — there is no "page" level; east-ui doesn't own the page chrome, the host shell does. Rendered inside the host's content area.

2.6.2FreshnessChip

Coloured dot + label + optional pulse + timestamp. state: "ok" | "running" | "dirty" | "error". Pulses subtly when state is "running". Auto-injects paired icon per §0.3 to remain accessible without colour.

FreshnessChip.Root({ state, label, updatedAt?, details?, pulsing? })
state · ok Source / model is fresh

failed· 12m ago source disconnected· auth expired solver timeout· 60s

2.6.6AuditTrail

Timeline of committed patches — each entry self-describes its at, by, kind, patch, and optional reason. Reversible: onRevert synthesises the inverse via East.invertPatch — no separate undo state. Consecutive entries can be composed for "what changed in this window?" diffs.

2.6.11RosterGrid

Workforce-specific preset of AssignmentBoard (§2.5.9) with a built-in shift-kind palette (day / aft / night). Inherits the full assignment-board API; adds shiftColors: Record<string, string> for brand overrides. Pairs with UnassignedTray, ConflictAnnotator, and SupplyDemandView in a typical roster screen.

RosterGrid.Root({ rows, unassigned?, rules?, onAssign, onSelection?, legend? })
preset note RosterGrid is a thin wrapper — most styling comes from AssignmentBoard
★ Preset relationship. RosterGrid renders an AssignmentBoard with: rows = workers, columns = days, cells = shift assignments. The shift-kind palette is the default shiftColors; the legend is derived from shiftColors + the rules registry. See §2.5.9 AssignmentBoard for the full drag-drop / keyboard / conflict mechanics.
