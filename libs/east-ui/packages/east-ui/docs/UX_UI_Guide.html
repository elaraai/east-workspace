UX/UI guide

A visual reference for anyone building Elara AI interfaces. Framework-agnostic — it shows what the product should look and feel like, not how to wire it up. All design tokens are embedded in this file; copy what you need.

The guide is in three parts. Part 1 — Foundations covers the tokens and rules that apply everywhere. Part 2 — Marketing surface covers the public-facing site, decks, and CEO briefings. Part 3 — Product surface covers the analyst workspace itself: app shell, tables, charts, filters, keyboard, density. Marketing and Product share tokens but diverge sharply on density, motion, and voice — don't import a marketing pattern into the product, or vice versa.

If you find yourself reaching for a colour, weight, radius, or motion that isn't on this page, the answer is almost always no. Anti-patterns are shown beside correct usage so you can recognise them in flight — most off-brand work doesn't look obviously wrong, it looks almost right.

Part 1

Foundations

Tokens and rules that apply across every Elara surface — colour, type, spacing, surfaces, borders, buttons, forms, icons, motion, accessibility. Marketing and product both inherit from here.

01Brand foundations

Elara is enterprise-formal, mathematics-led, restrained. The product reads as confident and quietly technical — not playful, not loud, not consumer-y. Three rules carry the brand more than any other:

  • Restraint over expression. A near-monochrome palette of deep teal ink and cool neutrals does the work; accent colour appears in single, deliberate places.
  • Mathematical precision. Tight tracking on display type, conservative radii, exact spacing on a 4-pixel grid. Nothing approximate.
  • No decoration. Borders are structural, shadows are functional, motion is purposeful. If an element exists only to look nice, it should be removed.

03Typography

Two families, three jobs

  • DM Sans — display face. Headings (h1–h4), big numerals, hero copy. Tight tracking, semibold/bold.
  • Inter Tight — UI face. Everything else: body, labels, buttons, table cells, helper text.
  • JetBrains Mono — code, formulas, IDs, API tokens. Never for prose.

Rules that trip people up

  • Letter-spacing is negative on display. H1 −0.02em, H2 −0.015em, H3 −0.01em. Don't render display type at default tracking.
  • Letter-spacing is positive on the eyebrow. +0.12em, uppercased. Eyebrows label sections — never use them as decorative tags.
  • Body line-height is 1.625. Generous on purpose. Don't compress it to look "denser".
  • Headings sit at 1.25. Tight, but not crashed. Don't reduce below 1.2.
  • Sentence case for everything. Headings, buttons, labels, nav. The only Title-Cased phrases are proper concept names: Digital Twin, Reinforcement Learning.
  • Periods end marketing section headings. They turn a label into a statement. Skip the period in product UI labels.
  • No exclamation marks. No emoji. Anywhere.

Density

The system is comfortable, not compact. Defaults:

  • Card interior padding: 24 px.
  • Form field gap: 16–20 px.
  • Button hit area: 36 px tall minimum.
  • Table row height: 40–44 px.
  • Marketing section vertical rhythm: 80–120 px.
  • Container max-width: 1200 px.

DO / DON'T

  • DO stack content with explicit gap rather than per-element margins.
  • DO use gap: 24px for cards, gap: 16px for body, gap: 64px between marketing blocks.
  • DON'T crowd content. If two elements look squashed, the answer is more space, not a smaller font.
  • DON'T invent in-between values (10, 14, 18, 22, 28). Stick to the scale.

06Borders & corners

Borders

  • 1 px, solid, always. No 2 px decorative borders. No dashed except on file-drop targets.
  • Subtle (gray-200) — default for cards, table rows, dividers.
  • Strong (gray-300) — inputs, separators that need to register against bg-secondary.
  • Focus (brand-500) — only when an element receives keyboard focus.
  • Never coloured borders for decoration. A red border means error. A teal border means focus. Anything else is wrong.

Corner radii

Conservative. The default card is 8 px. The biggest you go is 16 px for dialogs.

07Buttons

Variants

Four roles. The label tells you the intent.

  • Solid (brand 500) — the one primary action on a screen. Two solid buttons next to each other = one is wrong.
  • Ink (brand 900) — the dual-CTA partner to solid. Used in marketing pairs.
  • Outline — secondary actions, less assertive.
  • Ghost — tertiary, low-stakes (Cancel, Dismiss).
  • Disabled — flat gray, muted text, no shadow.

Sizes

States — every button has all four

Hover · −1 step

Focus · 3 px ring

Hover darkens by exactly one brand step (500 → 600). Active scales to 0.98 and darkens further (→ 700). Focus shows a 3 px brand-tinted glow — never an outline.

DO / DON'T

  • DO keep one primary (solid) action per screen or section.
  • DO put icons before labels, with an 8 px gap.
  • DON'T stack two solid buttons. Pair solid + ink, or solid + outline.
  • DON'T use accent hues (purple, orange, green) for buttons.
  • DON'T add gradients, glows, inner shadows, or animated shimmers.
  • DON'T make buttons full-width unless inside a narrow form column on mobile.

09Iconography

Rules

  • System: a single line/solid icon family used consistently — Font Awesome, Lucide, or Phosphor are all acceptable. Pick one and don't mix.
  • Style: 1.5–2 px stroke or geometric solid. No filled-circle backgrounds, no duo-tone, no 3D, no skeuomorphic glyphs.
  • Sizes: 16 px inline · 20 px UI affordances · 24–32 px feature lead-ins.
  • Weight: Solid for status / feature bullets · Regular (or stroke) for toolbar actions.
  • Colour: fg-muted by default · brand-600 on hover · accent hue only in marketing concept-bullets.
  • No emoji. Anywhere. Replace 🚀 / ✨ / ✅ with an icon or remove.
  • Mathematical Unicode is welcome: → ← ↗ × · ≈ ∑. Reinforces the "mathematics" positioning.

10Motion

Durations

  • 120 ms — instant micro-interactions: button colour, hover.
  • 200 ms — default. Reveals, dismissals, dropdown open.
  • 360 ms — slow. Dialog open, page-level transitions, chart interpolations.

Easing

  • Out — cubic-bezier(0.16, 1, 0.3, 1). The default. Soft landing.
  • In-out — cubic-bezier(0.65, 0, 0.35, 1). Used on durations that need symmetry (slide-in dialogs).

Rules

  • Motion is purposeful and short. Fades, short translates (≤ 8 px), opacity. No bounces, springs, overshoot.
  • Never auto-play decorative motion (pulsing dots, drifting backgrounds, parallax).
  • Chart transitions use natural-curve interpolations, not stepped morphs.
  • Respect prefers-reduced-motion. Reveals should fade, not translate, when reduced motion is on.

11Accessibility

Elara is enterprise software. Accessibility isn't optional and it isn't a "phase 2". The rules below are the floor — WCAG 2.1 AA is the target.

Contrast

  • Body text on white: minimum 4.5:1. Defaults — fg-primary (#1a2626) on white = 14.2:1, fg-secondary (#4a5f5f) = 7.4:1. Both pass.
  • Body text on dark (brand-900): gray-100 = 14.8:1. Pass.
  • Don't drop secondary text below gray-500. Below that fails AA on white.
  • Disabled controls are exempt from contrast minimums but should still be visually unambiguous.

Hit targets

  • 44 × 44 px minimum for any tap target on touch devices. Default buttons (36 px tall) are fine on desktop; bump to 44+ on mobile.
  • Inline icon buttons need at least 8 px of clear space around them.

Focus

  • Every interactive element gets a visible focus ring. The 3 px brand-tinted box-shadow is the only acceptable treatment.
  • Don't outline: none without replacing it. The browser default is ugly; invisible is unusable.
  • Focus order matches reading order. Positive tabindex values are a bug.
  • Skip-link to main content on every full-page route.

Semantics

  • Use the right element. <button> for actions, <a> for navigation. A <div onClick> is a bug.
  • Headings are hierarchical — never skip levels for size. Style with classes, not tag choice.
  • Form fields pair with <label>. Helper and error text reference the field via aria-describedby.
  • Icon-only buttons need aria-label.

Reduced motion

  • Honour prefers-reduced-motion: reduce. Replace translate / scale animations with simple fades. Disable auto-playing transitions entirely.
  • Chart animations stay (they convey data) but skip entrance flourishes.

Colour as information

  • Never carry meaning in colour alone. Errors pair red border + red helper text. Status pairs the dot with a word.
  • Charts that rely on colour to distinguish series must also use shape, label, or pattern when there are more than three series.

13Imagery

Rules

  • Vector-only by default. Commissioned SVG illustrations carry the visual weight of the marketing site.
  • No stock photography of people. No team photos, no smiling office shots.
  • No film-grain, no warm tones. If a raster appears, it's monochrome or muted.
  • No background gradients as decoration. Flat white or flat brand-900 only.
  • No noise textures, no patterns, no hand-drawn sketches.

The one recurring motif

The Elara mark — a dotted-diamond / compass-rose composition of small ink dots — is the only geometric motif allowed as a decorative hint. Use sparingly: a corner mark on a hero, a quiet watermark, or the favicon. Don't redraw it. Don't recolour it. Don't add to it.

Product surface

20Filters & segmentation

The filter bar is how analysts query. Chips show what's applied; clicking opens an editor; an "+" trigger adds a new clause.

scenario=Procurement v3× regioninEU, NA× date=last 30 days + Add filter Showing 1,284 events

Specs

  • Chip: 26 px tall, 6 px radius, 1 px border, 5 × 10 padding. Three states — neutral (border-subtle), active (brand-500 outline + 6% brand fill), placeholder (dashed border, muted).
  • Anatomy: field name (muted) · operator (muted, italicised intent) · value (primary) · close × (muted, hover-darken).
  • Editor: popover anchored to the chip. Field selector → operator → value picker. ↵ commits, Esc reverts.
  • Compare-to mode: a second filter row, 50% opacity until populated, prefixed "compared to". Gives charts a built-in A/B treatment.
  • Date range: presets (24h / 7d / 30d / 90d / YTD) + custom + relative ("last N days"). Always show the resolved absolute range under the trigger.
  • Saved segment: a chip cluster you can name and pin. Pinned segments live in the left rail.

  • Empty: 13 px secondary text + a single primary link/action. No illustration unless the empty state is a first-run experience.
  • Error: red border on the frame, red title, neutral body, single retry link. Don't replace the frame with an error page — keep layout stable.
  • Live: pulsing brand-500 dot + "Live" label top-right. Newly arriving cells/bars flash at 35% brand-500 for 600 ms then settle.
