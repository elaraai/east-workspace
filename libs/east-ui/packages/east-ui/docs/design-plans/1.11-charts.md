# 1.11 — Charts (cross-cutting upgrades; retire `charts/bar-segment` and `charts/bar-list`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.11](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Cross-cutting upgrades on existing chart types — default `colorScale`, shared `ReferenceMarker` helper, retire `BarSegment` and `BarList` (moved to §1.7 display). Advanced chart types (Heatmap, Waterfall, Sankey, etc.) are **deferred**, not in scope.

**Type-shape convention note (README §Type-shape convention, 0-conventions §3.8).** Charts differ from other primitives: their "style"-adjacent fields (`xAxis`, `yAxis`, `tooltip`, `legend`, `margin`, `brush`, `grid`, `ReferenceLine|Dot|Area`, series definitions) are **compound functional configs**, not visual style. They stay on the main type even though they carry visual sub-fields internally. Chart-chrome-only visual presets — `colorScale`, `colorPalette`, and cross-chart style tokens like `fillOpacity` / `strokeWidth` / `curveType` / `barSize` / `barGap` / `radius` / `showDots` / `connectNulls` / `stackOffset` / `stacked` / `layout` — remain top-level on each chart's main type for this revision (charts have dozens of these and moving them all inside a single `style` bucket would sprawl the style struct and disrupt the existing Recharts-aligned call-site). A future **charts restructure** could introduce a small `style` struct for axis/grid chrome colours (`background`, `axisColor`, `gridColor`) — out of scope here. Explicitly document this deviation from the convention so §0.10 `check-contracts.ts` knows to allowlist every chart main type.

**Out of scope:** advanced chart types (deferred per gaps doc). Full `{ content, style }` restructure of chart types (deferred to a later plan).

## 3. Per-entry design

### 3.1 `colorScale` on every chart

```ts
// src/charts/types.ts
export const ColorScaleKindType = VariantType({
    categorical: NullType, sequential: NullType, diverging: NullType,
});

export const ColorScaleType = StructType({
    kind: ColorScaleKindType,
    palette: OptionType(StringType),         // "teal" | "ocean" | brand-defined
    categories: OptionType(ArrayType(StringType)),   // when categorical
    domain: OptionType(ArrayType(FloatType)),        // [min, max] when sequential
});
```

Each chart type adds `colorScale: OptionType(ColorScaleType)`. Precedence: `colorScale` > `colorPalette` > Chakra default.

**Dichromacy:** default palettes (`teal`, `warm`, `cool`) are pre-tested against deuteranopia/protanopia. See §0.3 contract.

### 3.2 `ReferenceMarker` shared helper

```ts
export const ReferenceMarkerType = StructType({
    position: VariantType({ x: NullType, y: NullType }),    // axis
    value: FloatType,
    label: OptionType(UIComponentType),
    labelPosition: OptionType(VariantType({ start: NullType, center: NullType, end: NullType })),
    style: OptionType(StructType({
        stroke: OptionType(StringType),
        strokeDasharray: OptionType(StringType),
        color: OptionType(StringType),
    })),
});
```

Existing `ChartReferenceLineType` / `ChartReferenceDotType` / `ChartReferenceAreaType` stay (existing chart APIs keep them); the new `ReferenceMarker` is a simpler shared shape for *target / threshold / P90* use cases that should look identical across chart types.

### 3.3 BarSegment / BarList deletion sequence

(Same sequence as §1.7 plan — reproduced here so the chart-plan implementer has the chain.)

1. Land `display/segmented-meter/` and `display/bar-strip/` per §1.7.

3. Remove from `east-ui/src/charts/` and `east-ui-components/src/charts/`.
4. Remove from `east-ui/src/component.ts` `UIComponentType`.
