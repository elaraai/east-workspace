# 2.7 — Cross-cutting helpers (`Format.*`, `LocaleProvider`, `Timezone`, `ColorScale`, `Provenance`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §2.7](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** The "not quite pattern, not quite primitive" helpers that every other pattern consumes: the `Format.*` namespace (currently buried in `charts/types.ts`), a `LocaleProvider` scope, a `Timezone` helper, a `ColorScale` helper with dichromacy-safe defaults, and the `Provenance` shared struct (its presentational forms `Provenance.Stamp` / `Provenance.Footer` are already specified in §2.1 / §2.6; this plan covers the shared struct and namespace exports).

**Type-shape convention note (README §Type-shape convention, 0-conventions §3.8).** These are **helper namespaces, not UIComponent primitives** — `Format.*` / `Timezone.*` / `ColorScale.*` return typed formatter / scale / timezone values, not `UIComponentType` expressions. `LocaleProvider` is a scope wrapper around children; it does not render a visual surface of its own. `Provenance` is a *data* shape (shared struct carrying model-version / updatedAt / sources / links) consumed by `Provenance.Stamp` (inline, §2.1) and `Provenance.Footer` (row, §2.6). The main/style split therefore **does not apply to this file's helpers directly**, but any pattern that consumes these helpers — `StatCard.info` trigger passing a `Provenance` struct, `LocaleProvider` wrapping a subtree — must itself follow the convention: content/config/behaviour on main, visual presets + colour slots inside the pattern's own `style` sub-struct. `LocaleProvider.Root(children, { locale, currency?, timezone? })` puts `locale` / `currency` / `timezone` on main (they're configuration of the provider scope, not visual choices).

**Out of scope:** the shared primitives `MetricDef`, `MetricChip`, `ChipRail`, `EditableChip`, `OptionList` — these live in the primitive layer per the gaps doc (§1.7 / §1.2 / §1.9) and are not re-specified here; this plan only notes the dependency graph.

## 3. Per-entry design

### 3.1 `Format.*` namespace — promoted from `charts/types.ts`

**East IR types (all pre-existing; restructured).**
```ts
// east-ui/src/format/types.ts
export const NumberFormatType = StructType({
    minimumFractionDigits: OptionType(IntegerType),
    maximumFractionDigits: OptionType(IntegerType),
    useGrouping: OptionType(BooleanType),
    notation: OptionType(VariantType({
        standard: NullType, scientific: NullType, engineering: NullType, compact: NullType,
    })),
});

export const CurrencyFormatType = StructType({
    currency: StringType,                                  // "AUD" | "USD" | ...
    currencyDisplay: OptionType(VariantType({
        symbol: NullType, "narrow-symbol": NullType, code: NullType, name: NullType,
    })),
    minimumFractionDigits: OptionType(IntegerType),
    maximumFractionDigits: OptionType(IntegerType),
    compactDisplay: OptionType(VariantType({ short: NullType, long: NullType })),
});

export const PercentFormatType = StructType({
    minimumFractionDigits: OptionType(IntegerType),
    maximumFractionDigits: OptionType(IntegerType),
    signDisplay: OptionType(VariantType({
        auto: NullType, always: NullType, exceptZero: NullType, never: NullType,
    })),
});

export const CompactFormatType = StructType({
    compactDisplay: VariantType({ short: NullType, long: NullType }),
    maximumFractionDigits: OptionType(IntegerType),
});

export const UnitFormatType = StructType({
    unit: StringType,                                      // e.g. "kilometer-per-hour"
    unitDisplay: OptionType(VariantType({
        short: NullType, narrow: NullType, long: NullType,
    })),
    minimumFractionDigits: OptionType(IntegerType),
    maximumFractionDigits: OptionType(IntegerType),
});

export const DateFormatType = StructType({
    dateStyle: OptionType(VariantType({
        full: NullType, long: NullType, medium: NullType, short: NullType,
    })),
    timezone: OptionType(StringType),                      // IANA zone
    calendar: OptionType(StringType),
});

export const TimeFormatType = StructType({
    timeStyle: OptionType(VariantType({
        full: NullType, long: NullType, medium: NullType, short: NullType,
    })),
    hour12: OptionType(BooleanType),
    timezone: OptionType(StringType),
});

export const DateTimeFormatType = StructType({
    dateStyle: OptionType(VariantType({ full, long, medium, short })),
    timeStyle: OptionType(VariantType({ full, long, medium, short })),
    hour12: OptionType(BooleanType),
    timezone: OptionType(StringType),
});

// NEW in this plan:
export const RelativeTimeFormatType = StructType({
    numeric: OptionType(VariantType({ always: NullType, auto: NullType })),
    style: OptionType(VariantType({ long: NullType, short: NullType, narrow: NullType })),
});

export const ListFormatType = StructType({
    type: OptionType(VariantType({
        conjunction: NullType,          // "a, b, and c"
        disjunction: NullType,          // "a, b, or c"
        unit: NullType,                 // "a, b, c" no conjunction word
    })),
    style: OptionType(VariantType({ long: NullType, short: NullType, narrow: NullType })),
});
```

**Namespace export (`east-ui/src/format/index.ts`):**
```ts
export const Format = {
    Number: (opts?: NumberFormatOpts) => /* returns an East format value */,
    Currency: (opts: { currency: string, ...CurrencyFormatOpts }) => ...,
    Percent: (opts?) => ...,
    Compact: (opts) => ...,
    Unit: (opts) => ...,
    Date: (opts?) => ...,
    Time: (opts?) => ...,
    DateTime: (opts?) => ...,
    RelativeTime: (opts?) => ...,
    List: (opts?) => ...,
    Types: {
        Number: NumberFormatType,
        Currency: CurrencyFormatType,
        Percent: PercentFormatType,
        Compact: CompactFormatType,
        Unit: UnitFormatType,
        Date: DateFormatType,
        Time: TimeFormatType,
        DateTime: DateTimeFormatType,
        RelativeTime: RelativeTimeFormatType,
        List: ListFormatType,
    },
} as const;

// A catch-all union type for anywhere the API accepts "some format":
export const FormatType = VariantType({
    Number: NumberFormatType,
    Currency: CurrencyFormatType,
    Percent: PercentFormatType,
    Compact: CompactFormatType,
    Unit: UnitFormatType,
    Date: DateFormatType,
    Time: TimeFormatType,
    DateTime: DateTimeFormatType,
    RelativeTime: RelativeTimeFormatType,
    List: ListFormatType,
});
```

**Back-compat.** `charts/types.ts` re-exports each format type from `format/types.ts` so existing chart IRs keep compiling. The re-exports are marked `@deprecated`; the IR itself is identical.

**Tests:**
- Every format type round-trips.
- Re-exports from `charts/types.ts` resolve to the same identity.
- `FormatType` discriminated union carries each variant.

**Examples:**
- `formatCurrencyAud` — `Format.Currency({ currency: "AUD", compactDisplay: "short" })`.
- `formatPercentSign` — `Format.Percent({ signDisplay: "exceptZero", maximumFractionDigits: 1 })`.
- `formatRelativeTime` — `Format.RelativeTime({ numeric: "auto" })`.
- `formatList` — `Format.List({ type: "conjunction" })` rendering `"apple, banana, and pear"`.

### 3.2 `LocaleProvider`

**East IR:**
```ts
export const LocaleProviderType = StructType({
    locale: StringType,                                    // "en-AU", "en-US", ...
    currency: OptionType(StringType),                      // default currency if unspecified downstream
    timezone: OptionType(StringType),                      // IANA zone
    body: UIComponentType,
});
```

**Factory.** `LocaleProvider.Root({ locale, currency?, timezone?, body })`.

**React renderer.** Wraps body in a React context providing `{ locale, currency, timezone }`. The renderer's format helpers (`toChakraNumeric`, `toChakraDateTime`, etc.) read from this context to resolve the `locale` argument to `Intl.*Format`. If no `LocaleProvider` wraps a surface, defaults come from `navigator.language`.

**Nesting.** Nested providers override outer ones for their subtree (scoped-stacked). Chakra's context stacking is sufficient.

**Tests:**
- Outer vs inner provider precedence.
- Default resolution via `navigator.language`.
- Timezone propagation to DateTime renderers.

**Examples:**
- `localeProviderAu` — en-AU wrapping a briefing page.
- `localeProviderNested` — outer en-AU, inner en-US.

### 3.3 `Timezone` helpers

**Pure TypeScript helpers (not East IR).**
```ts
// east-ui/src/format/timezone.ts
export const Timezone = {
    // Format a DateTime in a specific zone.
    format: (ts: Date | ExprType<DateTimeType>, opts?: {
        tz?: string,
        style?: "full" | "long" | "medium" | "short",
        locale?: string,
    }) => string /* or east-side StringType expression */,

    // Produce a paired { local, utc } struct for audit / provenance displays.
    pair: (ts: Date | ExprType<DateTimeType>, locale?: string) => { local: string, utc: string },

    // List of IANA zones (cached).
    list: () => string[],

    // Resolve the user's preferred zone (from LocaleProvider context or navigator).
    resolve: () => string,
} as const;
```

Used by `DateTimeInput`, `AuditTrail`, `Timeline`, `Provenance.Stamp`, `StatCard` timestamps. East-side access via a platform wrapper (separate helper: `Time.format` or similar) — defer that expression wrapper unless a consumer needs it in IR; TS helpers cover the renderer-side needs.

**Tests:**
- `format` respects DST boundaries.
- `pair` renders both zones consistently.
- `resolve` prefers context over navigator.

**Examples:**
- `timezoneFormat` — same Date rendered in three zones.
- `timezonePair` — audit-trail paired display "14:22 local · 03:22 UTC".

### 3.4 `ColorScale` helpers

**Pure TypeScript helpers — feed Chakra theme resolution at render time.**
```ts
// east-ui/src/format/color-scale.ts
export type CategoricalPalette = "teal" | "ocean" | "warm" | "cool" | "semantic" | string[];

export type SequentialPalette = "teal" | "ocean" | "warm" | "rose" | string;

export type DivergingPalette = "teal-rose" | "blue-red" | string;

export const ColorScale = {
    Categorical: (categories: string[], palette?: CategoricalPalette) => {
        // Returns a function: (category: string) => color
    },

    Sequential: (opts: { domain: [number, number], palette?: SequentialPalette }) => {
        // Returns (value: number) => color
    },

    Diverging: (opts: { domain: [number, number, number], palette?: DivergingPalette }) => {
        // Returns (value: number) => color
    },

    // Dichromacy-check: returns `true` if the palette is safe.
    dichromacySafe: (palette: string[] | string) => boolean,

    // Default palettes (constants):
    defaults: {
        categorical: ["teal", "ocean", "warm", "cool"] as const,
        sequential: ["teal", "ocean"] as const,
        diverging: ["teal-rose"] as const,
    },
} as const;

export const ColorScaleType = StructType({
    kind: VariantType({
        categorical: NullType, sequential: NullType, diverging: NullType,
    }),
    palette: OptionType(StringType),
    categories: OptionType(ArrayType(StringType)),
    domain: OptionType(ArrayType(FloatType)),
});
```

**Dichromacy-safe default palettes** are baked into Chakra theme tokens (not shipped as raw hex in east-ui); ColorScale helpers read those tokens. If a caller supplies a custom `palette: string[]`, `ColorScale.dichromacySafe(palette)` is a lint-time check (not enforced at runtime but surfaced in tests).

**Consumed by.** `Matrix`, `CalendarHeatmap`, `SegmentedMeter`, `BarStrip`, every chart.

**Tests:**
- Categorical scale maps known categories to stable colours.
- Sequential scale interpolates within domain.
- `dichromacySafe` flags palettes that fail deuteranopia or protanopia simulation.
- Default palettes all pass the safety check.

**Examples:**
- `colorScaleCategoricalStatus` — `["ok","warn","err","neutral"]`.
- `colorScaleSequentialDemand` — domain `[0, 100]`, palette `teal`.
- `colorScaleDivergingDelta` — domain `[-10, 0, 10]`, palette `teal-rose`.

## 4. Contract compliance

- **§0.1 States** — Helpers themselves have no states (they're value helpers). Consuming patterns own `state`.
- **§0.2 A11y** — `LocaleProvider` has no DOM of its own. Format helpers produce strings with correct locale ordering (RTL support is Chakra's job — we pass through). `Timezone.pair` renders both forms so SR users hear both.
- **§0.3 Colour / dichromacy** — `ColorScale` defaults are dichromacy-safe; `dichromacySafe` helper flags custom palettes.
- **§0.4 Responsive** — N/A.
- **§0.5 Hover intent** — N/A.
- **§0.8 Patches** — N/A (helpers don't emit state changes).

## 7. Open questions

1. **`Format.Types` shape.** Exposing all types under `Format.Types.*` vs flat exports. Both. Namespace for discoverability; individual exports for destructuring.
2. **`LocaleProvider` as an IR variant vs renderer-only context.** IR variant so serialised snapshots carry locale. Confirmed — the React context is the implementation, but the IR must record the provider scope. Already reflected in the plan.
3. **`Timezone` — expression-side wrapper.** Defer until a consumer needs `Timezone.format` inside an East function body. Renderer-side TS helpers cover the current demand.
4. **`ColorScale.dichromacySafe`** — run at build time or runtime? Runtime JS function (for tests); pre-bake default palette status into a constant so we don't recompute at render time.
5. **Currency formatting default digits.** `Format.Currency` doesn't set `minimumFractionDigits` by default — `Intl` picks per-currency (AUD → 2, JPY → 0). Leave it that way; authors can override.
6. **`Provenance` struct location.** Lives in `east-ui-patterns` because `Stamp` and `Footer` are patterns. If primitives end up needing it (unlikely), promote to `east-ui` — cheap move.
