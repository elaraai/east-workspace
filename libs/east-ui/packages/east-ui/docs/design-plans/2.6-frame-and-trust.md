# 2.6 — Frame & trust patterns

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §2.6](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Frame & trust patterns — cross-cutting concerns that run across every decision mode: header chrome (section-level, **not** app-level), freshness / provenance surfaces, permission gating, commit approval, error fallbacks, keyboard shortcuts overlay, and `ChangeSinceLastVisit` (patch-aware diff against a user's checkpoint).

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** content (`title`, `description`, `breadcrumb`, `meta`, `actions`, `label`, `updatedAt`, `details`, `events`, `by`, `kind`, `patch`, `reason`, `artifactLink`, `modelVersion`, `sources`, `links`, `summary`, `current`, `base`, `stateType`, `checkpointKey`, `requiredRoles`, `contact`, `required`, `signed`, `policyRef`, `inputRef`, `logsLink`, `groups`), state (`pulsing`, `state` on FreshnessChip, `visible`), config (`level`, `ageMs`, `threshold`, `autoRefreshAt`, `has`, `triggerKey`, `showIcon`), semantic classification (`status` / `kind` / `level` / `severity`), and behaviour (`onRefresh`, `onApprove`, `onRescind`, `onAllApproved`, `onRevert`, `onRetry`, `onContact`) on main. Visual presets (`level` on Header, `size`, `variant`, `density`) + colour slots in `style: OptionType(XxxStyleType)`.

**Out of scope:** App-level shell / top-bar / left-nav — host app owns viewport chrome per §0.4. `RosterGrid` lives in §2.5 (Configure → Decide preset).

## 3. Per-entry design

### 3.1 `Header` (section / subsection only — no `page` level)

```ts
export const HeaderLevelType = VariantType({
    section: NullType,         // top of a content area
    subsection: NullType,      // nested group
});

export const HeaderStyleType = StructType({
    titleColor: OptionType(StringType),
    descriptionColor: OptionType(StringType),
    metaColor: OptionType(StringType),
    borderColor: OptionType(StringType),
});

export const HeaderType = StructType({
    level: HeaderLevelType,
    breadcrumb: OptionType(UIComponentType),               // Breadcrumb component
    title: UIComponentType,
    description: OptionType(UIComponentType),
    meta: OptionType(UIComponentType),                     // DataList or MetricRail
    actions: OptionType(UIComponentType),                  // Button row
    style: OptionType(HeaderStyleType),
});
```

**Factory.** `Header.Root({ level, breadcrumb?, title, description?, meta?, actions?, style? })`.

**Renderer.** `section` level: larger heading (`textStyle: heading-lg`), optional breadcrumb above, description below, meta (DataList or MetricRail) to the right of title, actions far right, bottom hairline `borderColor`. `subsection` level: smaller heading (`heading-md`), no breadcrumb slot, no bottom hairline by default.

**Tests:** level styling; all slots render; responsive behaviour.

**Examples:** `headerSection` (Briefing §2 heading), `headerSubsection` (nested group), `headerWithMeta` ("scenario" meta chips).

### 3.4 `ChangeSinceLastVisit` (patch-typed)

```ts
export const ChangeSinceLastVisitStyleType = StructType({
    // inherits Banner
    newIndicatorColor: OptionType(StringType),
});

export const ChangeSinceLastVisitType = StructType({
    stateType: TypeType,
    current: ExprType,                                     // TState current value
    checkpointKey: StringType,                             // State.bind key
    summary: FunctionType(
        [ExprType /* PatchTypeOf<TState> */],
        UIComponentType,
    ),
    onCheckpoint: OptionType(FunctionType([], NullType)),  // "Mark as read"
    autoCheckpoint: OptionType(BooleanType),               // default false
    style: OptionType(ChangeSinceLastVisitStyleType),
});
```

**Factory.** `ChangeSinceLastVisit.Root<TState>({ stateType, current, checkpointKey, summary, onCheckpoint?, autoCheckpoint?, style? })`.

**Renderer.** On mount: reads checkpoint via `State.bind([TState], checkpointKey, current)` — if absent, seed with `current` and render nothing. If present and `!East.equals(checkpoint, current)`:
1. Compute patch = `East.diff(checkpoint, current)`.
2. Call `summary(patch)` to produce the banner body.
3. Render as `Banner` with status `info` + new-indicator chip.
4. "Mark as read" button: writes `current` into the checkpoint and fires `onCheckpoint`.
5. If `autoCheckpoint`, updates the checkpoint once the user scrolls past (mount-point is past the fold).

**Tests:**
- First-ever mount seeds checkpoint with current.
- Subsequent mount with different `current` fires summary with the correct patch.
- Mark-as-read updates the stored checkpoint.
- `autoCheckpoint` semantics (scroll trigger).

**Examples:** `changeSinceLastVisitAlerts` ("3 new alerts since you last looked"), `changeSinceLastVisitEmpty` (no changes → no banner).

### 3.6 `AuditTrail` (patch-typed)

```ts
export const AuditEventKindType = StringType;              // caller-defined ("commit"|"revert"|"approve" etc.)

export const AuditUserType = StructType({
    name: UIComponentType,
    avatar: OptionType(UIComponentType),                   // Avatar UIComp
});

export const AuditEventType = StructType({
    at: DateTimeType,
    by: OptionType(AuditUserType),
    kind: AuditEventKindType,
    description: UIComponentType,
    patch: ExprType,                                       // PatchTypeOf<TState>
    reason: OptionType(UIComponentType),
    artifactLink: OptionType(StringType),                  // href to committed artifact
});

export const AuditTrailStyleType = StructType({
    // inherits Timeline
    kindColor: OptionType(DictType(StringType, StringType)),  // per-kind tint
});

export const AuditTrailType = StructType({
    stateType: TypeType,
    events: ArrayType(AuditEventType),
    limit: OptionType(IntegerType),                        // default 20
    expandable: OptionType(BooleanType),                   // default true; "Show more"
    onRevert: OptionType(FunctionType([ExprType /* inverse patch */], NullType)),
    onInspect: OptionType(FunctionType([IntegerType /* event index */], NullType)),
    style: OptionType(AuditTrailStyleType),
});
```

**Factory.** `AuditTrail.Root<TState>({ stateType, events, limit?, expandable?, onRevert?, onInspect?, style? })`.

**Renderer.** `Timeline` (§1.9). Each event: `at` (timestamp, tz-aware) + avatar + `description` + kind badge (tinted via `kindColor.<kind>`). Expand row → shows `reason`, `artifactLink`, and a "Inspect diff" button (fires `onInspect` → typically opens a `DiffView` of `patch` against the snapshot-at-that-time).

Revert action: on each event, renders "Revert" if `onRevert` is supplied. Click computes `inverse = East.invertPatch(event.patch, stateType)` and calls `onRevert(inverse)`. Consumers wire this to their commit pipeline (standard strength with confirm).

Composing "between two events" support: selecting a range of events exposes a secondary action "Summarise changes" which composes `East.composePatch(selected[0..n].patch)` and opens a `DiffView`.

**Tests:**
- Revert produces the correct inverse patch.
- Range summarise composes correctly.
- Timeline renders events in chrono order (newest first by default).
- `expandable` shows/hides beyond `limit`.

**Examples:**
| Name | Description |
|---|---|
| `auditTrailBasic` | 5 events, no revert |
| `auditTrailWithRevert` | Revert on each entry |
| `auditTrailSummariseRange` | Select 3 events → summarise diff |
| `auditTrailManyEvents` | 50 events with expandable limit |
| `auditTrailBranded` | Custom per-kind tint |

### 3.8 `CommitApproval` / `MultiPartyCommit`

```ts
export const ApprovalRoleType = StructType({
    role: StringType,                                      // opaque role key
    label: UIComponentType,                                // display label
    approverCandidates: OptionType(ArrayType(StringType)), // user ids
});

export const ApprovalSignedType = StructType({
    role: StringType,
    by: AuditUserType,
    at: DateTimeType,
    note: OptionType(UIComponentType),
});

export const CommitApprovalStyleType = StructType({
    requiredColor: OptionType(StringType),
    signedColor: OptionType(StringType),
    pendingColor: OptionType(StringType),
    policyColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
});

export const CommitApprovalType = StructType({
    stateType: TypeType,
    base: ExprType,                                        // current TState
    patch: ExprType,                                       // PatchTypeOf<TState>
    required: ArrayType(ApprovalRoleType),
    signed: ArrayType(ApprovalSignedType),
    policyRef: OptionType(UIComponentType),                // link to policy
    onApprove: FunctionType([StringType /* role */, OptionType(StringType) /* note */], NullType),
    onRescind: OptionType(FunctionType([StringType /* role */], NullType)),
    onAllApproved: OptionType(FunctionType([ExprType /* patch */], NullType)),
    style: OptionType(CommitApprovalStyleType),
});
```

**Factory.** `CommitApproval.Root<TState>({ stateType, base, patch, required, signed, policyRef?, onApprove, onRescind?, onAllApproved?, style? })`.

**Renderer.** Two-section layout:
1. **Top:** `DiffView` of `{ base, after: East.applyPatch(base, patch) }` — approvers see exactly what they're signing.
2. **Bottom:** `Timeline` of required roles, each showing:
   - Signed roles: `signedColor` check + name + timestamp + note (collapsible).
   - Pending roles: `pendingColor` dot + role label + candidate list.
   - Approve / Rescind buttons per row for the current user (if authorised).
   - Policy link at footer in `policyColor`.

When `signed.length === required.length`, fires `onAllApproved(patch)` exactly once.

**Tests:**
- Sign flow marks role complete.
- Rescind removes signed entry.
- All approved fires exactly once.
- DiffView reflects pending patch.

**Examples:** `commitApprovalTwoRoles`, `commitApprovalAllSigned`, `commitApprovalWithNotes`, `commitApprovalBranded`.

## 4. Contract compliance

- **§0.1 States** — `AuditTrail`, `CommitApproval`, `ComputeError` each inherit `Card.state`. `StaleDataBanner` below threshold → no render (implicit empty state).
- **§0.2 A11y** —
  - `Header` uses semantic `<h1>`/`<h2>` per level.
  - `AuditTrail` Timeline items are focus-reachable; Revert button has `aria-label="Revert this commit"`.
  - `KeyboardShortcutsOverlay` trigger key is global (`window` listener — hosts must avoid collisions); Escape closes.
  - `AccessDeniedState` is announced as `role="status" aria-live="polite"`.
  - `CommitApproval` DiffView keyboard-navigable; Approve/Rescind buttons per-row labelled.
- **§0.3 Colour / dichromacy** — `FreshnessChip` state paired with icon. `AuditTrail` kind tints paired with kind label text.
- **§0.4 Responsive** — `Header` collapses action row to overflow menu under 480px. `AuditTrail` Timeline single-column under 768px. `CommitApproval` DiffView switches mode per §2.4 responsive rules.
- **§0.5 Hover intent** — `Provenance.Footer` per-source tooltips use `HoverIntentType`.
- **§0.8 Patches** — `ChangeSinceLastVisit` uses `East.diff`; `AuditTrail` holds patches per entry and uses `East.invertPatch` for revert + `East.composePatch` for range summaries; `CommitApproval` holds the pending patch and previews via `East.applyPatch`.

## 5. Acceptance criteria

- [ ] `Header` has no `page` level.
- [ ] `FreshnessChip` state animations respect `prefers-reduced-motion`.
- [ ] `StaleDataBanner` threshold gate: renders iff `ageMs > threshold`.
- [ ] `ChangeSinceLastVisit` seeds checkpoint on first mount; "Mark as read" resets it.
- [ ] `Provenance.Footer` per-source staleness flips colour at threshold.
- [ ] `AuditTrail.onRevert` receives `East.invertPatch(event.patch, stateType)`.
- [ ] `AuditTrail` range-summarise composes patches correctly.
- [ ] `CommitApproval` fires `onAllApproved(patch)` exactly once when all roles signed.
- [ ] `ComputeError` caught by `ErrorBoundary` with the thrown error surfaced.
- [ ] `KeyboardShortcutsOverlay` opens on `?` keydown; Escape closes.

## 7. Open questions

1. **`ChangeSinceLastVisit` checkpoint scope.** Global per-user vs per-route? `State.bind` is browser-local, so multiple users on the same machine share. Documented as "browser-local checkpoint"; server-side user-scoped persistence is the host's job.
2. **`AuditTrail` pagination.** 50+ events need proper pagination. Ship with `expandable + limit` for v1; add `Pagination` primitive integration later.
3. **`CommitApproval` policy-engine integration.** No opinion on the policy source — caller supplies `required` array. Consider a helper type `PolicyRule` later if two apps converge on a format.
4. **`KeyboardShortcutsOverlay` trigger-key conflicts.** `?` is a common form-input character. Overlay uses `Shift+?` (`?` requires Shift on US keyboards) to avoid conflicts. Document.
5. **`Header` actions overflow.** Collapse to an overflow menu by default? Yes under 480px. Above that, show up to 3 actions inline, rest in a menu.
6. **`AuditTrail` entry identity.** Do we need a stable `id` per entry? Yes — add `id: OptionType(StringType)` so revert callbacks can reference the correct entry if the ordering mutates. Update spec.
