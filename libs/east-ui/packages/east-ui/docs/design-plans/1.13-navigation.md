# 1.13 — Navigation (`Breadcrumb`, + new `NavList`, `TableOfContents`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.13](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Widen `Breadcrumb` labels to `UIComponentType` + colour escape hatches. Add two new primitives: `NavList` (grouped in-panel navigation; **not** an app-level sidebar — east-ui doesn't ship a shell) and `TableOfContents` (right-rail anchor navigation for long scrollable content). Apply the Type-shape convention (README §Type-shape convention, 0-conventions §3.8): content (`items`, `sections`, `separator` content element), state (`activeId`, `active`, `current`), config (`href`, `scrollContainer`, `offset`, `collapsible`, `defaultOpen`), and behaviour (`onClick`, `onSelect`) on main; visual presets (`variant`, `size`, `orientation`, `density`) + colour slots in `style`.
**Out of scope:** app-level shell / top-bar / left-nav — host app owns viewport chrome (§0.4).

## 3. Per-entry design

### 3.1 `Breadcrumb` — rich labels

**East IR type (`types.ts`):**
```ts
export const BreadcrumbVariantType = VariantType({ underline: NullType, plain: NullType });

export const BreadcrumbStyleType = StructType({
    // Visual presets
    variant: OptionType(BreadcrumbVariantType),
    size: OptionType(SizeType),
    // Colour slots
    linkColor: OptionType(StringType),
    currentColor: OptionType(StringType),
    separatorColor: OptionType(StringType),
    hoverColor: OptionType(StringType),
    background: OptionType(StringType),
});

export const BreadcrumbItemType = StructType({
    label: UIComponentType,                            // was StringType
    current: OptionType(BooleanType),
    href: OptionType(StringType),
    onClick: OptionType(FunctionType([], NullType)),
});

export const BreadcrumbType = StructType({
    // Content
    items: ArrayType(BreadcrumbItemType),
    separator: OptionType(UIComponentType),            // default "/"; allow icon — content slot
    // Visual
    style: OptionType(BreadcrumbStyleType),
});
```

**Factory:**
```ts
Breadcrumb.Root(items: Array<{ label: string | UIComp, current?, onClick?, href? }>, opts?)
Breadcrumb.Item({ label, current?, onClick?, href? })    // per-item factory (rare; items usually inline)
```
Factory coerces `label: string` → `Text.Root(s, { textStyle: "body-sm" })`.

**React renderer.** `toChakraBreadcrumb(value)` maps to `<Breadcrumb.Root>` → `<Breadcrumb.List>` → `<Breadcrumb.Item>` per item. `current` item → `<Breadcrumb.CurrentLink aria-current="page">`; others → `<Breadcrumb.Link>` (with `onClick` / `href`). Separator from `separator` (coerces default "/"). css hatches: `linkColor` on non-current links, `currentColor` on current, `separatorColor` on separators, `hoverColor` via `&:hover`.

**Tests:**
- `label: string` coerces to `Text.Root`.
- `label: UIComp` (e.g. `HStack([Icon, Text])`) passthrough.
- Exactly one item with `current: true` allowed (renderer asserts; multi-current is an author error — warn, render last).
- Each colour escape hatch surfaces on the right slot.
- Keyboard: Tab traverses links; Enter activates `onClick`; disabled `current` not focusable.

**Examples:**
| Name | Keywords | Mockup |
|---|---|---|
| `breadcrumbBasic` | breadcrumb, navigation | shift-optimiser top area |
| `breadcrumbWithIcons` | breadcrumb, icon | Home → "Scenarios" (with folder icon) → "Week 12" |
| `breadcrumbBranded` | breadcrumb, brand, color | Branded link color + accent separator |
| `breadcrumbWithBadge` | breadcrumb, badge | Current crumb "Draft · 3 pending" (Badge inline) |

**Migration.** Existing callers passing `label: string` keep working (coerced). Code reading `item.label` as plain string must switch to reading the IR value — list callers in `grep -r "breadcrumb.*label"`.

### 3.2 `NavList` (new — grouped panel nav)

**East IR type:**
```ts
export const NavListItemType = StructType({
    key: StringType,
    label: UIComponentType,
    icon: OptionType(IconType),
    badge: OptionType(UIComponentType),                // e.g. count chip, "New"
    active: OptionType(BooleanType),
    disabled: OptionType(BooleanType),
    href: OptionType(StringType),
    onClick: OptionType(FunctionType([], NullType)),
});

export const NavListSectionType = StructType({
    label: OptionType(UIComponentType),                // section heading; omit for ungrouped
    items: ArrayType(NavListItemType),
    collapsible: OptionType(BooleanType),              // default false
    defaultOpen: OptionType(BooleanType),              // default true
});

export const NavListStyleType = StructType({
    // Visual presets
    orientation: OptionType(OrientationType),          // default vertical
    size: OptionType(SizeType),
    density: OptionType(DensityType),                  // §1.1
    // Colour slots
    sectionLabelColor: OptionType(StringType),
    itemColor: OptionType(StringType),
    itemHoverBackground: OptionType(StringType),
    activeColor: OptionType(StringType),
    activeBackground: OptionType(StringType),
    activeIndicatorColor: OptionType(StringType),      // left-edge stripe
    badgeBackground: OptionType(StringType),
    badgeColor: OptionType(StringType),
    borderColor: OptionType(StringType),
    background: OptionType(StringType),
});

export const NavListType = StructType({
    // Content
    sections: ArrayType(NavListSectionType),
    // Behaviour
    onSelect: OptionType(FunctionType([StringType], NullType)),  // key
    // Visual
    style: OptionType(NavListStyleType),
});
```

**Factory:**
```ts
NavList.Root(sections: Array<{ label?, items, collapsible?, defaultOpen? }>, opts?)
NavList.Section({ label?, items, collapsible?, defaultOpen? })
NavList.Item({ key, label, icon?, badge?, active?, disabled?, href?, onClick? })
```

**React renderer.** Vertical: `<Stack gap="1">`; each section → `<Box>` with optional `<Heading textStyle="overline">` label; items as `<Button variant="ghost">` or `<Link>` (depending on `href`). Active item gets a left-edge `::before` pseudo 3px stripe (`activeIndicatorColor`) + `activeBackground`. Collapsible sections use Chakra `<Collapsible.Root>`. Keyboard: ArrowUp/Down traverse items, Home/End jump, Enter activates, Space toggles collapsible headings. A11y: renderer uses `<nav aria-label>` if a label is supplied at section level; items use `aria-current="page"` when active.

**Horizontal variant.** `orientation: "horizontal"` renders a `<HStack>` with a bottom-border active-indicator (stripe becomes the underline). Section labels become group dividers (vertical rule). Narrow subset — most NavLists are vertical.

**Density integration.** `density: "compact"` → 4px paddings, 28px min-height items; `comfortable` → 8px / 36px; `condensed` → 2px / 24px. `DensityType` cascade from context honored if not set explicitly.

**Tests:**
- Sections render section label as heading; items as list items.
- Exactly one `active: true` per NavList OR zero (no `active`) — multi-active warns.
- `collapsible` sections respond to Space on heading.
- `badge` renders aligned to right.
- `disabled` items unfocusable, `aria-disabled="true"`.
- Keyboard: ArrowUp/Down wrap; Home/End work.
- Each colour escape hatch lands on the right slot.

**Examples:**
| Name | Keywords | Description |
|---|---|---|
| `navListSubnavSettings` | navlist, subnav, settings | Inner settings nav: "General / Security / Integrations" group + "Advanced" collapsible group |
| `navListWithBadges` | navlist, badge, count | Inbox-style nav with per-item unread counts |
| `navListHorizontal` | navlist, horizontal, tabs-alt | Horizontal orientation as dense tab-list alternative |
| `navListBrandedActive` | navlist, brand, active | Uses `activeIndicatorColor` stripe in brand accent |
| `navListDensityCompact` | navlist, density | Same content at `comfortable` / `compact` / `condensed` |

**Showcase.** "Navigation" page, three-column layout with one NavList per column demonstrating different orientations and densities.

**Implementation notes.**
- Do **not** stylise as a full-height app-shell sidebar. The primitive is meant for a *panel region* (settings pane, in-drawer navigation, card sub-tabs). Documentation repeats this.
- React renderer uses `React.memo` with item-key identity comparison so re-renders from sibling state changes don't reflow the whole list.

### 3.3 `TableOfContents` (new — right-rail anchor nav)

**East IR type:**
```ts
export const TableOfContentsItemType = StructType({
    id: StringType,                                    // target element id
    label: UIComponentType,
    level: IntegerType,                                // 1 | 2 | 3; others clamped
});

export const TableOfContentsStyleType = StructType({
    itemColor: OptionType(StringType),
    activeColor: OptionType(StringType),
    activeIndicatorColor: OptionType(StringType),      // stripe / dot on active
    connectorColor: OptionType(StringType),            // vertical guide for nesting
    hoverColor: OptionType(StringType),
    background: OptionType(StringType),
});

export const TableOfContentsType = StructType({
    items: ArrayType(TableOfContentsItemType),
    activeId: OptionType(StringType),                  // controlled
    scrollContainer: OptionType(StringType),           // CSS selector; default window
    offset: OptionType(StringType),                    // scroll-margin-top
    onSelect: OptionType(FunctionType([StringType], NullType)),
    style: OptionType(TableOfContentsStyleType),
});
```

**Factory.** `TableOfContents.Root(items, opts?)`. `items` may be auto-derived from `<h2>` / `<h3>` in the body at render-time by a helper (`TableOfContents.fromDom(container, selectors?)`) — sugar; not an IR concept.

**React renderer.**
- Renders a `<nav aria-label="On this page">` with `<ol>` structure. Level 1 items are top-level; 2 indented by `16px`, 3 by `32px`. Nesting connector is a `::before` vertical line in `connectorColor`.
- Active tracking: if `activeId` is controlled, use it; else a React `IntersectionObserver` watches target elements and picks the topmost one whose `<1/2` line is in view.
- Click: `onSelect` fires; renderer also `scrollIntoView({ behavior, block: "start" })` (respects `prefers-reduced-motion` → `"auto"`).
- Active item gets an `::after` left-stripe (`activeIndicatorColor`) and `activeColor` on label.
- Keyboard: Tab traverses; Enter activates.

**A11y.** `aria-current="true"` on active item; list is an `<ol>` so screen readers announce position. Heading anchors must have `id` matching the item; renderer warns if any `id` is absent from DOM.

**Tests:**
- Level clamped to 1–3.
- `activeId` controlled wins over observer.
- `onSelect` fires on click; observer fires on scroll once target id crosses threshold.
- Nesting connectors render correctly for mixed-level item lists.
- Colour escape hatches.

**Examples:**
| Name | Keywords | Description |
|---|---|---|
| `tocBasic` | toc, anchor, nav | 5-item flat list |
| `tocNested` | toc, nested, hierarchy | Three-level nesting with connectors |
| `tocWithScrollContainer` | toc, scroll, container | Right-rail inside a scrollable card (uses `scrollContainer`) |
| `tocBrandedActive` | toc, brand | Uses `activeIndicatorColor` in brand accent |

**Showcase.** Pairs with a long-content card (e.g. "Audit trail reference") as the right column of a two-column split.

**Implementation notes.**
- The observer disconnects on unmount. Renderer creates one observer per `TableOfContents` instance.
- `offset` prevents sticky headers from obscuring scrolled-to sections (passes through as `scroll-margin-top` on the target elements — renderer sets this via inline style on target refs when they're added via React; otherwise the consumer must set it on their heading components).

## 4. Contract compliance

- **§0.1 States** — Breadcrumb/NavList have no loading state (they're navigation chrome; if the nav data itself is loading, parent renders `Skeleton`). TableOfContents renders nothing when `items` is empty (no `EmptyState` — it would be visual noise).
- **§0.2 A11y** — `<nav>` landmarks with `aria-label`; `aria-current="page"` / `"true"` semantics. Keyboard traversal for both NavList and TOC. Focus visible via `FocusStyleType`.
- **§0.3 Colour/dichromacy** — active state uses the indicator stripe *in addition to* colour, so dichromat users see the stripe. Stripe can be disabled via `activeIndicatorColor: "transparent"` only by explicit author choice.
- **§0.4 Responsive** — NavList collapsible sections default to open above 768px, collapsed under. TOC hides under 768px (small viewports don't have a right rail). Both read `DensityType`.
- **§0.5 Hover intent** — N/A (no hover-to-open primitives).
- **§0.8 Patches** — N/A (nav is read-mostly).

## 7. Open questions

1. **NavList header fill** — should collapsible section headings carry a chevron affordance on the left, right, or both? Chakra convention is right-aligned; match that.
2. **TOC auto-derivation** — `TableOfContents.fromDom` helper is convenient but imperative. Ship it? Yes, but as a TypeScript helper only (not East IR), with doc noting it must run after the content mounts.
3. **Mobile TOC** — spec says hide under 768px. Consider a collapsible floating button instead? Defer; out of v1 scope. Hosts can wrap in a `Drawer` if they need it.
