# 2.5 — Configure patterns (inc. AssignmentBoard suite + DraftPublishBar)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §2.5](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Configure-mode patterns (settings / assumptions / parameters / validation). Plus the AssignmentBoard suite — a generic drag-to-assign grid with tray + source library + conflict annotation — and the `DraftPublishBar` commit surface that composes multi-patch drafts. All edits flow through patches per §0.8.

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** content (`assumptions` / `value` / `fields` / `cells` / `columns` / `items` / `templates` / `grid` / `tray` / `presets` / `drafts` / `outcome` / `guardrails` / `actions` / `base` / `current` / `target` / `tolerance` / `supply` / `demand` / `whatIfs` / `elasticity` / `patch` / `reason`), typed patch config (`stateType`), config (`severity` / `recomputeTime` / `blockCommit` / `acceptsType` / `mode` / `grouped` / `format` / `columns` count / `rowLabels` / `syncAxis` / `gapIndicator` / `axis` / `validate`), state (`readOnly` / `activeId` / `allowCustom` / `state` on swap), behaviour (`onEdit` / `onAcknowledge` / `onSelect` / `onAssign` / `validateDrop` / `onClaim` / `onApplyBulk` / `onRespond` / `onPublish` / `onDiscard` / `onReviewDiff` / `onAssumptionEdit` / `onWhatIf` / `onPreset` / `onToggle` / `onRun`) on main. Visual presets (`density`, `variant`, `size`, `placement`, `emphasis`) + colour slots in `style: OptionType(XxxStyleType)`. Per-cell / per-item colours on their item sub-types stay on the item (data-level).

**Out of scope:** `ConstraintEditor` (deferred — most v1 apps use textarea + validation). `TimeSegmentedBar` / `ProportionBar` → `SegmentedMeter` (§1.7). `DayOfWeekStrip` → `CalendarHeatmap.Weekly`.

### 3.1 `AssumptionsBar`

**East IR type:**
```ts
export const AssumptionFieldType = StructType({
    key: StringType,
    label: UIComponentType,
    editable: OptionType(BooleanType),                     // default true
    format: OptionType(FormatType),
    hint: OptionType(UIComponentType),                     // tooltip body
});

export const AssumptionsBarStyleType = StructType({
    background: OptionType(StringType),
    chipBackground: OptionType(StringType),
    chipColor: OptionType(StringType),
    chipLabelColor: OptionType(StringType),
    chipBorderColor: OptionType(StringType),
    readOnlyChipBackground: OptionType(StringType),
});

export const AssumptionsBarType = StructType({
    stateType: TypeType,
    assumptions: ExprType,                                 // TAssumptions
    fields: ArrayType(AssumptionFieldType),
    onEdit: FunctionType([ExprType /* PatchTypeOf<TAssumptions> */], NullType),
    readOnly: OptionType(BooleanType),
    density: OptionType(DensityType),
    style: OptionType(AssumptionsBarStyleType),
});
```

**Factory.** `AssumptionsBar.Root<TAssumptions>({ stateType, assumptions, fields, onEdit, readOnly?, density?, style? })`.

**Renderer.** `ChipRail` of `EditableChip`s — one per field. Click opens `Popover` containing an inline `Field` (typed per the assumption value: `Integer`, `Float`, `String`, `DateRange`, etc.). On commit, compute `East.diff(currentAssumptions, editedAssumptions)` and emit via `onEdit(patch)`. Read-only chips render with `readOnlyChipBackground` and no click handler.

**Tests:**
- Each field type renders the right popover control.
- `onEdit` emits a patch matching the structural change.
- Multi-field edits can be staged by parent without committing.

**Examples:** `assumptionsBarScenario` (shift-optimiser assumption row), `assumptionsBarReadOnly`, `assumptionsBarBranded`.

**Factory.** `ParameterFormSection.Root<TParams>({ stateType, value, title, description?, fields, guardrails?, actions?, onEdit, state?, style? })`.

**Examples:** `parameterFormBasic`, `parameterFormWithGuardrail`, `parameterFormPermissionDenied`.

### 3.8 `AssignmentBoard`

```ts
// Grid interface — structural interface, not a variant.
// A CellAddressableComponent must expose cellId addressing for drop targets.
// Matrix and Planner both satisfy this interface.
export const CellAddressableComponentType = UIComponentType;  // opaque; renderer asserts at runtime

export const AssignmentBoardValidationType = StructType({
    allowed: BooleanType,
    reason: OptionType(UIComponentType),
});

export const AssignmentBoardModeType = VariantType({
    single: NullType,        // one item per cell
    stack: NullType,         // multiple items per cell
});

export const AssignmentBoardStyleType = StructType({
    gridBackground: OptionType(StringType),
    trayBackground: OptionType(StringType),
    dropTargetBackground: OptionType(StringType),
    dropTargetBorderColor: OptionType(StringType),
    dropTargetInvalidBackground: OptionType(StringType),
    dropTargetInvalidBorderColor: OptionType(StringType),
    ghostBackground: OptionType(StringType),
    conflictColor: OptionType(StringType),
});

export const AssignmentBoardType = StructType({
    stateType: TypeType,
    grid: CellAddressableComponentType,                    // Matrix or Planner
    tray: OptionType(UIComponentType),                     // UnassignedTray typically
    acceptsType: StringType,                               // DnD type key
    mode: OptionType(AssignmentBoardModeType),
    onAssign: FunctionType(
        [StringType /* opaque DnD key */, StringType /* cellId */],
        AssignmentBoardValidationType,
    ),                                                     // ALSO runs as validate
    commit: FunctionType(
        [StringType /* opaque DnD key */, StringType /* cellId */],
        ExprType /* PatchTypeOf<TBoard> */,
    ),
    onCommit: FunctionType([ExprType], NullType),
    conflicts: OptionType(UIComponentType),                // ConflictAnnotator recipe output
    legend: OptionType(UIComponentType),
    style: OptionType(AssignmentBoardStyleType),
});
```

**Factory.** `AssignmentBoard.Root<TBoard>({ stateType, grid, tray?, acceptsType, mode?, onAssign, commit, onCommit, conflicts?, legend?, style? })`.

**Renderer.** `Splitter` 2-panel (grid left, tray right) wrapped in `DnD.Context`. The grid renders its cells as `DnD.DropZone`s (addressed by `cellId`); draggable items come from `tray` or anywhere inside the context. Drop flow:
1. `onAssign(dndKey, cellId)` runs as validate. If `allowed: false`, drop state renders `dropTargetInvalidBackground` + tooltip `reason`. Drop is blocked.
2. If `allowed: true`, renderer calls `commit(dndKey, cellId)` → `Patch<TBoard>`; passes through to `onCommit(patch)`.

Keyboard parity (per §0.2): focus on a draggable, Space picks up, Tab through DropZones, Space drops. Invalid drops (keyboard) announce reason via live region.

**Tests:**
- Valid drop fires `commit` + `onCommit` with correct patch.
- Invalid drop is blocked (no patch emitted).
- Keyboard flow from tray to grid cell.
- Conflicts rendered via `conflicts` slot.

**Examples:** `assignmentBoardBasic` (3×3 grid, simple tray), `assignmentBoardWithConflicts`, `assignmentBoardStackMode`.

## 7. Open questions

1. **ValueMatrixEditor — explicit cell focus ring.** Default Chakra ring vs a custom one? Use `FocusStyleType.emphasis` for edited cells; keeps the focus-ring policy central.
2. **AssignmentBoard — grid typed interface.** `CellAddressableComponentType` is structural (opaque `UIComponentType`). Should it be a nominal TS interface as well? Yes — `CellAddressableComponent` TS interface on `grid` factories (Matrix, Planner) so authors get a compile-time signal.
3. **DraftPublishBar — draft serialisation.** Drafts typically live in `State.bind` as `Array<Patch<T>>`. The `drafts` prop is an `ExprType` so the renderer subscribes. Document the typical consumer pattern (bind via `State.bind`, pass through).
4. **CalendarHeatmap — month vs year layouts.** `columns: 7` is weekly; a caller supplying `columns: 30` gets a month strip. Year calendars (GitHub-style 53-week) are a preset worth shipping — add `CalendarHeatmap.Year` in a later pass.
5. **RosterGrid shift colours.** Defaults (day = warm, afternoon = teal, night = indigo) dichromacy-safe? Verify against deuteranopia/protanopia during theme review. Document override path via `style.shiftColors`.
6. **AssignmentBoard `mode: "stack"` render.** Multiple items per cell visualised as a mini-list inside the cell. Defer the visual polish; v1 renders them stacked with `gap: 2`. Revisit if it's cluttered.
