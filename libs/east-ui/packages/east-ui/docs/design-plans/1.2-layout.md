# 1.2 — Layout (`Box`, `Flex`, `Stack`, `Grid`, `Splitter`, `Separator`, + new `Sticky`, `ScrollArea`, `ChipRail`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.2](../COMPONENT_AND_PATTERN_GAPS.md) and `§2.7` for `ChipRail`.
**Scope:** Widen `Box`/`Flex`/`Stack` with position/z-index/shadow/transform/transition/cursor/animation/fontFamily/fontVariantNumeric fields; promote `Separator.label` to rich content; keep `Grid`/`Splitter` unchanged; add `Sticky`, `ScrollArea`, and the shared `ChipRail` primitive (used by `MetricRail`, `AssumptionsBar`, `FilterBar`, `LegendRail`). Apply the Type-shape convention (README §Type-shape convention, 0-conventions §3.8) to every new/modified component — content/state/behaviour on main, all visual in `style: OptionType(XxxStyleType)`.
**Out of scope:** the semantic-layer tokens themselves (§1.1). This plan consumes them.

## 3. Per-entry design

### 3.1 `Box` — widen

Add to `BoxStyleType`:
```ts
position: OptionType(PositionType),
top/right/bottom/left: OptionType(StringType),
zIndex: OptionType(IntegerType),   // prefer ElevationType for authors; ZIndexTokenType as escape hatch
boxShadow: OptionType(BoxShadowType),  // + raw string fallback via StringType union
transform: OptionType(StringType),
transition: OptionType(TransitionType),  // + raw string fallback
cursor: OptionType(CursorType),
opacity: OptionType(FloatType),
fontFamily: OptionType(FontFamilyType),  // inherits to children
fontVariantNumeric: OptionType(FontVariantNumericType),
animation: OptionType(AnimationPresetType),
```

**Renderer:** every new field maps to a Chakra `css={...}` key. `animation: "pulse"` invokes the shared keyframe from `east-ui-components/src/style/animation.ts`; honours `usePrefersReducedMotion()`.

**Tests:** one test per new field asserting the Option shape round-trips and renders a correct style string.

**Examples:**
- `boxSticky` — a header-row `Box` with `position: "sticky"`, `top: "0"`, scrolls its parent for ~5 rows.
- `boxElevated` — `Box` with `boxShadow: "md"` + `borderRadius: "md"`.
- `boxAnimated` — `Box` with `animation: "pulse"` + a status dot inside (to seed `Status` look).

### 3.2 `Flex`, `Stack` — same additions

Copy the Box field set where relevant. No new shapes.

### 3.3 `Grid.Item.area`

`OptionType(StringType)` referencing a named area from `templateAreas`. Shape already present; adding the `area` field on the per-item struct.

### 3.4 `Separator` — rich label + align (main/style split)

Separator becomes a main + style shape. `label` (content) on main; everything visual — orientation, variant, size, colour, align — inside `SeparatorStyleType`.

```ts
export const SeparatorAlignType = VariantType({
    start: NullType, center: NullType, end: NullType,
});

export const SeparatorStyleType = StructType({
    orientation: OptionType(OrientationType),
    variant: OptionType(SeparatorVariantType),     // solid | dashed | dotted
    size: OptionType(SizeType),
    color: OptionType(StringType),
    align: OptionType(SeparatorAlignType),
});

// Main variant (inline in component.ts, keeps the recursive `node` available):
Separator: StructType({
    label: OptionType(node),                       // rich content — string coerces to Text.Root at factory
    style: OptionType(SeparatorStyleType),
});
```

Renderer renders `label` inside the separator line with left/right hairlines calibrated to `style.align`.

**Migration:** existing callers of the form `Separator.Root({ orientation: "horizontal", variant: "solid", color: "…", label: "foo", align: "center" })` become `Separator.Root({ label: "foo", style: { orientation: "horizontal", variant: "solid", color: "…", align: "center" } })`. The factory may accept literal-union shorthands on style fields (e.g. `style.variant: "solid"`) for ergonomics.

**Example:**
- `separatorWithEyebrow` — mirrors the Nestle deck's `chain-divider` style: a horizontal separator with `style.align: "center"` and `label: Text.Root("Cross-phase decisions", { style: { textStyle: "label-sm", textTransform: "uppercase", color: "fg.muted" } })`. **Use semantic token colours; do not port raw `var(--ink)` values from the CSS.** (See `deck-v3.css` `.chain-divider` for visual target — line height/spacing only.)

### 3.5 `Sticky` (new)

Main = `{ content }` (the only non-visual field). Every positioning / boundary / colour field is visual and lives in `StickyStyleType`.

```ts
export const StickyBoundaryType = VariantType({
    parent: NullType, viewport: NullType,
});

export const StickyStyleType = StructType({
    offset: OptionType(StringType),                // "0", "12px", etc. — positioning
    boundary: OptionType(StickyBoundaryType),      // parent (nested-sticky) | viewport (fixed fallback)
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    shadowColor: OptionType(StringType),           // applied when stuck (IntersectionObserver boundary)
});

// Main variant (inline in component.ts):
Sticky: StructType({
    content: node,
    style: OptionType(StickyStyleType),
});
```

Factory: `Sticky.Root(content, { style? })`. Default `style.boundary = "parent"`, default `style.offset = "0"`.

Renderer: `<Box position="sticky" top={style?.offset ?? "0"} zIndex="sticky" css={...}>`. Chakra already has `zIndex` tokens for this. `style.boundary: "viewport"` falls back to `position: fixed` for browsers that don't honour nested sticky; flagged in the renderer.

**Tests:** shape, correct top / boundary, style escape hatches.

**Examples** (2):
| Export | Description |
|---|---|
| `stickyHeader` | A card with a sticky header that stays put while body scrolls |
| `stickySubnav` | Left-column `NavList` that sticks at `top: 0` while main content scrolls |

### 3.6 `ScrollArea` (new)

Radix-style. Cross-browser consistent scrollbar treatment. Main = `{ content }`; everything visual (orientation, scrollbar mode, colours) in `ScrollAreaStyleType`.

```ts
export const ScrollAreaOrientationType = VariantType({
    vertical: NullType, horizontal: NullType, both: NullType,
});
export const ScrollbarStyleType = VariantType({
    overlay: NullType, reserved: NullType,
});

export const ScrollAreaStyleType = StructType({
    orientation: OptionType(ScrollAreaOrientationType),
    scrollbarStyle: OptionType(ScrollbarStyleType),
    thumbColor: OptionType(StringType),
    trackColor: OptionType(StringType),
    background: OptionType(StringType),
});

// Main variant (inline in component.ts):
ScrollArea: StructType({
    content: node,
    style: OptionType(ScrollAreaStyleType),
});
```

Factory: `ScrollArea.Root(content, { style? })`.

**Renderer:** `@radix-ui/react-scroll-area`. Lazy-loaded on first use (code-split).

**Examples** (2):
| Export | Description |
|---|---|
| `scrollAreaDriverList` | Vertical scroll of a 40-item driver list inside a drawer-width container |
| `scrollAreaTableInDrawer` | A wide `Table` inside a narrow `Drawer`, horizontal + vertical scroll |

### 3.7 `ChipRail` (new, shared primitive for §2 patterns)

Main = `{ chips }` (the content array). Every visual preset — density, separator style, overflow strategy, colours — lives in `ChipRailStyleType`.

```ts
export const ChipRailSeparatorType = VariantType({
    line: NullType, dot: NullType, none: NullType,
});
export const ChipRailOverflowType = VariantType({
    wrap: NullType, menu: NullType,
});

export const ChipRailStyleType = StructType({
    density: OptionType(DensityType),              // visual preset (cascades through React context; per-component override)
    separator: OptionType(ChipRailSeparatorType),  // visual: line | dot | none
    overflow: OptionType(ChipRailOverflowType),    // visual-layout strategy: wrap | collapse-to-menu
    background: OptionType(StringType),
    separatorColor: OptionType(StringType),
    overflowTriggerColor: OptionType(StringType),
});

// Main variant (inline in component.ts):
ChipRail: StructType({
    chips: ArrayType(node),                        // each child is a Tag / Badge / EditableChip / MetricChip
    style: OptionType(ChipRailStyleType),
});
```

Factory: `ChipRail.Root(chips, { style? })`. Literal-union shorthand accepted on `style.separator` / `style.overflow` / `style.density` for ergonomics.

**Renderer:** `<Flex>` with `gap` from `style.density` (or the `DensityProvider` context fallback); separator renders as a thin `<Separator orientation="vertical">` or a `·` text per `style.separator`; `style.overflow: "menu"` places trailing chips in an overflow `<Menu>` when the container runs out of space (ResizeObserver-driven).

**Examples** (3):
| Export | Description |
|---|---|
| `chipRailBasic` | 6 `Tag` chips with line separators, `compact` density |
| `chipRailDots` | Same chips with `·` separators |
| `chipRailOverflow` | 20 chips in a narrow container — last few collapse into overflow `Menu` |

### 3.8 `Box.transition` raw-string guidance

Prefer `transition: TransitionType` (semantic preset). Raw string accepted but JSDoc-flagged as "escape hatch; prefer TransitionType for theme coherence."

### 3.9 `Box.cursor: help | not-allowed` pairing

Renderer emits matching `aria-disabled="true"` for `cursor: not-allowed` on any non-`<button>` element — otherwise cursor-only affordance violates §0.2. Test enforces via `keyboard.spec.tsx`.

## 5. Acceptance criteria

- [ ] Every new Box/Flex/Stack field round-trips through the IR.
- [ ] `Separator.label` accepts both `string` (coerced) and `UIComponentType`.
- [ ] `Separator` / `Sticky` / `ScrollArea` / `ChipRail` all follow the Type-shape convention: `{ content/items, style: OptionType(XxxStyleType) }` on main, every visual field inside the style struct.
- [ ] `Sticky`, `ScrollArea`, `ChipRail` registered in `UIComponentType` RecursiveType and pass shape tests.
- [ ] Renderers use theme tokens, not hard-coded pixel values, for shadows/radii/shadows/colours.
- [ ] `ScrollArea` lazy-loaded — bundle analyser shows it in a separate chunk.
- [ ] `style.overflow: "menu"` on ChipRail demonstrably collapses items on narrow containers (showcase test).
