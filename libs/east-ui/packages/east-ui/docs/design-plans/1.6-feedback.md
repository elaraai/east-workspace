# 1.6 — Feedback (Alert, Banner, Progress, ProgressCircle, Skeleton, Spinner, Status, Toast, EmptyState)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.6 Feedback](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Widen `Alert` and `Progress`; add seven new primitives (`Banner`, `ProgressCircle`, `Skeleton`, `Spinner`, `Status`, `Toast`, `EmptyState`); wire all visual props (including visual presets `variant`/`size`/`colorPalette` + `striped`/`animated` on Progress + `thickness`/`speed` on Spinner + `shape` on Skeleton) into a single `style: OptionType(XxxStyleType)` sub-struct per component per the Type-shape convention (README §Type-shape convention, 0-conventions §3.8); enforce §0.3 paired-icon contract on every semantic-status primitive.

**Main vs style:** `status` / `value` (semantic status classification), `title` / `description` / `body` / `label` / `actions` / `icon` (content), `closable` / `dismissible` / `pulsing` / `indeterminate` / `showValue` / `showValueText` / `showIcon` (wiring flags + state), `estimatedDuration` / `startedAt` / `duration` / `lines` / `count` / `fontSize` / `shape` (config/content), and every callback stay on main. `variant`, `size`, `colorPalette`, `thickness`, `speed`, `striped`, `animated`, `width`, `height` + all colour slots (`color`, `background`, `borderColor`, `iconColor`, `accentColor`, `dotColor`, `trackColor`, `fillColor`, `labelColor`, `shimmerColor`) go in `style`.

**Out of scope for this plan:** the patch-typing work in §0.8 is not exercised here (no commit-adjacent components in §1.6); `CommandPalette`, `InfoAffordance`, `Tour`, `CoachMark` live in §1.12 and have their own plan.

## 3. Per-entry design

### 3.1 `Alert`

**Mode tag:** generic feedback surface (not mode-specific).

**East IR type** (`src/feedback/alert/types.ts`):

```ts
export const AlertStatusType = VariantType({
    info: NullType, warning: NullType, success: NullType,
    error: NullType, neutral: NullType, // <-- NEW
});

export const AlertStyleType = StructType({
    variant: OptionType(AlertVariantType),    // solid | subtle | outline — visual preset
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    iconColor: OptionType(StringType),
});

export const AlertType = StructType({
    // Semantic classification (drives paired icon + palette) — content/semantic on main
    status: AlertStatusType,
    // Content
    title: OptionType(UIComponentType),       // was StringType
    description: OptionType(UIComponentType), // was StringType
    body: OptionType(ArrayType(UIComponentType)),   // NEW
    actions: OptionType(UIComponentType),     // NEW
    icon: OptionType(IconType),               // explicit override of the paired default
    // State / wiring
    closable: OptionType(BooleanType),        // NEW
    showIcon: OptionType(BooleanType),        // default true (Alert usually shows icon)
    // Behaviour
    onClose: OptionType(FunctionType([], NullType)), // NEW
    // Visual
    style: OptionType(AlertStyleType),
});
```

**Migration:** shipped `AlertType` has top-level `variant` — this plan moves it into `style` (visual preset). Call sites using `variant: "solid"` at the top level move to `style: { variant: "solid" }`.

**East factory** (`src/feedback/alert/index.ts`):

```ts
Alert.Root({
    status: "info" | "warning" | "success" | "error" | "neutral" | ExprType<AlertStatusType>,
    title?: string | ExprType<UIComponentType>,
    description?: string | ExprType<UIComponentType>,
    body?: Array<ExprType<UIComponentType>>,
    actions?: ExprType<UIComponentType>,
    closable?: boolean,
    onClose?: () => void,
    variant?: "solid" | "subtle" | "outline" | ExprType<AlertVariantType>,
    style?: AlertStyle,
});
```

**§0.3 paired-icon contract:** `Alert` auto-injects a semantic icon corresponding to `status` unless the caller passes `showIcon: false` via an internal flag (not a user-facing prop — Alert always shows an icon; only `Banner` / `Status` expose the opt-out). Icon mapping: `info → faCircleInfo`, `warning → faTriangleExclamation`, `success → faCircleCheck`, `error → faCircleXmark`, `neutral → faCircle`. Pairing is done in the **IR factory**, not the renderer, so every renderer inherits.

**React renderer** (`east-ui-components/src/feedback/alert/index.tsx`):

- Pure fn: `toChakraAlert(value: AlertValue): AlertRootProps` — maps `status` (+ `neutral → "info"` with a `data-tone="neutral"` marker), `variant`.
- Component: `EastChakraAlert({ value })` renders `<Alert.Root>` with `<Alert.Indicator />` (the paired icon — read from the IR, not inferred in React), `<Alert.Content>` with optional `<Alert.Title>`, `<Alert.Description>`, and any `body` children recursively rendered via `UIComponentRenderer`. `actions` renders into an end-of-row slot (Chakra v3 exposes `Alert.Actions` compound). `closable: true` adds a `<CloseButton />` that calls `onClose` if provided.
- Memo equality: `alertEqual = equalFor(Alert.Types.Alert)` (pattern already used in the existing renderer — keep it).

**Colour escape hatches** via `style` struct:

| `style` field | Chakra override |
|---|---|
| `color` | `<Alert.Root css={{ color }}>` |
| `background` | `<Alert.Root css={{ bg: background }}>` |
| `borderColor` | `<Alert.Root css={{ borderColor }}>` |
| `iconColor` | `<Alert.Indicator css={{ color: iconColor }}>` |

**Tests** (`test/feedback/alert.spec.ts` — add these to the existing file):

- `creates alert with body containing an input` — assert `body` array holds a `StringInput` variant.
- `creates alert with actions` — assert `actions` variant tag is `some`.
- `creates dismissible alert` — `closable: true`, `onClose` wired.
- `creates neutral-status alert` — `status.hasTag("neutral") === true`.
- `applies style overrides` — `style.color === "#7a3b2e"` round-trip.
- `a11y — alert has role="alert"` (assertion is about the IR representing the intent; renderer verified in component tests).

**Examples** (`test/feedback/alert.examples.ts`):

| Export | Keywords | Description | What it must show | Ref mockup |
|---|---|---|---|---|
| `alertBasic` *(existing)* | `Alert`, `status` | Info / warn / success / error side by side | No change | — |
| `alertEmbeddedInput` | `Alert`, `body`, `Input` | An alert with an embedded integer input and a button | The `n_trials = 0` warn alert from `shift-optimiser-mockup.html`: warn status, mono label "n_trials", a compact `Input.Integer` with `size: "xs"`, no decorative flourish beyond Chakra defaults | `shift-optimiser-mockup.html` lines ~1044–1053 (n_trials warn block) |
| `alertWithActions` | `Alert`, `actions`, `Button` | Warn alert with "Accept" + "Dismiss" buttons at the trailing end | Actions `HStack` with one ghost + one subtle button | — |
| `alertDismissible` | `Alert`, `closable`, `onClose` | Success alert that disappears on close click (wired via State.bind) | Demonstrates `State.bind` on a boolean, conditional render | — |
| `alertNeutral` | `Alert`, `neutral` | Neutral-status alert; shows that colour is muted and the paired icon is `faCircle` | Contrast with the other status colours | — |

**Showcase entry:** `App.tsx` "Feedback" card lists `alertEmbeddedInput`, `alertWithActions`, `alertDismissible`, `alertNeutral` alongside existing `alertBasic`.

**Implementation notes:**
- Don't render body children in a `<p>` — `Alert.Description` in Chakra v3 wraps in a `<div>`; when `body` contains form controls you must use Alert.Content + appended children below the description row.
- Keyboard: when `closable`, the close button must be focusable and trigger `onClose` on Enter / Space per §0.2.

**Migration:** Apps passing `title: string` — still accepted because `StringType` is assignable to `UIComponentType` via the `Text` variant at the factory boundary (factory wraps string args in `Text.Root`). Apps constructing the IR directly need to wrap strings; this is a known breaking move per §0.7.

### 3.2 `Banner`

**East IR type** (`src/feedback/banner/types.ts`):

```ts
export const BannerStyleType = StructType({
    variant: OptionType(AlertVariantType),        // solid | subtle | outline
    size: OptionType(SizeType),
    // Colour slots
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    iconColor: OptionType(StringType),
    accentColor: OptionType(StringType),          // the prominent left/top stripe
});

export const BannerType = StructType({
    // Semantic classification
    status: AlertStatusType,
    // Content
    title: UIComponentType,
    description: OptionType(UIComponentType),
    actions: OptionType(UIComponentType),
    icon: OptionType(IconType),                   // explicit override of the paired default
    // State / wiring
    dismissible: OptionType(BooleanType),
    showIcon: OptionType(BooleanType),
    // Behaviour
    onDismiss: OptionType(FunctionType([], NullType)),
    // Visual
    style: OptionType(BannerStyleType),
});
```

**East factory:** `Banner.Root({ status, title, description?, actions?, icon?, dismissible?, onDismiss?, style? })`.

**§0.3 paired-icon:** same status → icon map as `Alert`; caller overrides via `icon`.

**React renderer:** Chakra v3 has no dedicated `Banner` component. Compose from `Box` with:
- `display: flex`, full-width, `px={4} py={3}`, `bg` derived from `status` + `variant` (use the same semantic palette tokens Alert uses, not hard-coded colours — `fg.{status}`, `bg.{status}.subtle`).
- Left accent stripe: `borderLeftWidth="4px"`, `borderLeftColor="colorPalette.{status}.solid"` — overridable by `style.accentColor`.
- Icon (`<FontAwesomeIcon>`), title (bold), description (muted), trailing actions slot, trailing `<CloseButton />` when dismissible.
- Memo equality: `equalFor(Banner.Types.Banner)`.

**Tests** (`test/feedback/banner.spec.ts`):

- Shape tests for each field.
- Default icon injected per status.
- `icon` override wins over default.
- `dismissible` without `onDismiss` still renders (renders the button but it no-ops).
- Style escape hatches round-trip.

**Examples** (`test/feedback/banner.examples.ts`):

| Export | Keywords | Description | What it must show |
|---|---|---|---|
| `bannerStaleData` | `Banner`, `warning`, `stale` | "Data last refreshed 48m ago — refresh" warning banner with a "Refresh" action | Mirrors §2.6 `StaleDataBanner` usage |
| `bannerFrozenScenario` | `Banner`, `info`, `scenario` | "You're viewing a frozen scenario — editing is disabled" info banner | No actions; `dismissible: false` |
| `bannerRunWarnings` | `Banner`, `warning`, `actions` | "3 warnings on this run — review" with "Review" action | Shows how patterns compose warnings |
| `bannerDismissible` | `Banner`, `dismissible` | Banner with visible close button, wired to `State.bind` | Demonstrates dismissal |

**Showcase:** new "Banner" card on the Feedback row of `App.tsx`.

**Implementation notes:**
- Width: Banner fills its parent (`width="100%"`). Responsive: description wraps; on narrow containers (< 480 px) title + description stack over actions.
- A11y: `role="status"` for info/success/neutral, `role="alert"` for warning/error (Chakra's Alert does the same — mirror it).
- Animation: if the host has `prefers-reduced-motion: reduce`, skip the slide-in enter animation; IR carries no animation flag, renderer reads user pref per §0.2.

**Reference mockup:** no direct match in the two mockups — authored from first principles per §1.6 in gaps doc. Nestle briefing's red "conn-band" style offers a visual ceiling for the solid variant but don't copy it.

### 3.3 `Progress` (widen)

**East IR type changes:**

Shipped `ProgressType` has `colorPalette`/`size`/`variant`/`striped`/`animated` at top level. These are all visual presets (style). The existing `label`/`valueText` are content (main). Add `indeterminate`/`showValue`/`estimatedDuration`/`startedAt` to main.

```ts
export const ProgressStyleType = StructType({
    variant: OptionType(ProgressVariantType),     // outline | subtle
    colorPalette: OptionType(ColorSchemeType),
    size: OptionType(SizeType),
    striped: OptionType(BooleanType),             // visual preset (cosmetic stripes)
    animated: OptionType(BooleanType),            // visual — animates the stripes
    // Colour slots
    trackColor: OptionType(StringType),
    fillColor: OptionType(StringType),
    labelColor: OptionType(StringType),
});

export const ProgressType = StructType({
    // Content / config
    value: FloatType,
    min: OptionType(FloatType),
    max: OptionType(FloatType),
    label: OptionType(StringType),
    valueText: OptionType(StringType),
    indeterminate: OptionType(BooleanType),       // NEW
    showValue: OptionType(BooleanType),           // NEW
    estimatedDuration: OptionType(IntegerType),   // seconds — NEW
    startedAt: OptionType(DateTimeType),          // NEW
    // Visual
    style: OptionType(ProgressStyleType),
});
```

**Migration:** call sites with top-level `colorPalette` / `size` / `variant` / `striped` / `animated` move them into `style`.

**React renderer changes:** when `indeterminate` is true, render `<Progress.Root value={null}>`; when `startedAt` + `estimatedDuration` are both present, render a small "~N seconds remaining" text inside `<Progress.ValueText>` computed at render time (not in IR) via `Date.now() - startedAt.getTime()` against the estimated duration; refresh on an interval (renderer-owned, 1s tick).

**Tests:** add `indeterminate` shape, `estimatedDuration` numeric round-trip, `style.fillColor` override.

**Examples:** `progressIndeterminate`, `progressWithETA` ("Solver running… ~1m 20s remaining").

### 3.5 `Skeleton`

**East IR:**

```ts
export const SkeletonShapeType = VariantType({
    text: NullType, rect: NullType, circle: NullType,
});

export const SkeletonStyleType = StructType({
    // Dimensions (visual)
    width: OptionType(StringType),
    height: OptionType(StringType),
    // Colour
    background: OptionType(StringType),
    shimmerColor: OptionType(StringType),
});

export const SkeletonType = StructType({
    // Content / identity — the shape determines what the skeleton represents
    shape: SkeletonShapeType,
    lines: OptionType(IntegerType),      // only used when shape=text — content config
    fontSize: OptionType(StringType),    // only used when shape=text — content config
    count: OptionType(IntegerType),      // repeat N times — content config
    // Visual
    style: OptionType(SkeletonStyleType),
});
```

`shape` stays on main because it determines what the component represents (identity), not just how it looks. `width`/`height` are visual dimensions → style.

**Renderer:** switch on `shape`:
- `text` → `<SkeletonText noOfLines={lines ?? 3} />`
- `rect` → `<Skeleton />` with w/h
- `circle` → `<SkeletonCircle />` with size=w (square)

When `count > 1`, wrap in a vertical `<Stack>`.

**Tests:** per-shape correct dispatch; count>1 produces Stack wrapper; shimmerColor override through `css`.

**Examples** (3):

| Export | Description |
|---|---|
| `skeletonTextBlock` | 3 lines of text skeleton |
| `skeletonCard` | 1 rect (image) + 2 text lines + 1 rect (button) — a typical card skeleton |
| `skeletonRow` | 5-row repeated table-row skeleton via `count: 5` |


**Factory:** `Status.Root(label: string | ExprType<UIComponentType>, { value, pulsing?, size?, icon?, showIcon?, style? })`.

**§0.3 paired-icon** auto-injection: same map as Alert (success → check, warning → triangle, danger → xmark, info → info, neutral → circle) — **performed in the IR factory, not the renderer**. `showIcon: false` opts out; `icon` overrides.

**React renderer:** `<Status.Root>` compound in Chakra v3, with `<Status.Indicator />` (the dot; animate pulse via keyframes if `pulsing` + `prefers-reduced-motion` allows). Icon (if present) rendered via `<FontAwesomeIcon>` to the left of the label.

**Tests:** must include paired-icon assertion — when `showIcon !== false`, the IR value's `icon` field is `some(...)` with the correct status-paired icon.

**Examples** (4):

| Export | Description |
|---|---|
| `statusBasic` | Success / warning / danger / info / neutral side-by-side, each with default paired icon |
| `statusPulsing` | "Recomputing" danger status with pulse; paired with a freshness timestamp in muted text |
| `statusRichLabel` | Label is a `HStack` of label text + a muted secondary string (e.g. "Up to date · 14:32") |
| `statusCustomIcon` | Shows the `icon` override (a non-default Font Awesome icon) |

**Showcase:** the "Up to date" / "Recomputing" chip in the shift-optimiser mockup header. Reference: `shift-optimiser-mockup.html` lines ~903–912 — compose from `Status` + a sibling `Text`, not a single component.

**Implementation notes:**
- `pulsing` renders a CSS keyframe animation on the dot — the renderer reads `window.matchMedia('(prefers-reduced-motion: reduce)')` and skips the animation when reduced.
- `Status.Indicator` colour derives from `value` via Chakra palette semantic tokens (`bg.success.solid`); escape hatch `style.dotColor` overrides.

## 4. Contract compliance

- **States (§0.1):** Alert / Banner / EmptyState render `loading` = muted content, `empty` = `<EmptyState>`, `error` = `status: "error"` banner overlay. Progress / ProgressCircle's `indeterminate` is the "loading" fallback used by `Card.state: loading`.
- **A11y (§0.2):** Every primitive in this section has a known ARIA role (`alert`, `status`, `progressbar`) — map them exactly from Chakra. Paired icons satisfy §0.3 dichromacy. Minimum hit target for `closable` close buttons: 24 px (compact) / 32 px (comfortable) — Chakra's `<CloseButton />` meets both with default sizes.
- **Colour / dichromacy (§0.3):** `Alert`, `Banner`, `Status`, `Toast` auto-inject paired icons in the IR factory; opt-out via `showIcon: false` (Banner/Status only — Alert always shows icon per Chakra convention).
- **Responsive (§0.4):** Banner reflows actions below the title on < 480 px containers; Toaster positioning stays top-right on desktop, top-centre on narrow.
- **Hover intent (§0.5):** n/a — no hover-to-open primitives here.
- **Patches (§0.8):** n/a — feedback surfaces are not commit-adjacent.

## 7. Open questions

1. **`neutral` status colour.** Does the Chakra theme already resolve `neutral` tokens, or do we need to pin them in the theme? Decide before implementing Alert.
2. **Banner composition.** Worth prototyping two variants (`Banner` as a styled `Alert` vs `Banner` as a bespoke Box) and picking based on how well Chakra's Alert stretches visually. Author's bet: bespoke Box is cleaner.
3. **Toaster mount location.** For embedded usage (east-ui lives inside a host app), should `<Toaster />` be host-owned or east-ui-components-owned? Author's bet: host-owned, documented in the renderer comment; east-ui-components exposes `<Toaster />` re-export so hosts that don't have one can drop it in cheaply.
4. **Pulse animation on Status.** CSS keyframe in the renderer, or an `AnimationPresetType: "pulse"` flag on the IR that the renderer honours? Second is more consistent with §1.1 but arguably overkill here. Decide during Status implementation.
