# 1.14 — Platform / reactive (`Clipboard`, `Toast`, `Download`, `Share`, `FocusScope`, `DnD`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.14](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Add browser-side platform primitives that East expressions can invoke: `Clipboard.copy`, `Toast.emit` (pairs with Toast renderer in §1.6), `Download.blob`/`csv`/`xlsx`, `Share.link`, `FocusScope` (focus-trap as IR), and the full `DnD.*` platform (`Context`, `Draggable`, `DropZone`, `DragHandle`, `KeyboardMove`). `Reactive.Root` + `State.bind` already ship (✓) — no changes.

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** platform calls (`Clipboard.copy`, `Toast.emit`, `Download.*`, `Share.link`) are **imperative side-effects**, not UIComponent variants — they are invoked from within East expressions and carry only their args struct, so the main/style split doesn't apply to them. The only UIComp-producing primitives in this plan are `FocusScope` and the `DnD.*` family — those follow the convention: `body` + state (`active` / `disabled`) + config (`accepts` / `type` / `data` key / `initialFocus` / `returnFocus` / `handle` / `autoScroll`) + behaviour (`onDrop` / `validate` / `onEscape` / `onOutsideClick` / `onDragStart` / `onDragEnd`) on main; visual presets + colour slots inside `style: OptionType(XxxStyleType)`. `FocusScope` has no visual fields today and therefore no `style` sub-struct; `DnD.DropZone`'s existing `style` struct (valid / invalid / active backgrounds + borders) is correct. Later visual additions to any of these primitives belong in their style struct.

**Out of scope:** `Print.preview` (deferred per gaps doc).

## 3. Per-entry design

### 3.1 `Clipboard.copy`

**East platform:**
```ts
// src/platform/clipboard.ts
import { East, StringType, NullType } from "@elaraai/east";

const clipboard_copy = East.platform("clipboard_copy", [StringType], NullType, { optional: true });

export const Clipboard = {
    copy: clipboard_copy,
} as const;
```

**Usage (East expression):**
```ts
Button.Root("Copy ID", {
    onClick: East.fn([], NullType, () => Clipboard.copy(scenario.id)),
});
```

**Renderer impl (`east-ui-components/src/platform/clipboard-impl.ts`):**
```ts
export async function clipboardCopyImpl(value: string): Promise<null> {
    if (navigator.clipboard?.writeText) {
        await navigator.clipboard.writeText(value);
    } else {
        // fallback: temporary textarea + execCommand("copy")
    }
    return null;
}
```

Wired at renderer root via the platform registration hook (same pattern as `State.bind`).

**A11y.** The copy action itself has no visual. Authors should pair with `Toast.emit` to confirm ("Copied!") so screen readers hear it.

**Tests:** round-trip IR; mock `navigator.clipboard.writeText`; verify fallback path fires when API absent.

**Examples:** `clipboardCopyId` — `IconButton` that copies a cell value and emits a toast.

### 3.2 `Toast.emit` (pairs with §1.6 `Toaster`)

**East types (referenced from §1.6):** `ToastStatusType = VariantType({ info, success, warning, danger, neutral })`.

```ts
// src/platform/toast.ts
export const ToastActionType = StructType({
    label: UIComponentType,
    variant: OptionType(VariantType({ solid: NullType, outline: NullType, ghost: NullType })),
    onClick: FunctionType([], NullType),
});

export const ToastArgsType = StructType({
    title: UIComponentType,
    description: OptionType(UIComponentType),
    status: OptionType(ToastStatusType),
    durationMs: OptionType(IntegerType),                // default 5000; 0 = sticky
    actions: OptionType(ArrayType(ToastActionType)),
    id: OptionType(StringType),                         // dedupe key
});

const toast_emit = East.platform("toast_emit", [ToastArgsType], NullType, { optional: true });
const toast_dismiss = East.platform("toast_dismiss", [StringType], NullType, { optional: true });

export const Toast = {
    emit: toast_emit,
    dismiss: toast_dismiss,
} as const;
```

**Renderer impl.** A single host-side Chakra `createToaster({ placement: "top-end", max: 4 })` instance is registered; `toast_emit` pushes a toast record to that toaster, mapping status + duration + actions. `toast_dismiss` calls `toaster.dismiss(id)`.

**Placement** is a host decision — the implementation exposes the toaster instance so the host can retain control. Default renders at `top-end`.

**Tests:** IR round-trip for each status; dedupe when same `id` emitted twice (second replaces); `actions[].onClick` fires.

**Examples:**
- `toastBasic` — button triggers `Toast.emit({ title: "Saved", status: "success" })`.
- `toastWithAction` — "Reverted — undo" with an action button firing an East callback.
- `toastSticky` — `durationMs: 0` shows until dismissed.

### 3.3 `Download.blob` / `csv` / `xlsx`

```ts
// src/platform/download.ts
export const BlobDownloadArgsType = StructType({
    filename: StringType,
    mimeType: StringType,
    data: BlobType,                                    // east-side Blob primitive if it exists; else BytesType
});

export const CsvDownloadArgsType = StructType({
    filename: StringType,
    rows: ArrayType(DictType(StringType, StringType)),  // simple cell-stringified shape
    columns: OptionType(ArrayType(StructType({
        key: StringType,
        label: OptionType(StringType),
        format: OptionType(VariantType({ string: NullType, number: NullType, date: NullType })),
    }))),
    includeHeader: OptionType(BooleanType),            // default true
    delimiter: OptionType(StringType),                 // default ","
});

export const XlsxSheetType = StructType({
    name: StringType,
    rows: ArrayType(DictType(StringType, StringType)),
    columns: OptionType(ArrayType(/* as CSV */)),
});

export const XlsxDownloadArgsType = StructType({
    filename: StringType,
    sheets: ArrayType(XlsxSheetType),
});

const download_blob = East.platform("download_blob", [BlobDownloadArgsType], NullType, { optional: true });
const download_csv = East.platform("download_csv", [CsvDownloadArgsType], NullType, { optional: true });
const download_xlsx = East.platform("download_xlsx", [XlsxDownloadArgsType], NullType, { optional: true });

export const Download = {
    blob: download_blob,
    csv: download_csv,
    xlsx: download_xlsx,
} as const;
```

**Renderer impl.**
- `download_blob`: wrap data in a `Blob`, `URL.createObjectURL`, create `<a download>` + click + revoke.
- `download_csv`: serialise per RFC 4180 (escape quotes, wrap in `"..."` if it contains `,` / `"` / `\n`); BOM prefix `\uFEFF` for Excel UTF-8 detection; same anchor-click dispatch.
- `download_xlsx`: dynamic `import("xlsx")`; build workbook per sheet; write to array buffer; anchor-click.

**Tests:** CSV escaping matrix (plain / quotes / commas / newlines / unicode); BOM present; multi-sheet XLSX round-trip via SheetJS read.

**Examples:**
- `downloadCsvTable` — "Export selected rows" button → Download.csv.
- `downloadXlsxMultiSheet` — scenario summary + detail rows in two sheets.
- `downloadBlob` — generic PDF blob download (caller supplies bytes).

### 3.4 `Share.link`

```ts
// src/platform/share.ts
export const ShareLinkArgsType = StructType({
    // opaque serialisable state — app serialises its own shape into a dict
    state: DictType(StringType, StringType),
    basePath: OptionType(StringType),                  // default current pathname
    replace: OptionType(BooleanType),                  // default true (replaces history)
});

const share_link = East.platform("share_link", [ShareLinkArgsType], StringType /* the resulting URL */, { optional: true });
const share_readLink = East.platform("share_readLink", [], DictType(StringType, StringType), { optional: true });

export const Share = {
    link: share_link,
    readLink: share_readLink,
} as const;
```

**Renderer impl.**
- `share_link`: serialises `state` to a query string (URLSearchParams), appends to `basePath || location.pathname`, calls `history.replaceState` (or `pushState` if `replace: false`), returns the full URL string for the caller to `Clipboard.copy` or `Toast.emit`.
- `share_readLink`: parses `location.search` into a dict. Caller deserialises. Useful on first render to restore state.

**Tests:** round-trip state-to-URL-to-state; query-string escaping; special-character keys.

**Examples:** `shareCurrentScenario` — "Share this view" button composes `Share.link` + `Clipboard.copy` + `Toast.emit`.

### 3.5 `FocusScope` (IR-level focus trap)

**East IR type (`src/overlays/focus-scope/types.ts`):**
```ts
export const FocusScopeType = StructType({
    body: UIComponentType,
    active: OptionType(BooleanType),                   // default true; false = trap disabled
    initialFocus: OptionType(StringType),              // CSS selector inside body
    returnFocus: OptionType(BooleanType),              // default true
    onEscape: OptionType(FunctionType([], NullType)),  // fires on Esc (optional)
    onOutsideClick: OptionType(FunctionType([], NullType)),
});
```

**Factory.** `FocusScope.Root(body, { active?, initialFocus?, returnFocus?, onEscape?, onOutsideClick? })`.

**React renderer.** Wraps body in a Chakra `<FocusScope>` (or `focus-trap-react` if Chakra's is insufficient). On mount, moves focus to `initialFocus` element (or first focusable); traps Tab / Shift+Tab within. On unmount, restores focus to the previously focused element. `onEscape` bound to keydown; `onOutsideClick` bound to pointerdown outside the scope.

**Consumer.** `Dialog`, `Drawer`, `Popover` (§1.12) wrap their body in `FocusScope` internally — callers don't usually use this directly. Exposed for custom overlays (e.g. a Tour step with its own focus semantics).

**Tests:** Tab cycles within body; Shift+Tab reverse-cycles; Esc fires `onEscape`; returnFocus on unmount.

**Examples:** `focusScopeCustomOverlay` — a hand-rolled floating toolbar with trap.

### 3.6 `DnD` platform — five primitives

**East IR types (`src/dnd/types.ts`):**
```ts
export const DragPreviewType = VariantType({
    default: NullType,                                 // dnd-kit default: clone
    custom: UIComponentType,
});

export const DraggableType = StructType({
    body: UIComponentType,
    data: StringType,                                  // opaque key — see below
    type: StringType,                                  // "task" | "shift" | etc.
    preview: OptionType(DragPreviewType),
    disabled: OptionType(BooleanType),
    handle: OptionType(BooleanType),                   // if true, only DragHandle within initiates drag
});

export const DropZoneValidationType = StructType({
    allowed: BooleanType,
    reason: OptionType(UIComponentType),               // shown when disallowed
});

export const DropZoneType = StructType({
    body: UIComponentType,
    accepts: ArrayType(StringType),                    // types this zone accepts
    onDrop: FunctionType([StringType /* key */], NullType),
    validate: OptionType(FunctionType([StringType /* key */], DropZoneValidationType)),
    disabled: OptionType(BooleanType),
    style: OptionType(StructType({
        background: OptionType(StringType),
        borderColor: OptionType(StringType),
        activeBackground: OptionType(StringType),      // valid drop hover
        activeBorderColor: OptionType(StringType),
        invalidBackground: OptionType(StringType),
        invalidBorderColor: OptionType(StringType),
    })),
});

export const DragHandleType = StructType({
    body: UIComponentType,                             // glyph / icon wrapping
    label: StringType,                                 // aria-label (required)
});

export const DnDContextType = StructType({
    body: UIComponentType,                             // the draggable region
    onDragStart: OptionType(FunctionType([StringType], NullType)),
    onDragEnd: OptionType(FunctionType([StringType], NullType)),
    autoScroll: OptionType(BooleanType),               // default true
});

// KeyboardMove is the enforced A11y companion. It is a *renderer-side obligation*
// rather than an independent IR variant: a Draggable always carries a keyboard
// affordance in the renderer. Exposed as a factory so authors can opt to customise
// the keyboard hint text; default values suffice for most cases.
export const KeyboardMoveHintType = StructType({
    pickUp: OptionType(StringType),                    // default "Space"
    move: OptionType(StringType),                      // default "Arrow keys"
    drop: OptionType(StringType),                      // default "Space"
    cancel: OptionType(StringType),                    // default "Escape"
});
```

**The opaque-key design** (per gaps doc §1.14 and clarifications): `Draggable.data` is a **string key**, not an arbitrary payload. The renderer maintains a JavaScript-side registry `Map<string, unknown>` that resolves the key at drop time. The IR carries only the key — keeps snapshots small, keeps `State.bind` diffing simple, avoids serialising callback-owned payloads. Authors register payloads alongside the key in host code when the Draggable mounts. A helper will be provided (`DnD.registerPayload(key, payload)`).

**Factory namespace:**
```ts
export const DnD = {
    Context: createDnDContext,         // DnD.Context(body, { onDragStart?, onDragEnd?, autoScroll? })
    Draggable: createDraggable,        // DnD.Draggable(body, { data: key, type, preview?, disabled?, handle? })
    DropZone: createDropZone,          // DnD.DropZone(body, { accepts: string[], onDrop, validate?, style? })
    DragHandle: createDragHandle,      // DnD.DragHandle(body, { label })
    // Helper utility (not an IR variant):
    registerPayload: registerPayload,  // (key: string, payload: unknown) => void  — host-side map
    Types: {
        Draggable: DraggableType,
        DropZone: DropZoneType,
        // ...
    },
} as const;
```

**React renderer.**
- `DnD.Context` → `<DndContext>` from `dnd-kit/core` with `<DndContext sensors={[PointerSensor, KeyboardSensor]} autoScroll={autoScroll}>`. The `KeyboardSensor` is non-optional — this is what enforces §0.2 keyboard-parity without author opt-in.
- `DnD.Draggable` → `useDraggable({ id: data, data: { type } })`. Attached attributes/listeners go on the wrapping Box unless `handle: true`, in which case the listeners attach to a descendant that renders via `DnD.DragHandle`. Renders a second invisible `aria-describedby` span containing the keyboard hint ("Press Space to pick up, arrow keys to move, Space to drop, Escape to cancel").
- `DnD.DropZone` → `useDroppable({ id: generated, data: { accepts } })`. On drop, the renderer checks `accepts.includes(activeDragData.type)` and `validate(key).allowed` (if validate supplied). If both pass, fires `onDrop(key)`. The visual state (`active`, `invalid`) is reflected in `isOver && valid`, `isOver && !valid`.
- `DnD.DragHandle` → a child with `aria-label={label}` + `role="button" tabIndex=0` hooked into the parent Draggable's keyboard sensor. Mandatory `label` (enforced at IR factory).
- Lazy-load dnd-kit: renderer uses `React.lazy` so apps without DnD don't pay the bundle cost.

**Payload resolution contract.**
```ts
// In the host, near where the Draggable is rendered:
DnD.registerPayload("shift-2026-04-22-employee-42", { employeeId: 42, shiftId: 2026042, ... });

// The onDrop callback receives "shift-2026-04-22-employee-42";
// the host can look up the payload via its own registry or use East expressions
// to fetch it from State.bind.
```

**A11y contract.** Keyboard parity is *non-negotiable*: every Draggable produces a keyboard-operable element. Renderer warns (dev-only) if a Draggable's body is not keyboard-reachable (missing tabIndex, etc.). Screen-reader live region announces pick-up / drop / cancel.

**Tests:**
- IR round-trip for each factory.
- Opaque key registration/resolution map consistency.
- Keyboard flow: Space on Draggable picks up, Arrow moves focus across DropZones of matching `accepts`, Space drops, Esc cancels — verified via React Testing Library events.
- `validate` predicate gates drop; returns a `reason` UIComp that renders in the invalid state.
- `accepts` mismatch never fires `onDrop`.
- Reduced-motion respected (no drag-preview animation).

**Examples:** (in `test/dnd/`):
- `dndBasicDragDrop` — single list reordering.
- `dndMultiZone` — three zones, one draggable type, per-zone validate rule.
- `dndDragHandleOnly` — card with only a handle grip zone.
- `dndKeyboardOnly` — same as basic but driven entirely by keyboard (demonstrates the A11y contract).
- `dndCustomPreview` — shows `preview: variant("custom", Box(...))`.
- `dndAssignmentMini` — a 3×3 grid of DropZones with an UnassignedTray panel; mini-rehearsal for §2.5's `AssignmentBoard`.

## 4. Contract compliance

- **§0.1 States** — DnD DropZones respect disabled state (renders but doesn't accept drops). `Toast` messages themselves are ephemeral; no states contract.
- **§0.2 A11y** — `DnD` keyboard parity enforced in the *renderer* (non-optional `KeyboardSensor` + `DragHandle.label` required). `FocusScope` enforces focus-trap semantics. `Toast` uses `aria-live="polite"` for info/success, `aria-live="assertive"` for warning/danger. `Clipboard.copy` pairs with `Toast.emit` for screen-reader feedback.
- **§0.3 Colour / dichromacy** — DnD valid/invalid drop states must include a border or icon signal, not colour alone. Default theme renders a dashed outline on invalid zones.
- **§0.4 Responsive** — Toast placement responsive (top-end → top-center under 480px).
- **§0.5 Hover intent** — N/A.
- **§0.8 Patches** — Platform calls themselves are imperative side effects; they don't produce patches. Callers that want a patch trail wrap the side effect in an East fn that also emits a patch via the enclosing draft system (e.g. `PresetPicker.onSelect` calls `Clipboard.copy` and emits a patch).

## 5. Acceptance criteria

- [ ] `Clipboard.copy` works under secure + insecure contexts (fallback path verified).
- [ ] `Toast.emit` surfaces all five statuses with the correct Chakra tint + paired icon.
- [ ] `Download.csv` round-trips through a second read (e.g. `papaparse`) without field mangling, including quoted commas/newlines.
- [ ] `Download.xlsx` produces a valid `.xlsx` per SheetJS read.
- [ ] `Share.link` round-trip preserves state; `basePath` override works.
- [ ] `FocusScope.Root` traps Tab + Shift+Tab; Esc fires callback; focus returns on unmount.
- [ ] `DnD` keyboard flow passes per §0.2: pick up / move / drop / cancel via Space+Arrows+Esc.
- [ ] `DnD.DropZone.validate` gates drops; invalid attempts do not fire `onDrop`.
- [ ] dnd-kit and SheetJS bundles lazy-load (verified via build analyser).
- [ ] east-ui core bundle (sans DnD / CommandPalette / virtualization / xlsx) stays under the 80 KB gzipped budget in §UI-9.

## 7. Open questions

1. **Opaque key lifetime.** The `DnD.registerPayload` map leaks unless the registration site unregisters on unmount. Plan: React hook `useDnDPayload(key, payload)` that registers on mount, deletes on unmount. Document that bare `registerPayload` is an escape hatch.
2. **Toast placement ownership.** If two east-ui-powered surfaces mount on the same page, they currently share one toaster. Acceptable — document that `Toast.emit` is a global side effect. If isolation is required later, add a `ToasterProvider` component.
3. **Download progress.** Large xlsx generation blocks the main thread. Consider moving SheetJS work to a worker — defer until a user reports a hang.
4. **Share.link security.** Query-string state is user-visible and forwarded to servers. Document that sensitive values must not be serialised. No CSP opinion here — host-app concern.
5. **`Print.preview`** — re-evaluate after v1 ships. Likely needs a snapshot-rendering path that strips interactive affordances and bakes a `<style>` block with print-media rules. Non-trivial; out of this pass.
