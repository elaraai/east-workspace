# 1.5 — Forms (`Input` suite, `Checkbox`, `Switch`, `Select`, `Combobox`, `Slider`, `Field`, `FileUpload`, `Textarea`, `TagsInput`, `RadioGroup`/`RadioCardGroup`, + new `DateRangeInput`, `TimeRangeInput`, `TimeScaleControl`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.5](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Widen every input with colour escape hatches + `autoComplete`/`inputMode` where applicable; turn `IntegerInput`/`FloatInput` into a full `NumberInput` via `showStepper` + `format` + addons; add calendar toggle on DateTimeInput + new `DateRangeInput` / `TimeRangeInput` / `TimeScaleControl`; promote `Checkbox`/`Switch` labels to rich UIComp; add `marks[]` + range mode to `Slider`; upgrade `Field.errorState` to structured; add `RadioGroup` / `RadioCardGroup`; keep `Combobox` distinct from `Select`.

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** every form primitive splits:
- **Main** — `value` / `defaultValue` / `placeholder` / `label` (string form) / `items` / numeric constraints (`min` / `max` / `step` / `precision` / `maxLength` / `pattern` / `accept` / `maxFiles` / `maxFileSize`) / wiring flags (`multiple` / `allowCustomValue` / `autoresize` / `addOnPaste` / `allowDrop` / `showStepper` / `showCalendar` / `showValue` / `range` / `format` / `presets` / `groupedItems` / `marks` — all "does this UI element exist / what data does it show"), state (`checked` / `disabled` / `readOnly` / `required` / `indeterminate` / `invalid` / `editable`), addons (`startAddon` / `endAddon` / `prefix` / `suffix` / `inlineHelp` — rich content), input-mode hints (`autoComplete` / `inputMode` / `delimiter` / `blurBehavior` / `capture` / `resize`), callbacks (`onChange` / `onBlur` / `onFocus` / `onValidate` / `onInputChange` / `onHighlightChange` / `onFileAccept` / `onFileReject`).
- **`style: OptionType(XxxStyleType)`** — visual presets (`variant` / `size` / `colorPalette`) + geometric presentation (`orientation`) + typography (`textAlign` / `fontFamily`) + colour escape hatches (slot-specific, see each entry).

**Out of scope:** `NumberInput` as a separate primitive — we widen existing Integer/Float Input (per gaps doc).

## 3. Per-entry design

### 3.1 `StringInput`, `IntegerInput`, `FloatInput`, `DateTimeInput`

Each Input variant follows the main/style split. Shared style struct components below; per-variant specifics after.

```ts
export const InputModeType = VariantType({
    text: NullType, numeric: NullType, decimal: NullType,
    tel: NullType, email: NullType, url: NullType, search: NullType,
});

// Shared style fields (each Input variant has its own XxxInputStyleType containing a subset):
// Visual presets: variant (InputVariantType), size (SizeType)
// Typography: textAlign (TextAlignType), fontFamily (FontFamilyType)
// Colour escape hatches: color, background, borderColor, focusBorderColor, placeholderColor
// Variant-specific: stepperColor (Integer/Float), calendarBackground / calendarHighlightColor / calendarSelectedBackground (DateTime)
```


## 4. Contract compliance

- §0.2 — every primitive supports keyboard operation out of Chakra. `Slider.marks` with labels announce via `aria-valuetext`. `RadioCardGroup` keyboard: arrow keys navigate cards.
- §0.3 — `Field.errorState.level` ties into the same semantic palette; IR factory does not auto-inject an icon here (Field shows its own inline warning icon when `level === "warning"` etc.).
- §0.10 — every form primitive follows the main/style split. Content (`value` / `items` / `placeholder` / addons), state (`disabled` / `readOnly` / `required` / `checked` / `indeterminate` / `invalid` / `editable`), config (`min` / `max` / `step` / `precision` / `maxLength` / `pattern` / `accept` / `maxFiles` / `multiple` / `allowCustomValue` / `autoresize` / `showStepper` / `showCalendar` / `showValue` / `range` / `format` / `presets` / `groupedItems` / `marks` / `autoComplete` / `inputMode` / `delimiter` / `blurBehavior` / `capture` / `resize` / `addOnPaste` / `allowDrop`), and behaviour (every `onX` callback) all on main.
