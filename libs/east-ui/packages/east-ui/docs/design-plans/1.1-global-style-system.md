# 1.1 — Global style system (raw tokens + semantic layer)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.1](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Introduce every type listed in §1.1 — raw tokens (`PositionType`, `CursorType`, `FontFamilyType`, `FontVariantNumericType`, `BoxShadowType`, `RadiusType`, `AnimationPresetType`, `ZIndexTokenType`) and the semantic layer (`TextStyleType`, `DensityType`, `VerbosityType`, `ElevationType`, `MotionDurationType`, `MotionEasingType`, `TransitionType`, `FocusStyleType`, `HoverIntentType`, `StatusTokenType`). Deprecate and delete the clashing `TableVariantType` in `src/style.ts`. Add the global `colorPalette` semantic tokens (`success|warning|danger|info|neutral`). Ship the `Style` namespace helpers for each.
**Out of scope for this plan:** theme values (owned by the consuming app's Chakra theme). Any per-component prop additions — covered in each component's own plan.

**Consumption rule:** Every token defined here is consumed **inside** a component's `style: OptionType(XxxStyleType)` sub-struct per the README Type-shape convention (§0.10 in `0-conventions.md`). This plan ships the token vocabulary only; per-component plans (1.2 onward) plug the tokens into each `XxxStyleType`. The previous wording in the gaps doc that framed the `style` struct as a "colour escape hatch only" bucket is superseded: `style` is the **whole-visual-presentation bucket** — every token family (layout, colour, border, typography, opacity/motion/shadow, visual presets, geometric presentation) lives inside it.

## 1. Dependencies

No runtime deps. Chakra v3 must resolve every new token in its theme. Work with the host theme authors to publish resolved values for:
- `textStyles` — 17 named text styles.
- `layerStyles` / `recipes` for `ElevationType`, `FocusStyleType`.
- Duration + easing tokens for `MotionType`.
- Animation keyframes for `AnimationPresetType`.

## 3. Per-entry design

For each token: shape + `Style.*` helper signature + JSDoc requirement.

### 3.1 Raw tokens

export function Position(p: PositionLiteral): ExprType<PositionType> { /* East.value(variant(p, null), PositionType) */ }

### 3.3 `ColorSchemeType` extension

Extend existing type with: `success`, `warning`, `danger`, `info`, `neutral`. Keep hue tokens (`gray`, `red`, `teal`, etc.) for now — apps using them still work. A future revision may deprecate hue tokens if adoption of semantic tokens becomes universal.

### 3.4 Renderer helpers

See file plan §2. Each helper is a pure function `(token) → CSS / Chakra prop value`. They read from the consumer's Chakra theme via `theme.tokens.*`, so changing theme values doesn't require re-releasing east-ui-components.

### 3.5 Tests

`test/style.spec.ts`:
- For every new token, assert round-trip: `Style.X("y").eq(Style.X("y"))` is true; `Style.X("y").eq(Style.X("z"))` is false.
- Assert that deleted `TableVariantType` is no longer exported (TS compile error if re-imported — enforced via `// @ts-expect-error` tombstone).
- `ColorSchemeType` round-trips for all five new semantic tokens.

**Examples** (`test/style.examples.ts`):

| Export | Keywords | Description | What it must show |
|---|---|---|---|
| `textStyleScale` | `textStyle`, `display`, `heading`, `body`, `label` | Each `textStyle` value rendered as `Text.Root("Aa")` with its name below in `textStyle: "caption"` | All 17 styles visible at once |
| `densityKnob` | `DensityType`, `comfortable`, `compact`, `condensed` | Three copies of a tiny `Table` (or `DataList`) under different `DensityProvider` settings | Visible row-height delta |
| `elevationScale` | `ElevationType`, `raised`, `overlay`, `floating` | Five `Box` cards at different elevations, stacked vertically | Distinct shadow + bg per level |
| `motionDurationSwatches` | `MotionDurationType`, `TransitionType` | Four buttons that transition a border colour on hover with different durations | Author can feel the speeds |
| `statusPalette` | `StatusTokenType`, `semantic`, `dichromacy` | Row of five `Status.Root` with `success|warning|danger|info|neutral` — dichromacy-safe | Paired icon appears on each |

**Showcase:** one "Design tokens" card on the landing page, rendering these examples.

## 7. Open questions

1. Should the `Style.*` helpers be kept in the `Style` namespace or exported loose (`import { FontFamily } from "@elaraai/east-ui"`)? Preserve the `Style` namespace for consistency with existing `FontWeight`, `TextAlign`, etc.
2. `TextStyleType` naming: `"display-lg"` vs `"display.lg"`? Chakra v3 uses dots in theme paths. Vote: dashes in the variant tag (string-safer), renderer maps to dots when reading theme.
3. Do we ship `AnimationPresetType` with keyframes in the renderer, or leave apps to register custom keyframes? Start shipping (pulse, spin, fade-in, shimmer) — `bounce` and `none` are trivial. Apps can register more via the theme.
