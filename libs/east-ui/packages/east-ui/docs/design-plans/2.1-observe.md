# 2.1 — Observe patterns

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §2.1](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** The Observe-mode patterns (and the two Project-mode patterns that share the Observe visual surface: `ForecastView`, `ProjectionToTarget`). All patterns below land in a new package `@elaraai/east-ui-patterns` under `src/observe/` (+ `src/project/` for the two projection patterns).

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** every pattern IR follows the same split. Content (`cards`, `items`, `signals`, `segments`, `chips`, `total`, `label`, `value`, `history`, `forecast`, `horizonMarker`, `meta`, `push`, `clear`, `search`, `sort`, `emptyState`, `details`, `list`, `detail`, `value`, `target`, `projection`, `a`, `b`, `delta`, `onOpen`-payload data) stays on main. State (`selectedId`, `activeId`, `visible`, `pinned`) stays on main. Config (`limit`, `columns`, `dimension`, `interactive`, `format`) stays on main. Behaviour (`onChipToggle`, `onSelect`, `onClear`, `onOpen`, `onSwapA`, `onSwapB`, `onClick`, `styleBy` callback) stays on main. Visual presets (`variant`, `size`, `density`, `verbosity`, `dividers`, `separator`, `orientation`) + colour slots + dimensions + placement presets live inside `style: OptionType(XxxStyleType)`. **`styleBy: FunctionType([..., IntegerType], MetricStyle)` — a per-item theming callback — is a behaviour function, not a style override; it stays on main.**

**Out of scope:** `Explain` patterns (§2.2); advanced chart types (deferred per §1.11).

**Package.** New sibling package `@elaraai/east-ui-patterns` consuming `@elaraai/east-ui` + `@elaraai/east-ui-components`. Per-mode folders: `observe/`, `explain/`, `project/`, `decide/`, `compare/`, `configure/`, `trust/`, `safety/`. Test + example structure mirrors `east-ui`: `test/<mode>/<pattern>.spec.ts` + `.examples.ts`.

## 3. Per-entry design

### 3.1 `StatCard`

**East IR type:**
```ts
// east-ui-patterns/src/types.ts
export const DeltaPillType = StructType({
    value: UIComponentType,                               // Numeric or Text
    direction: VariantType({ up: NullType, down: NullType, flat: NullType }),
    magnitude: OptionType(VariantType({
        "higher-is-better": NullType,
        "lower-is-better": NullType,
        "target-is-best": StructType({ target: FloatType, tolerance: OptionType(FloatType) }),
    })),
    ci: OptionType(StructType({ low: FloatType, high: FloatType })),
    significant: OptionType(BooleanType),
});

// stat-card/types.ts
export const StatCardLayoutType = VariantType({
    vertical: NullType,
    horizontal: NullType,
    inline: NullType,
    "trend-led": NullType,
});

export const StatCardStyleType = StructType({
    labelColor: OptionType(StringType),
    valueColor: OptionType(StringType),
    baselineColor: OptionType(StringType),
    indicatorColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    accentColor: OptionType(StringType),
});

export const StatCardType = StructType({
    label: UIComponentType,
    value: UIComponentType,
    baseline: OptionType(UIComponentType),
    delta: OptionType(DeltaPillType),
    indicator: OptionType(StatIndicatorType),              // §1.7
    info: OptionType(UIComponentType),                     // ToggleTip content
    trend: OptionType(UIComponentType),                    // typically a Sparkline
    layout: OptionType(StatCardLayoutType),
    size: OptionType(SizeType),
    density: OptionType(DensityType),
    verbosity: OptionType(VerbosityType),
    state: OptionType(StateValueType),                     // inherits Card.state
    style: OptionType(StatCardStyleType),
});
```

**Factory:**
```ts
StatCard.Root({ label, value, baseline?, delta?, indicator?, info?, trend?, layout?, size?, density?, verbosity?, state?, ... })
```
Coerces `label: string` → `Text.Root(s, { textStyle: "label-md" })`; `value: string|number` → `Numeric.Root(x)`.

**React renderer.** Wraps a `Card` (inheriting `Card.state` fallbacks from §1.8). Layouts:
- `vertical` (default): Stack: label + info-trigger row; value (mono-kpi); baseline + delta row; trend below.
- `horizontal`: Grid 2-col: label/value left; baseline/delta/trend right.
- `inline`: HStack one-line compact; trend omitted.
- `trend-led`: trend sparkline fills the card width; value overlaid top-left.

Style hatches: `labelColor` on label Text; `valueColor` on the Numeric; `baselineColor` on baseline text; `indicatorColor` on the up/down chevron. `accentColor` renders as a 3px left-edge stripe. When `state: "loading"`, Card renders a skeleton sized to `layout`.

**Tests:**
- Layouts round-trip.
- `delta.magnitude: "target-is-best"` inverts colour mapping around the tolerance band.
- `indicator` direction+sentiment orthogonality: up+positive = green+▲; up+negative = red+▲; down+negative = red+▼, etc.
- `state: loading/empty/error/stale/permission-denied` render appropriate fallbacks.
- Density cascade via context.
- `info` opens a ToggleTip (click, not hover — ToggleTip is click-persistent).

**Examples:**
| Name | Keywords | Reference |
|---|---|---|
| `statCardVertical` | statcard, kpi | Briefing §2 KPI rail |
| `statCardHorizontal` | statcard, comparison | shift-optimiser "Revenue vs plan" |
| `statCardInline` | statcard, inline | compact row inside a Card.Section |
| `statCardTrendLed` | statcard, trend | Briefing sparkline-led KPI |
| `statCardWithInfo` | statcard, info, toggletip | ToggleTip explains "Rotation plan" |
| `statCardLoading` | statcard, state, skeleton | `state: loading` |
| `statCardTargetBest` | statcard, target, delta | `delta.magnitude: "target-is-best"` |
| `statCardBranded` | statcard, color | All escape hatches at once |

### 3.2 `StatGrid`

**East IR:**
```ts
export const StatGridStyleType = StructType({
    dividerColor: OptionType(StringType),
    background: OptionType(StringType),
});

export const StatGridType = StructType({
    cards: ArrayType(StatCardType),                        // or UIComponentType for arbitrary tiles
    columns: OptionType(IntegerType),                      // default 4; responsive rule: columns ÷ 2 under 768px
    dividers: OptionType(VariantType({ lines: NullType, gap: NullType })),
    density: OptionType(DensityType),
    style: OptionType(StatGridStyleType),
});
```

**Factory.** `StatGrid.Root(cards, { columns?, dividers?, density? })`.

**Renderer.** Compiles to `Grid.Root(cards, { templateColumns: \`repeat(\${columns}, 1fr)\` })`; `dividers: "lines"` adds a 1px `dividerColor` hairline between cells via `gridLines`-style gap fill; `"gap"` uses plain spacing. Responsive: `useMediaQuery` halves columns under 768px, single-column under 480px.

**Tests:** columns default; responsive breakpoint; divider rendering; cards of heterogeneous layouts.

**Examples:** `statGrid4Up`, `statGridResponsive` (verbose description shows the breakpoint), `statGridWithDividers`.

**East IR:**
```ts

    key: StringType,

    icon: OptionType(IconType),
    info: OptionType(UIComponentType),

    unit: OptionType(StringType),

});

export const MetricStyleType = StructType({
    labelColor: OptionType(StringType),
    valueColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    accentColor: OptionType(StringType),
});

export const MetricRailVariantType = VariantType({
    header: NullType, footer: NullType, inline: NullType,
});

export const MetricRailStyleType = StructType({
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    separatorColor: OptionType(StringType),
    labelColor: OptionType(StringType),
    valueColor: OptionType(StringType),
});

export const MetricRailType = StructType({
    items: ArrayType(MetricDefType),
    variant: OptionType(MetricRailVariantType),
    density: OptionType(DensityType),
    verbosity: OptionType(VerbosityType),
    separator: OptionType(VariantType({ line: NullType, dot: NullType, none: NullType })),
    push: OptionType(UIComponentType),                     // trailing slot (e.g. overflow menu)
    styleBy: OptionType(FunctionType([MetricDefType, IntegerType], MetricStyleType)),
    style: OptionType(MetricRailStyleType),
});
```

**Factory.** `MetricRail.Root(items, { variant?, density?, verbosity?, separator?, push?, styleBy?, style? })`.

**Renderer.** Wraps `ChipRail`. For each item renders a small `{label, value, delta?}` chip. `styleBy(item, idx)` returns per-item `MetricStyle` overriding rail defaults. Overflow ≥8 items → menu (from `ChipRail` §1.2). `variant: header` adds a bottom hairline; `footer` a top hairline; `inline` no border — just padding.

**A11y.** `role="group" aria-label={ariaLabel}`; each item's value uses `aria-labelledby={label}`.

**Tests:**
- `styleBy` supplies per-item colour.
- Overflow menu triggers at threshold.
- Density + verbosity cascading.

**Examples:** `metricRailHeader` (Briefing page header 6 KPIs), `metricRailFooter` (card footer mini metrics), `metricRailStyleByStatus` (green/red per item via `styleBy`).

### 3.6 `ListDetailShell`

Preset: composes `ListDetailLayout` + `SelectionController`. One factory:
```ts
ListDetailShell.Root({

    mode?: "single" | "multi",
    placement?: "drawer" | "panel" | "modal",
```

Factory internals create the selection controller, pass the selected id(s) to both renderers. Renders `ListDetailLayout` underneath.

**Examples:** `listDetailShellScenarios` — scenarios list + per-scenario summary card.

## 4. Contract compliance

- **§0.1 States** — `StatCard`, `StatGrid`, `AttentionList`, `ForecastView`, `ProjectionToTarget` all accept `state` and delegate to `Card.state` fallbacks. `FirstRunState` *is* the default empty fallback when set.
- **§0.2 A11y** — `MetricRail` is a grouped aria region; `LegendRail interactive` items are buttons with `aria-pressed`; `FilterBar.search` wired with `role="search"`; `AttentionList` items keyboard-reachable with Enter to open. Charts inherit Recharts a11y (accessibility plugin + aria descriptions).
- **§0.3 Colour/dichromacy** — `LegendRail` swatches paired with labels. `ThresholdBand` zones paired with labels (no colour-only zones). `DeltaPill` pairs direction arrow with colour. `AttentionList` severities use `Status` primitive with auto-injected icon.
- **§0.4 Responsive** — `StatGrid` halves columns under 768px. `MetricRail` overflows to menu. `ListDetailLayout` `panel` collapses to stacked layout under 768px.
- **§0.5 Hover intent** — `StatCard.info` uses `ToggleTip` (click-persistent), not hover — deliberate because info blocks are interactive (may contain links).
- **§0.8 Patches** — N/A for Observe. `ChangeSinceLastVisit` (§2.6 Frame & trust) is the patch-aware sibling.

## 7. Open questions

1. **`StatCard.layout: "trend-led"` vs separate pattern.** Gaps doc absorbed `TrendTile` into this layout. Keep — saves a pattern. If ≥2 apps complain about the layout/size coupling, extract later.
2. **`FilterBar.sort` — standalone component?** Debated. Keep inline for now; if ≥2 apps want a standalone `SortControl`, extract.
3. **`ListDetailShell` detail-as-function** requires the detail to be re-rendered on selection change. Per-pattern `Reactive.Root` wrapping? Yes — document that the returned UIComp should wrap in `Reactive.Root` if it reads state. The shell does not auto-wrap (consistent with §0.6).
4. **`ForecastView` interactive brush.** Recharts supports `<Brush>`. Add as optional? Yes — `brush: OptionType(BooleanType)`, default false. Keeps the simple case simple.
5. **`AttentionList.signals` ranking.** Caller supplies pre-ranked signals; pattern does not rank. Document. An opinionated ranker (severity × freshness × threshold proximity) would be a future helper (`AttentionList.rank(...)`) if ≥2 apps converge on the same algorithm.
