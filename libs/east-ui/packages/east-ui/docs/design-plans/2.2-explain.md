# 2.2 — Explain patterns (+ Measure-mode `OutcomeScorecard` / `ActualVsPredictedChart`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §2.2](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** The Explain-mode patterns that sit between Observe (descriptive) and Decide (prescriptive). Plus two Measure-mode patterns that share the Explain visual surface: `OutcomeScorecard`, `ActualVsPredictedChart`.

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** content (`drivers`, `indicators`, `nodes`, `points`, `details`, `summary`, `value`, `low`/`high`, `sampleSize`, `horizon`, `historicalAccuracy`, `metric` definition) + semantic classification (`kind`, `status`, `direction`) + state (`selectedId`, `view`) + config (`limit`, `residualBand`) + behaviour (`onSelect`, `onPointSelect`) on main. Visual presets (`orientation`, `style` variants, `size`, `density`, `verbosity`) + colour slots in `style: OptionType(XxxStyleType)`. Per-indicator / per-point / per-node `color` on item sub-types stays on the item (data-level).

**Out of scope:** `DeltaBreakdown`, `ConflictAnnotator` — documented as recipes in the Recipes appendix (not patterns). `SummaryNarrative` — downgraded to `Note` primitive in §1.3.

## 3. Per-entry design

### 3.1 `DriverList`

**East IR type:**
```ts
export const DriverItemType = StructType({
    name: UIComponentType,                                 // label (string coerced)
    observed: UIComponentType,                             // typically Numeric
    expected: OptionType(UIComponentType),
    contribution: FloatType,                               // 0..1; fraction of total delta
    direction: OptionType(VariantType({
        positive: NullType, negative: NullType, neutral: NullType,
    })),
    details: OptionType(UIComponentType),                  // Disclosure content
});

export const DriverListStyleType = StructType({
    nameColor: OptionType(StringType),
    valueColor: OptionType(StringType),
    barColor: OptionType(StringType),
    positiveColor: OptionType(StringType),
    negativeColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
});

export const DriverListType = StructType({
    drivers: ArrayType(DriverItemType),
    limit: OptionType(IntegerType),                        // default 8; overflow → "X more"
    summary: OptionType(UIComponentType),                  // Note above the list
    showContribution: OptionType(BooleanType),             // default true
    density: OptionType(DensityType),
    state: OptionType(StateValueType),
    style: OptionType(DriverListStyleType),
});
```

**Factory.** `DriverList.Root(drivers, { limit?, summary?, showContribution?, density?, state?, style? })`.

**React renderer.** `<Table>` with columns: `name`, `observed`, `expected?`, contribution bar (`Progress` with `direction`-derived tone colour), `contribution%`, `details`-chevron to reveal `Disclosure`. When `summary` present, rendered as `Note` variant `"narrative"` above the table. `state: loading` → 5 skeleton rows; `empty` → `EmptyState("No drivers to explain")`.

**Sort.** Defaults to `|contribution| desc`. Ties broken by name A→Z. `limit` clamps visible rows and appends a "+N more" expansion row that toggles the cutoff.

**A11y.** Contribution bar announces percent via `aria-valuenow`; direction announced via adjacent "up/down/neutral" text (not colour alone).

**Tests:**
- Sort default + tie-break.
- Limit overflow row renders count.
- `state` fallbacks.
- Direction colour follows tone defaults unless `style.positiveColor`/`negativeColor` set.

**Examples:**
| Name | Keywords | Description |
|---|---|---|
| `driverListRevenueDrop` | driverlist, revenue | Briefing §3 "What drove the drop?" (5 drivers) |
| `driverListWithSummary` | driverlist, narrative | Leading `Note` + drivers |
| `driverListLimitOverflow` | driverlist, limit | 12 drivers, limit=5 → overflow row |
| `driverListBranded` | driverlist, color | `barColor` + positive/negative overrides |
| `driverListLoading` | driverlist, state | skeleton fallback |

### 3.2 `IndicatorCluster` (merges `HealthRow` + `StatusChecklist`)

```ts
export const IndicatorItemType = StructType({
    key: StringType,
    label: UIComponentType,
    status: VariantType({
        pass: NullType, warn: NullType, fail: NullType, unknown: NullType,
    }),
    details: OptionType(UIComponentType),                  // tooltip body
    color: OptionType(StringType),                         // per-item override
});

export const IndicatorClusterStyleType = StructType({
    labelColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    detailsColor: OptionType(StringType),
});

export const IndicatorClusterType = StructType({
    indicators: ArrayType(IndicatorItemType),
    orientation: OptionType(OrientationType),              // row (default) | column
    style: OptionType(VariantType({ compact: NullType, detailed: NullType })),
    density: OptionType(DensityType),
    label: OptionType(UIComponentType),                    // aria-label + optional visible
    state: OptionType(StateValueType),
    style2: OptionType(IndicatorClusterStyleType),         // renamed to avoid collision w/ style prop above
});
```

**Naming clash note.** The gap doc used `style` for both the `compact/detailed` variant and the colour-hatch struct. IR resolves this by renaming the colour-hatch field to `styleOverride` (or `theme`) in the final implementation. Prefer `styleOverride: IndicatorClusterStyleType` to preserve `style: compact|detailed` as the primary API knob.

**Renderer.** `compact` style renders each indicator as a `Status` chip with a dot; `detailed` renders a `{ Status, label, details }` row. `orientation: row` → `HStack wrap`; `column` → `VStack`. Tooltip wraps each indicator when `details` present. Per-indicator `color` overrides status-derived palette.

**Tests:**
- `status` maps to `Status` primitive tone + paired icon (§0.3).
- Tooltip activates on hover+focus.
- Row orientation wraps under narrow container.

**Examples:** `indicatorClusterCompact` (shift-optimiser `.health` row: "3 of 4 checks passing"), `indicatorClusterDetailed` (settings page with labels), `indicatorClusterVertical`.

### 3.3 `UncertaintyBadge`

```ts
export const UncertaintyKindType = VariantType({
    percent: NullType,      // "82% conf."
    range: NullType,        // "± 6h"
    "p-value": NullType,    // "p < 0.05"
});

export const HistoricalAccuracyType = StructType({
    rate: FloatType,        // 0..1
    horizon: VariantType({ "7d": NullType, "30d": NullType, "90d": NullType }),
    comparableCases: IntegerType,
});

export const UncertaintyBadgeStyleType = StructType({
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    iconColor: OptionType(StringType),
});

export const UncertaintyBadgeType = StructType({
    kind: UncertaintyKindType,
    value: FloatType,
    low: OptionType(FloatType),
    high: OptionType(FloatType),
    unit: OptionType(StringType),
    historicalAccuracy: OptionType(HistoricalAccuracyType),
    style: OptionType(UncertaintyBadgeStyleType),
});
```

**Factory.** `UncertaintyBadge.Root({ kind, value, low?, high?, unit?, historicalAccuracy?, style? })`.

**Renderer.** `MetricChip` (§1.7) with `tone: "info"` by default:
- `kind: percent` → `"82% conf."` (value × 100 + "% conf.").
- `kind: range` → `"± 6h"` (with `unit`).
- `kind: p-value` → `"p < 0.05"` (signature form).

When `historicalAccuracy` present, the chip wraps in a `ToggleTip` whose content reads:
`"Model was right 87% of the time on 241 comparable cases in the last 90 days."`

**A11y.** `aria-description` on chip carries the expanded form for screen readers regardless of kind.

**Tests:**
- All three kinds render correctly.
- `historicalAccuracy` activates ToggleTip.
- Style hatches surface.

**Examples:** `uncertaintyPercent`, `uncertaintyRange`, `uncertaintyPValue`, `uncertaintyWithHistorical`.

### 3.4 `LineageTrail` (minimal list-style)

```ts
export const LineageNodeKindType = VariantType({
    source: NullType, transform: NullType, model: NullType, output: NullType,
});

export const LineageIssueType = VariantType({
    stale: NullType, missing: NullType, error: NullType,
});

export const LineageNodeType = StructType({
    id: StringType,
    kind: LineageNodeKindType,
    label: UIComponentType,
    ref: OptionType(StringType),                           // optional href
    issue: OptionType(LineageIssueType),
    updatedAt: OptionType(DateTimeType),
    details: OptionType(UIComponentType),
});

export const LineageTrailStyleType = StructType({
    nodeBackground: OptionType(StringType),
    nodeBorderColor: OptionType(StringType),
    nodeColor: OptionType(StringType),
    connectorColor: OptionType(StringType),
    staleColor: OptionType(StringType),
    missingColor: OptionType(StringType),
    errorColor: OptionType(StringType),
});

export const LineageTrailType = StructType({
    nodes: ArrayType(LineageNodeType),
    orientation: OptionType(OrientationType),              // default row
    style: OptionType(LineageTrailStyleType),
});
```

**Factory.** `LineageTrail.Root(nodes, { orientation?, style? })`.

**Renderer.** Row orientation: horizontal `Flex` of node cards, separated by `→` connectors (`connectorColor`). Column orientation: vertical `Stack` of cards with connector lines between. Each card renders:
- `kind` icon at top-left (database / function / brain / box per kind).
- `label` (rich UIComp).
- `updatedAt` as relative time (via `Provenance.Stamp` delegation).
- `issue` as a `Status` chip bottom-right (paired icon per §0.3).
- Clickable if `ref` is set → opens link (new tab for external).

**Explicit "no NodeGraph" callout.** This pattern is intentionally list-style; the richer DAG visualisation is deferred. Document at the top of the pattern file.

**Tests:**
- Node kind → icon mapping.
- Issue status colouring via `staleColor`/`missingColor`/`errorColor`.
- `ref` renders as link vs non-clickable card.
- Orientation renders connectors appropriately.

**Examples:**
| Name | Keywords | Description |
|---|---|---|
| `lineageTrailBasic` | lineage, audit | 4 nodes: source → transform → model → output |
| `lineageTrailWithIssues` | lineage, issue | One node `issue: stale`, one `missing` |
| `lineageTrailVertical` | lineage, column | Column orientation for sidebar placement |
| `lineageTrailCompliance` | lineage, compliance | Used as Briefing §9 provenance drill-down |

### 3.5 `OutcomeScorecard` (Measure)

```ts
export const OutcomeMetricKindType = VariantType({
    "hit-rate": NullType, mae: NullType, mape: NullType, rmse: NullType, custom: NullType,
});

export const OutcomeHorizonType = VariantType({
    "7d": NullType, "30d": NullType, "90d": NullType, custom: NullType,
});

export const OutcomeScorecardStyleType = StructType({
    // inherits StatCard style
    goodRangeColor: OptionType(StringType),
    badRangeColor: OptionType(StringType),
});

export const OutcomeScorecardType = StructType({
    metric: OutcomeMetricKindType,
    value: UIComponentType,
    sampleSize: IntegerType,
    horizon: OutcomeHorizonType,
    trend: OptionType(DeltaPillType),                      // vs previous window
    detail: OptionType(UIComponentType),                   // tooltip / drill
    state: OptionType(StateValueType),
    style: OptionType(OutcomeScorecardStyleType),
});
```

**Factory.** `OutcomeScorecard.Root({ metric, value, sampleSize, horizon, trend?, detail?, state?, style? })`.

**Renderer.** A `StatCard` with:
- `label` = metric name ("Hit rate" / "MAE" etc.) + horizon suffix ("7d").
- `value` = the metric value rendered as `Numeric` with metric-appropriate format.
- `baseline` = `"n = <sampleSize>"` caption.
- `delta` = `trend` (vs previous window).
- `info` = `detail` in a ToggleTip.

`goodRangeColor` / `badRangeColor` override the StatCard `valueColor` based on metric-kind thresholds (caller doesn't encode thresholds; renderer accepts hints via `style`).

**Tests:** metric-kind formatting; `trend` direction sign; sample-size caption.

**Examples:** `outcomeHitRate30d`, `outcomeMae7d`, `outcomeCustomMetric`.

### 3.6 `ActualVsPredictedChart` (Measure)

```ts
export const ActualVsPredictedPointType = StructType({
    predicted: FloatType,
    actual: FloatType,
    decisionId: OptionType(StringType),
    at: OptionType(DateTimeType),
});

export const ActualVsPredictedViewType = VariantType({
    scatter: NullType,
    timeseries: NullType,
});

export const ActualVsPredictedStyleType = StructType({
    pointColor: OptionType(StringType),
    residualColor: OptionType(StringType),
    identityLineColor: OptionType(StringType),
    biasLineColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
});

export const ActualVsPredictedChartType = StructType({
    points: ArrayType(ActualVsPredictedPointType),
    view: OptionType(ActualVsPredictedViewType),           // default scatter
    residualBand: OptionType(BooleanType),
    biasLine: OptionType(BooleanType),
    onPointSelect: OptionType(FunctionType([StringType /* decisionId */], NullType)),
    state: OptionType(StateValueType),
    style: OptionType(ActualVsPredictedStyleType),
});
```

**Factory.** `ActualVsPredictedChart.Root({ points, view?, residualBand?, biasLine?, onPointSelect?, state?, style? })`.

**Renderer.**
- `view: scatter`: Recharts `<ScatterChart>`; x=predicted, y=actual; `ReferenceMarker` y=x identity line; optional linear-regression bias line (drawn client-side from points); residual band as area between identity and bias line.
- `view: timeseries`: dual-line `<LineChart>` over `at`; predicted and actual series on shared y-axis; residuals area between.
- On point click, fires `onPointSelect(decisionId)` if `decisionId` present. Callers typically open the associated `AuditTrail` entry.

**Tests:** bias line fit correctness (tolerance ±0.01); point click fires with correct id; reduced-motion disables point-in animations.

**Examples:** `actualVsPredictedScatter`, `actualVsPredictedTimeseries`, `actualVsPredictedWithResiduals`.

## 4. Contract compliance

- **§0.1 States** — `DriverList`, `OutcomeScorecard`, `ActualVsPredictedChart` accept `state` and render fallbacks. `IndicatorCluster` itself rarely loads; its parent Card does.
- **§0.2 A11y** —
  - `DriverList`: Table semantics; contribution bar announces percent; direction announced textually.
  - `IndicatorCluster`: each indicator is a keyboard-focusable element with `aria-describedby` pointing at details when present.
  - `UncertaintyBadge`: `aria-description` carries expanded form.
  - `LineageTrail`: navigable as an `<ol>` with kbd traversal; nodes with `ref` are `<a>` elements.
  - `ActualVsPredictedChart`: Recharts a11y plugin; point selection via keyboard (Tab to plot, Arrow keys to move cursor) per §0.2.
- **§0.3 Colour/dichromacy** — status tones paired with icons/labels. Contribution bars tinted, but percent always shown adjacent.
- **§0.4 Responsive** — `DriverList` compresses to `{name, contribution%}` under 480px. `LineageTrail` row collapses to column under 600px. `ActualVsPredictedChart` goes `timeseries` under 480px regardless of `view` (scatter requires minimum pixel budget).
- **§0.5 Hover intent** — `IndicatorCluster` tooltips use shared `HoverIntentType`. `UncertaintyBadge.historicalAccuracy` ToggleTip is click-persistent.
- **§0.8 Patches** — N/A for Explain/Measure; these are read-only surfaces. `ActualVsPredictedChart.onPointSelect` is a navigation callback, not a patch emitter.

## 7. Open questions

1. **DriverList contribution signedness.** `contribution: 0..1` is magnitude; direction carries sign. Debate whether to let `contribution` be signed instead. Stay with magnitude + direction — matches how drivers are typically reported (Shapley values pair magnitude and direction separately in charts).
2. **IndicatorCluster `style` naming collision.** Ship the IR as `style: StructType({ layout: ..., theme: ColourHatches })` to avoid renaming? Probably cleaner. Revisit during implementation.
3. **LineageTrail `details` on hover vs click.** Tooltip (hover) for short details, Popover (click) for longer? Simplify v1 as Tooltip only; if ≥2 apps want richer detail, promote to `InfoAffordance` usage (§1.12).
4. **OutcomeScorecard metric thresholds.** Where do "good"/"bad" thresholds come from? Caller supplies via `style.goodRangeColor` at the presentation layer for now. A future refinement could accept per-kind threshold structs so the renderer picks colour automatically.
5. **ActualVsPredictedChart bias-line algorithm.** OLS vs Theil-Sen. OLS for v1 (Recharts-friendly); expose via a future helper if robustness matters.
