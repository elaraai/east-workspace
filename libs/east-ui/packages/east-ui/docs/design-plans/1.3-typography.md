# 1.3 — Typography (`Text`, `Heading`, `Numeric`, `Note`, `Code`, `CodeBlock`, `Link`, `Highlight`, `Mark`, `List`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.3](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Migrate `Text`/`Heading` to `TextStyleType` (retire raw `fontSize` as public prop on these); add new `Numeric` and `Note` primitives; widen `Code`/`CodeBlock`/`Link`/`Highlight`/`Mark`/`List` with full colour / typography / sizing / border escape hatches; add rich items + a11y-correct markers to `List`. Apply the Type-shape convention (README §Type-shape convention, 0-conventions §3.8) across every typography component: content on main, **all visual props** inside a `style: OptionType(XxxStyleType)` sub-struct. This is a breaking shape change for every existing typography type — their current top-level visual fields (color, padding, margin, lineHeight, border*, overflow*, width/height, textAlign, textDecoration, etc.) move into the new style struct.
**Out of scope:** theme values (§1.1 plan).

## 3. Per-entry design

### 3.1 `Text` — main/style split + `textStyle` migration

```ts
export const TextStyleType_Escapes = StructType({
    // Typography
    textStyle: OptionType(TextStyleType),
    fontWeight: OptionType(FontWeightType),
    fontStyle: OptionType(FontStyleType),
    fontFamily: OptionType(FontFamilyType),
    fontVariantNumeric: OptionType(FontVariantNumericType),
    textAlign: OptionType(TextAlignType),
    textDecoration: OptionType(TextDecorationType),
    textTransform: OptionType(TextTransformType),
    textOverflow: OptionType(TextOverflowType),
    whiteSpace: OptionType(WhiteSpaceType),
    lineHeight: OptionType(StringType),
    letterSpacing: OptionType(StringType),
    // Colour
    color: OptionType(StringType),
    background: OptionType(StringType),
    // Border
    borderWidth: OptionType(BorderWidthType),
    borderStyle: OptionType(BorderStyleType),
    borderColor: OptionType(StringType),
    // Layout / sizing
    overflow: OptionType(OverflowType),
    overflowX: OptionType(OverflowType),
    overflowY: OptionType(OverflowType),
    width: OptionType(StringType),
    height: OptionType(StringType),
    minWidth: OptionType(StringType),
    minHeight: OptionType(StringType),
    maxWidth: OptionType(StringType),
    maxHeight: OptionType(StringType),
    padding: OptionType(PaddingType),
    margin: OptionType(MarginType),
    // Opacity
    opacity: OptionType(FloatType),
});
// In types.ts the export is named `TextStyleType` (matching Xxx + StyleType); rename above
// to avoid collision with the `TextStyleType` variant from §1.1 — e.g. `TextVisualStyleType`
// or keep `TextStyleType` and import the variant under a different alias within typography/.
// (See "Naming collision note" below.)

export const TextType = StructType({
    value: StringType,
    style: OptionType(TextStyleType /* the Text's visual struct — see naming note */),
});
```

**Naming collision note:** The token `TextStyleType` from §1.1 is the **variant** of typography scale names (`display-lg`, `body-md`, `mono-kpi`, etc.). The Text component's visual struct also wants to be called `TextStyleType`. Resolve by naming the component's struct **`TextVisualStyleType`** (visual-style struct for the Text component) and keeping `TextStyleType` for the token variant. Factory call-site stays `Text.Root(value, { style: { textStyle: "body-md", color: "red" } })` — `textStyle` inside the visual struct references the token variant.

**Migration mapping** (published in `THEME-CONTRACT.md`):
| Old `fontSize` | New `style.textStyle` |
|---|---|
| `xs` | `caption` |
| `sm` | `body-sm` |
| `md` | `body-md` |
| `lg` | `body-lg` |

**Factory:** `Text.Root(value, { style?: TextVisualStyle })`. Literal-union shorthands on style members (`style.textStyle: "body-md"`, `style.fontWeight: "bold"`, etc.) accepted for ergonomics. Any call site passing `fontSize` / top-level `color` / etc. gets a build-time error pointing to the migration path; no runtime stub (breaking change per §0.7).

**Examples added:**
- `textStyleScale` — every `style.textStyle` displayed in its own row.
- `textMonoKpi` — big mono number using `style: { textStyle: "mono-kpi" }`; auto `tabular-nums`.
- `textTabularNums` — column of right-aligned numbers lined up correctly.

### 3.3 `Numeric` (new)

Content/state on main (the number itself, its format, its sentiment classification, whether to show a sign). Every visual field in style (including the typography preset, which is a visual choice).

```ts
export const NumericFormatType = VariantType({
    Number: NumberFormatType,
    Currency: CurrencyFormatType,
    Percent: PercentFormatType,
    Compact: CompactFormatType,
    Unit: UnitFormatType,
});

export const NumericSentimentType = VariantType({
    positive: NullType, negative: NullType, neutral: NullType,
});

export const NumericVisualStyleType = StructType({
    // Typography preset (visual)
    textStyle: OptionType(TextStyleType),          // default "mono-kpi" at the renderer
    // Colour
    color: OptionType(StringType),                 // overrides sentiment-derived default
    background: OptionType(StringType),
    signColor: OptionType(StringType),             // distinct tint for leading +/−
    // Layout / sizing — optional overrides (typography rarely sets these; still allowed)
    padding: OptionType(PaddingType),
    margin: OptionType(MarginType),
    opacity: OptionType(FloatType),
});

export const NumericType = StructType({
    // Main — content / state / config
    value: FloatType,                              // factory coerces Integer to Float
    format: OptionType(NumericFormatType),         // content: how the number is formatted
    sentiment: OptionType(NumericSentimentType),   // semantic classification (drives colour tint)
    showSign: OptionType(BooleanType),             // config: whether to show leading +/−
    // Visual presentation
    style: OptionType(NumericVisualStyleType),
});
```

**Factory:** `Numeric.Root(value, { format?, sentiment?, showSign?, style? })`. Default `style.textStyle = "mono-kpi"` at the renderer when not set.

**Renderer:** `<Text style={{ textStyle: style?.textStyle ?? "mono-kpi", fontVariantNumeric: "tabular-nums", color: style?.color ?? sentimentColour(sentiment), background: style?.background }}>` + locale-aware `Intl.NumberFormat.format(value)`. Leading `+` / `−` split into a separate span when `style.signColor` is set.

**Examples** (4):
| Export | Description |
|---|---|
| `numericKpi` | `$1.84M`, `$2.07M` side by side in mono-kpi style |
| `numericPercent` | `98%`, `−12%` with sentiment colouring |
| `numericCompact` | `1.24M`, `384K` — compact notation |
| `numericUnit` | `12 kg`, `42.5 °C` with unit format |

Reference mockups: every KPI tile in `shift-optimiser-mockup.html` (lines 1139–1175 summary grid); Nestle briefing cover big numbers (`deck-v3.css` `.cred .stats .stat .num` — visual target only, not styles).

### 3.4 `Note` (new — absorbs SummaryNarrative)

`variant: narrative | callout | quote` is a **semantic content preset** (it changes the meaning / role of the note — is this narration, an alert, a quotation?), so it stays on main. `emphasis` is a visual preset → style.

```ts

    narrative: NullType, callout: NullType, quote: NullType,
});

export const NoteEmphasisType = VariantType({
    subtle: NullType, strong: NullType,
});

export const NoteVisualStyleType = StructType({
    emphasis: OptionType(NoteEmphasisType),
    // Colour
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    accentColor: OptionType(StringType),
    // Layout / sizing
    width: OptionType(StringType),
    maxWidth: OptionType(StringType),
    padding: OptionType(PaddingType),
    margin: OptionType(MarginType),
    opacity: OptionType(FloatType),
});

// Main variant (inline in component.ts — carries UIComp body):
Note: StructType({
    body: node,                                    // content (string coerces to Text.Root at factory)
    variant: NoteVariantType,                      // semantic content preset — main
    style: OptionType(NoteVisualStyleType),
});
```

**Factory:** `Note.Root(body, { variant = "narrative", style? })`. String body coerces to `Text.Root(s)` at the factory.

**Renderer:**
- `narrative` → dashed border-left accent, `fg.muted` body, `padding: { x: 3, y: 2 }`.
- `callout` → solid border-left accent in semantic-info palette, bold italic body.
- `quote` → indented, italic, with a subtle left accent.
- `style.emphasis` controls the accent stroke width + fg intensity.

**Examples** (3):
| Export | Description |
|---|---|
| `noteNarrative` | "A slow process rate combined with setpoint drift since 02:00 is delaying Stage 1 by ~6 hours." — the exact text from Nestle case A drawer (`Nestle CEO Briefing v3.html` line ~654) |
| `noteCallout` | "Raising this retrains the workforce chain model — expect ~30 min recompute." — from shift optimiser |
| `noteQuote` | Short customer quote from Nestle briefing |

### 3.10 `List`

Main = `{ items, style }`. `items: ArrayType(UIComponentType)` is content. Visual presets (`variant`, `marker`), layout (`gap`, `padding`, `margin`, `width`, etc.), and colour (`markerColor`, `color`) all live in style.

```ts
export const ListMarkerType = VariantType({
    disc: NullType, circle: NullType, square: NullType,
    decimal: NullType, none: NullType,
    check: NullType, dash: NullType, icon: IconType,
});

export const ListVisualStyleType = StructType({
    // Visual presets
    variant: OptionType(ListVariantType),          // ordered | unordered
    marker: OptionType(ListMarkerType),
    colorPalette: OptionType(StringType),
    // Layout
    gap: OptionType(StringType),
    overflow: OptionType(OverflowType),
    overflowX: OptionType(OverflowType),
    overflowY: OptionType(OverflowType),
    width: OptionType(StringType),
    height: OptionType(StringType),
    minWidth: OptionType(StringType),
    minHeight: OptionType(StringType),
    maxWidth: OptionType(StringType),
    maxHeight: OptionType(StringType),
    padding: OptionType(PaddingType),
    margin: OptionType(MarginType),
    opacity: OptionType(FloatType),
    // Colour
    color: OptionType(StringType),                 // item text default
    markerColor: OptionType(StringType),           // marker tint
});

// Main variant (inline in component.ts — carries recursive `node` children):
List: StructType({
    items: ArrayType(node),
    style: OptionType(ListVisualStyleType),
});
```

**Factory:** `List.Root(items, { style? })`. Factory coerces `items: string[]` → `items: Array<Text.Root(s)>`.

**A11y:** `style.marker: "check"` / `"dash"` renders `<FontAwesomeIcon role="img" aria-label="completed">` (or appropriate) — **not a CSS `::before` character** (SR would skip).

**Examples added:**
- `listCheckmarks` — mirrors shift-optimiser `.wf-constraints` list (line ~1249 in Nestle briefing): "Max 5 consecutive shifts — 412 staff, clear" etc. with `style: { marker: "check", markerColor: "fg.success" }`.
- `listDashed` — "problem-notes" style from Nestle briefing (`.problem-notes`): `style: { marker: "dash", markerColor: "fg.danger" }` + italic body.
- `listIconMarkers` — icon-marker variant where each item has its own leading icon.
