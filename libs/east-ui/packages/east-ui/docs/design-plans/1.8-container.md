# 1.8 — Container (`Card` with compound helpers + state contract)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.8](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Keep current `Card` IR shape at the content level, add compound helpers (`Card.Header`, `Card.Title`, `Card.Description`, `Card.Body`, `Card.Footer`, `Card.Section`, `Card.Actions`); add `state: StateValueType` on main (runtime state with IR-factory fallback rendering); move visual presets — `elevation`, `variant`, `size`, dimensions, `overflow`, `flex` — INTO `CardStyleType` per the Type-shape convention (README §Type-shape convention, 0-conventions §3.8). Cards are the canonical state-contract consumer — most §2 patterns inherit state handling from here.
**Out of scope:** any pattern that embeds Card (their plans consume this).

## 3. Per-entry design

### 3.1 Card IR

```ts
// in component.ts
Card: StructType({
    // Content
    header: OptionType(node),
    body: ArrayType(node),
    footer: OptionType(node),
    // Runtime state (drives fallback-body rendering in the renderer)
    state: OptionType(StateValueType),
    // Visual
    style: OptionType(CardStyleType),
}),

// src/container/card/types.ts
export const CardStyleType = StructType({
    // Visual presets
    variant: OptionType(CardVariantType),          // elevated | outline | subtle
    size: OptionType(SizeType),
    elevation: OptionType(ElevationType),          // flat | raised | overlay | floating | modal
    // Layout / sizing
    width: OptionType(StringType),
    height: OptionType(StringType),
    minWidth: OptionType(StringType),
    minHeight: OptionType(StringType),
    maxWidth: OptionType(StringType),
    maxHeight: OptionType(StringType),
    flex: OptionType(StringType),
    overflow: OptionType(OverflowType),
    // Colour slots
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    headerBackground: OptionType(StringType),
    footerBackground: OptionType(StringType),
    accentColor: OptionType(StringType),           // left/top emphasis stripe
});
```

`state` stays on **main** — it's runtime state the app owns (not a presentation choice). The renderer switches on `state` to pick a body fallback (see §3.3). `elevation` / `variant` / `size` and dimensions are all visual → `style`.

### 3.2 Compound helpers (factory helpers, not new IR variants)

Each returns an `ExprType<UIComponentType>` that's recognisable when nested inside Card.header / Card.body / Card.footer:

- `Card.Header({ title, description?, actions?, eyebrow?, style? })` — returns a Stack/Flex-composed header.
- `Card.Title(value, { textStyle?, style? })` — wraps `Heading` with a semantic-h3 default.
- `Card.Description(value, { style? })` — wraps `Text` at `textStyle: "body-sm"`, `color: "fg.muted"`.
- `Card.Body(children, { padded?, style? })` — wraps `Box` with default padding; `padded: false` for no-pad content (e.g. tables).
- `Card.Footer({ children, actions?, style? })` — wraps `Flex` with space-between.
- `Card.Section({ title?, children, style? })` — horizontal-rule separated section inside Card.body; used for multi-section cards.
- `Card.Actions(buttons, { placement?: "start"|"end" })` — a `ChipRail`-like row of buttons, usually inside Card.Header.

These compile to plain Box/Flex/Heading/Text IR — **no new variants in `UIComponentType`**. Purely factory-side helpers.

### 3.3 `state` fallback contract

The **IR factory** sets a default `state: variant("ready", null)`. The **renderer** switches on `state`:

| State | Renderer picks |
|---|---|
| `ready` | Renders `header` / `body` / `footer` normally |
| `loading` | Renders `Skeleton` sized to body slots (heuristic: if `body` contains Table → SkeletonRows; if StatCard → SkeletonText; default 3 lines); header still rendered if present |
| `empty` | Renders `EmptyState` in the body; header still rendered if present |
| `error` | Renders `ComputeError` in the body |
| `stale` | Renders body at `opacity: 0.6` with a `StaleDataBanner` overlay on the body |
| `disabled` | Renders body with `aria-disabled="true"` + `opacity: 0.5` |
| `permission-denied` | Renders `AccessDeniedState` in the body |

The fallback render is **renderer-only** — IR carries only the `state` enum + body. Cards built on top (StatCard, ActionCard, ParameterFormSection) inherit this automatically.

### 3.4 `elevation` (inside `style`)

`elevation: OptionType(ElevationType)` lives inside `CardStyleType`. Renderer reads the `style/elevation.ts` helper (§1.1 plan). Default `flat`.

- [ ] All seven states render correct fallback in the showcase.
- [ ] `style.elevation` maps to theme shadow tokens.
