# 2.4 — Compare patterns (`DeltaPill`, `ContextSelector`, `VersusHeader`, `DiffView`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §2.4](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** The Compare-mode patterns. `DiffView` is the structural centrepiece — it renders directly from a `Patch<T>` and is reused by `CommitConfirmDialog` (§2.3), `DraftPublishBar` (§2.5), `AuditTrail` (§2.6), and ad-hoc compare views. `DeltaPill` is the chip building block used across Observe/Explain/Decide/Compare.

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** content (`value`, `unit`, `percent`, `direction`, `label`, `a`, `b`, `delta`, `base`, `after`, `patch`, `items`, `description`) + semantic classification (`magnitude`, `ci`, `significant`) + config (`stateType`, `hideUnchanged`) + behaviour (`onSwapA`, `onSwapB`, `onChange`) on main. Visual presets (`size`, `iconPosition`, `mode`) + colour slots (`color`, `background`, `borderColor`, `iconColor`, `addedBackground`, `removedBackground`, etc.) in `style: OptionType(XxxStyleType)`.

**Out of scope:** `ComparisonRow` / `BaselineRibbon` (absorbed into `StatCard` layouts, §2.1); `ComparisonMatrix` (recipe via `Matrix` + `StatCard` cells).

## 3. Per-entry design

### 3.1 `DeltaPill`

**Wireframe:** [`wireframes/2.4/delta-pill.svg`](./wireframes/2.4/delta-pill.svg)


**East IR type:**
```ts
export const DeltaDirectionType = VariantType({
    up: NullType, down: NullType, flat: NullType,
});

export const DeltaMagnitudeType = VariantType({
    "higher-is-better": NullType,
    "lower-is-better": NullType,
    "target-is-best": StructType({
        target: FloatType,
        tolerance: OptionType(FloatType),
    }),
});

export const DeltaPillStyleType = StructType({
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    iconColor: OptionType(StringType),
});

export const DeltaPillType = StructType({
    value: UIComponentType,                                // Numeric or Text (e.g. "+3.2")
    unit: OptionType(StringType),
    percent: OptionType(FloatType),                        // if present, renders "(+4.1%)"
    direction: DeltaDirectionType,
    magnitude: OptionType(DeltaMagnitudeType),
    ci: OptionType(StructType({ low: FloatType, high: FloatType })),
    significant: OptionType(BooleanType),                  // default true
    size: OptionType(SizeType),
    iconPosition: OptionType(VariantType({ start: NullType, end: NullType, none: NullType })),
    style: OptionType(DeltaPillStyleType),
});
```

**Factory.** `DeltaPill.Root({ value, direction, magnitude?, percent?, ci?, significant?, size?, iconPosition?, unit?, style? })`.

**Tone resolution.** (Implemented in IR factory — sets a tone token the renderer uses to pick default colour.)
- `higher-is-better` + `up` = positive; `down` = negative.
- `lower-is-better` + `up` = negative; `down` = positive.
- `target-is-best`: compute `|value - target|` vs `tolerance`. Within tolerance = neutral; outside = negative regardless of direction.
- `flat` direction = neutral regardless of magnitude.
- If `significant: false`, tone is muted (e.g. gray with asterisk marker).

**React renderer.** `MetricChip` with tone + paired icon (`FA chevron-up`/`chevron-down`/`minus`). `value` rendered as a `Numeric` with `mono-kpi` textStyle when numeric. `percent` rendered trailing in a slightly smaller size. `ci` rendered as `" ± [low..high]"` suffix. `significant: false` adds a `*` glyph and renders at 60% opacity.

**Tests:**
- Magnitude × direction truth table for tone.
- Target-is-best tolerance boundary.
- `significant: false` mutes.
- `ci` decoration.
- Style hatch overrides tone.

**Examples:**
| Name | Description |
|---|---|
| `deltaPillRevenueUp` | `+3.2 (+4.1%)`, `higher-is-better`, up → green |
| `deltaPillDefectsDown` | `-0.8%`, `lower-is-better`, down → green |
| `deltaPillOffTarget` | `target-is-best` over-tolerance → red |
| `deltaPillInsignificant` | `significant: false` → muted with asterisk |
| `deltaPillWithCi` | `+2.1 ± [0.5..3.7]` |
| `deltaPillBranded` | All four style hatches set |

### 3.4 `DiffView` (patch-typed)

**Wireframe:** [`wireframes/2.4/diff-view.svg`](./wireframes/2.4/diff-view.svg)


```ts
export const DiffViewModeType = VariantType({
    inline: NullType,                                      // in-place visual
    "side-by-side": NullType,                              // two-column
    unified: NullType,                                     // github-style unified diff
});

export const DiffViewStyleType = StructType({
    addedBackground: OptionType(StringType),
    addedColor: OptionType(StringType),
    removedBackground: OptionType(StringType),
    removedColor: OptionType(StringType),
    changedBackground: OptionType(StringType),
    changedColor: OptionType(StringType),
    unchangedColor: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    lineNumberColor: OptionType(StringType),               // for string/code diffs
});

export const DiffViewType = StructType({
    stateType: TypeType,                                   // T
    base: ExprType,                                        // T
    after: OptionType(ExprType),                           // T — supply either after or patch
    patch: OptionType(ExprType),                           // PatchTypeOf<T>
    mode: OptionType(DiffViewModeType),
    hideUnchanged: OptionType(BooleanType),                // default false
    maxDepth: OptionType(IntegerType),                     // for nested structs/arrays
    pathFilter: OptionType(ArrayType(StringType)),         // limit to paths matching prefixes
    style: OptionType(DiffViewStyleType),
});
```

**Factory.** `DiffView.Root<T>({ stateType, base, after?, patch?, mode?, hideUnchanged?, maxDepth?, pathFilter?, style? })`. Factory asserts exactly one of `after` / `patch` is supplied.

**Renderer — patch-structure-driven.** Per `@elaraai/east/patch` ([`types.ts`](../../../east/src/patch/types.ts)), every patch is `variant<unchanged | replace({before, after}) | patch(...)>`. The renderer dispatches on the variant tag, walking the inner `patch` payload per East type:

| East type | Patch shape (`PatchTypeOf<T>`) | Rendered as |
|---|---|---|
| Primitive (Int/Float/String/Bool/DateTime/Blob/Vector/Matrix) | `unchanged \| replace { before, after }` | Inline `[before] → [after]` chip with removed/added tints |
| `Ref<V>` | `unchanged \| replace \| patch: PatchTypeOf<V>` | Falls through to V's renderer when `patch` |
| `Array<E>` | `unchanged \| replace \| patch: Array<{ key, offset, operation: delete(E) \| insert(E) \| update(PatchTypeOf<E>) }>` | Ordered op rows; `delete` red strikethrough, `insert` green, `update` two-tone (recurse) — there is no Move op |
| `Set<K>` | `unchanged \| replace \| patch: Dict<K, delete \| insert>` | Two sections: keys deleted (red) + inserted (green); no payload |
| `Dict<K,V>` | `unchanged \| replace \| patch: Dict<K, delete(V) \| insert(V) \| update(PatchTypeOf<V>)>` | Per-key row tinted by op; `update` recurses into V's renderer |
| `Struct<Fields>` | `unchanged \| replace \| patch: Struct<{ [F]: PatchTypeOf<Fields[F]> }>` | One row per field; recurses; `unchanged` field rows elide when `hideUnchanged` |
| `Variant<Cases>` | `unchanged \| replace \| patch: Variant<{ [Tag]: PatchTypeOf<Cases[Tag]> }>` | Same-tag → render tag with indented sub-patch; cross-tag changes are emitted as `replace`, not `patch` |
| `Recursive<Node>` | `unchanged \| replace` only (no `patch` case) | Whole-tree replace, rendered via the type-of-record renderer |

The renderer is a recursive pure React function keyed on patch shape. Mode switches layout:
- `inline`: single column rendering, changes inline with `[old] → [new]` chips.
- `side-by-side`: two-column `<Table>` with left=base, right=after; changed rows tinted.
- `unified`: GitHub-style "- [old]" + "+ [new]" lines with optional line numbers (for string fields that look like multi-line text).

**Special handling for strings.** If the patch is a `Replace(oldStr, newStr)` on a string with line breaks, renderer uses a line-diff algorithm (Myers) to produce a code-style diff. Code-block fields (detected heuristically or opted into via `pathFilter`) render with `CodeBlock` primitive.

**Tests:**
- Round-trip: supplying `after` produces the same render as supplying `East.diff(base, after)`.
- Each patch variant renders the specified visual form.
- `hideUnchanged` elides unchanged rows.
- `pathFilter` limits render scope.
- Nested struct/array patches recurse correctly.
- String line-diff for multi-line values.

**Examples:**
| Name | Description |
|---|---|
| `diffViewStructSimple` | Struct with 2 changed fields |
| `diffViewArrayOps` | Array with insert/remove/move/replace |
| `diffViewDictChanges` | Dict with added/removed/changed keys |
| `diffViewVariantTagChange` | Variant tag changed |
| `diffViewNestedDeep` | 3-level nested struct with partial changes |
| `diffViewUnifiedMode` | Unified mode showing multi-line string diff |
| `diffViewHideUnchanged` | Large struct, only changed fields shown |
| `diffViewBranded` | All colour escape hatches set |

**Consumed by.**
- `CommitConfirmDialog` (§2.3) — passes `patch` directly.
- `DraftPublishBar.onReviewDiff` (§2.5) — renders composed drafts.
- `AuditTrail.onInspect` (§2.6) — per-entry patch.
- Standalone — apps can render arbitrary compares.

## 4. Contract compliance

- **§0.1 States** — `DiffView` with empty patch renders `"No changes"` (empty state). `DeltaPill` is always immediate.
- **§0.2 A11y** —
  - `DeltaPill` direction arrow paired with text + ARIA description ("up 3.2").
  - `ContextSelector` menu trigger has `aria-haspopup="menu"`.
  - `VersusHeader` swap buttons have `aria-label="Swap A"`/`"Swap B"`.
  - `DiffView` table semantics when `side-by-side`; each changed row announces "changed", added "added", removed "removed" via `aria-label` on the row.
- **§0.3 Colour/dichromacy** — DiffView added/removed/changed tints paired with `+`/`-`/`~` glyphs (never colour-only). DeltaPill direction arrow + colour.
- **§0.4 Responsive** — `VersusHeader` collapses to column under 480px. `DiffView` `side-by-side` degrades to `unified` under 768px.
- **§0.5 Hover intent** — N/A.
- **§0.8 Patches** — DiffView is **the** pattern that demonstrates patches. Every downstream pattern that needs to show "what changed" consumes it.

## 7. Open questions

1. **DiffView rendering for Blob / Bytes types.** No structural diff is meaningful. Render as `"[binary payload changed, N bytes]"`. Flagged in the spec — avoid attempting a byte-diff.
2. **DiffView Table vs Grid for side-by-side.** Table semantics preferred (keyboard nav + screen-reader friendly). Use `Table` primitive with frozen first column for path names.
3. **DiffView line-diff dependency.** Myers algorithm is ~100 lines hand-rolled; alternatively pull `diff-match-patch` (~30 KB). Hand-roll for core; lazy-load `diff-match-patch` only if a future "large-text diff" mode is introduced.
4. **DeltaPill CI decoration placement.** Inline (`+2.1 ± [0.5..3.7]`) vs tooltip? Inline for now — matches the gaps doc. Consider a tooltip-only mode if pills get too wide in dense tables.
5. **DiffView depth limit for nested structs.** Default `maxDepth: 4`; beyond that render `"…"` with a "Show more" toggle per branch. Document the default.
