# 1.12 — Overlays (`Tooltip`, `ToggleTip`, `Menu`, `Dialog`, `Drawer`, `Popover`, `HoverCard`, `ActionBar`, + new `CommandPalette`, `InfoAffordance`, `Tour`, `CoachMark`)

**Gaps-doc reference:** [`COMPONENT_AND_PATTERN_GAPS.md` §1.12](../COMPONENT_AND_PATTERN_GAPS.md).
**Scope:** Widen existing eight overlays with rich content (`UIComponentType`), consistent `hoverIntent`, colour escape hatches, and IR-enforced focus-trap + ESC + outside-click on Dialog/Drawer/Popover. Add four new primitives: `CommandPalette` (⌘K launcher), `InfoAffordance` (richness → overlay dispatcher), `Tour` (guided walkthrough), `CoachMark` (one-shot inline hint).

**Type-shape convention (README §Type-shape convention, 0-conventions §3.8):** content (`trigger`, `content`, `body`, `title`, `description`, `items`, `commands`, `steps`, `recents`, `scopes`, `label` strings), state (`open`, `stepIndex`, `selectionCount`, `visible`), config (`closeOnOverlay`, `closeOnEsc`, `initialFocus`, `returnFocus`, `skippable`, `dismissible`, `showOnce`, `triggerKey`, `scope.filter`), and behaviour (`onOpenChange`, `onSelect`, `onStepChange`, `onComplete`, `onSkip`, `onDismiss`, `onClick` on item structs) all stay on main. Visual presets (`size`, `placement`, `hasArrow`, `hoverIntent`) + colour slots live in `style`. `hoverIntent` is a visual-timing preset (it shapes the hover affordance) — `style`, not main.

**Out of scope:** `Print.preview` (deferred per §1.14); cross-mode pattern plans (see §2.x).

## 1. Dependencies

- Chakra v3 overlay primitives: `<Tooltip.Root>`, `<Menu.Root>`, `<Dialog.Root>`, `<Drawer.Root>`, `<Popover.Root>`, `<HoverCard.Root>`. All use `@zag-js/*` for state machines and `floating-ui` for positioning.
- `cmdk` (~3KB, peer-optional per §UI-9) for `CommandPalette` fuzzy matching. Bundled behind a dynamic `import()` in the renderer so apps that don't use `CommandPalette` pay zero bytes.
- `HoverIntentType`, `FocusStyleType` — from §1.1.
- `State.bind` — for `CoachMark.showOnce` keyed dismissal.
- **No** new deps for `Tour` or `CoachMark` — they're Popover + step-machine.

## 3. Per-entry design

### 3.1 `Tooltip`

**East IR type (in `types.ts`):**
```ts
export const TooltipStyleType = StructType({
    // Positioning / visual presets
    placement: OptionType(PlacementType),
    hasArrow: OptionType(BooleanType),
    hoverIntent: OptionType(HoverIntentType),      // §1.1 — visual timing preset
    // Colour slots
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    arrowColor: OptionType(StringType),
});

export const TooltipType = StructType({
    trigger: UIComponentType,
    content: UIComponentType,                      // was StringType
    style: OptionType(TooltipStyleType),
});
```

**Factory signature.**
```ts
Tooltip.Root(trigger: UIComp, content: string | UIComp, opts?: TooltipStyle)
```
Factory coerces `content: string` → `Text.Root(s, { textStyle: "body-xs" })`.

**React renderer.** `toChakraTooltip(value)` returns `<Tooltip.Root openDelay={hoverIntent.openDelay} closeDelay={hoverIntent.closeDelay}>` wrapping `<Tooltip.Trigger>{toChakra(trigger)}</Tooltip.Trigger>` and `<Tooltip.Content><Tooltip.Arrow css={{ '--arrow-background': style.arrowColor }}/>{toChakra(content)}</Tooltip.Content>`. Style escape hatches map to `css={{ color, background, borderColor }}`. A11y: Chakra handles `role="tooltip"` + `aria-describedby` wiring.

**Tests (`test/overlays/tooltip.spec.ts`):**
- `content: string` coerces to `Text.Root` in IR.
- `content: UIComp` passthrough.
- `hoverIntent` defaults (openDelay=400, closeDelay=200).
- `placement` variants round-trip.
- `style.arrowColor` present on output.

**Examples (`test/overlays/tooltip.examples.ts`):**
| Name | Keywords | Mockup |
|---|---|---|
| `tooltipBasic` | tooltip, label | shift-optimiser `.muted` icon affordances |
| `tooltipRichKpi` | tooltip, kpi, explain | Briefing §2 KPI rail hover |
| `tooltipDelayed` | tooltip, hover-intent | — |
| `tooltipInfoTint` | tooltip, brand | info-tinted warning tooltip (color: status-token info) |

**Showcase:** Overlays page, "Tooltip" card.

### 3.2 `ToggleTip`

Identical change to Tooltip. Difference from Tooltip is that it's click-opened (persists until outside-click), so `hoverIntent` is optional and primarily used for the kbd-activated variant (`Enter` opens after focus+delay).

**Examples:** `toggleTipInfoIcon` — rich "Why?" explainer in the ActionCard rationale panel.

### 3.3 `Menu` — rich items

**East IR type:**
```ts
export const MenuItemType = StructType({
    value: StringType,
    label: UIComponentType,                        // was StringType
    icon: OptionType(IconType),
    description: OptionType(UIComponentType),      // sub-line
    shortcut: OptionType(StringType),              // "⌘K" etc. — right-aligned
    disabled: OptionType(BooleanType),
});

export const MenuGroupType = StructType({
    label: OptionType(UIComponentType),
    items: ArrayType(MenuEntryType),
});

// Recursive (submenu children are more entries)
export const MenuEntryType: VariantType = VariantType({
    Item: MenuItemType,
    Group: MenuGroupType,
    Submenu: StructType({
        label: UIComponentType,
        icon: OptionType(IconType),
        items: ArrayType(MenuEntryType),
    }),
    Separator: NullType,
});

export const MenuStyleType = StructType({
    // Positioning / visual preset
    placement: OptionType(PlacementType),
    // Colour slots
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    itemColor: OptionType(StringType),
    itemHoverBackground: OptionType(StringType),
    selectedBackground: OptionType(StringType),
    separatorColor: OptionType(StringType),
});

export const MenuType = StructType({
    // Content
    trigger: UIComponentType,
    items: ArrayType(MenuEntryType),
    // Behaviour
    onSelect: OptionType(FunctionType([StringType], NullType)),
    // Visual
    style: OptionType(MenuStyleType),
});
```

**Factory helpers:**
- `Menu.Root(trigger, items, opts)` — top level.
- `Menu.Item({ value, label, icon?, description?, shortcut?, disabled? })`.
- `Menu.Group({ label?, items })`.
- `Menu.Submenu({ label, icon?, items })`.
- `Menu.Separator()`.

**Renderer.** Chakra `<Menu.Root>`; submenu → nested `<Menu.Root>` inside `<Menu.Item>` with `positioning={{ placement: "right-start" }}`. Shortcut right-aligned in `<Menu.ItemCommand>`. Icon left-slotted. `description` below label in `body-xs` `fg.muted`.

**Examples:**
- `menuWithShortcuts` — export / duplicate / delete with keystroke hints.
- `menuWithGroups` — "Actions" / "Developer" groups (Briefing §7 export menu).
- `menuWithSubmenus` — "Export → CSV / XLSX / JSON".

### 3.4 `Dialog`

**East IR type:**
```ts
export const DialogPlacementType = VariantType({ center: NullType, top: NullType });

export const DialogStyleType = StructType({
    // Visual presets
    size: OptionType(SizeType),
    placement: OptionType(DialogPlacementType),
    // Colour slots
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    overlayColor: OptionType(StringType),
    headerBackground: OptionType(StringType),
    footerBackground: OptionType(StringType),
    color: OptionType(StringType),
});

export const DialogType = StructType({
    // Content
    trigger: UIComponentType,
    title: OptionType(UIComponentType),            // was OptionType(StringType)
    description: OptionType(UIComponentType),      // same
    body: ArrayType(UIComponentType),
    footer: OptionType(UIComponentType),
    // Config / behaviour
    closeOnOverlay: OptionType(BooleanType),       // default true
    closeOnEsc: OptionType(BooleanType),           // default true
    initialFocus: OptionType(StringType),          // CSS selector or data-attr
    returnFocus: OptionType(BooleanType),          // default true
    // State
    open: OptionType(BooleanType),
    // Behaviour
    onOpenChange: OptionType(FunctionType([BooleanType], NullType)),
    // Visual
    style: OptionType(DialogStyleType),
});
```

**Factory.** Coerces `title: string` → `Card.Title(s)` and `description: string` → `Card.Description(s)`.

**Renderer.** Chakra `<Dialog.Root>` with `<Dialog.Backdrop>` `<Dialog.Positioner>` `<Dialog.Content>`. Focus trap is native to Chakra but **renderer enforces**: `closeOnOverlay: false` disables the `<Dialog.Backdrop onClick>`; `closeOnEsc: false` attaches `onKeyDown` that swallows Escape; `initialFocus` uses `useInitialFocusRef` pointing at the selector; `returnFocus` preserved via Chakra's default. A11y: renderer asserts at least one of `title` or `description` is present (warn if both absent — screen reader needs an accessible name).

**Colour escape hatches.** `overlayColor` → `css={{ '--overlay-color': ... }}` on backdrop; `headerBackground` on `<Dialog.Header>`; `footerBackground` on `<Dialog.Footer>`; `color` is text colour on body.

**Examples:**
- `dialogConfirm` — destructive confirm with `status-token danger` header tint.
- `dialogRichTitle` — title with an icon prefix (`HStack(Icon, Heading)`).
- `dialogForm` — embedded `ParameterFormSection`.
- `dialogBrandedCompliance` — compliance-coloured warning dialog (headerBackground = warning-surface).

### 3.5 `Drawer`

Same widen as Dialog. Adds `placement: VariantType({ start, end, top, bottom })`. Renderer uses Chakra `<Drawer.Root>`. Two-column drawer examples (one body / one footer action row) — no new IR, just compositions.

**Examples:**
- `drawerSidePanel` — right-side properties drawer (shift-optimiser `.side-panel` region).
- `drawerWithScrollableBody` — pairs with `ScrollArea` from §1.2.

### 3.6 `Popover`

Same widen. Renderer: `<Popover.Root>` with `<Popover.Trigger>`, `<Popover.Content>`. No backdrop by default — `closeOnOverlay` still accepted but unused (popovers close on outside-click unconditionally). A11y: `aria-haspopup="dialog"` if body contains interactive content; `aria-haspopup="listbox"` if items look like a list (heuristic: body is single list primitive).

**Examples:**
- `popoverDatePicker` — wraps `DateInput` in a popover trigger.
- `popoverFilters` — filter chip row with apply/reset footer.

### 3.7 `HoverCard`

Add `hoverIntent: OptionType(HoverIntentType)` and `style: OptionType(HoverCardStyleType)`. Renderer: Chakra `<HoverCard.Root openDelay closeDelay>`. Style hatches: `background`, `borderColor`, `arrowColor`.

**Examples:**
- `hoverCardPerson` — avatar + role + contact; hover a user avatar.
- `hoverCardSourceMetric` — metric name → lineage summary (Briefing Provenance pattern).

```ts

    group: OptionType(StringType),

    action: FunctionType([], NullType),

export const CommandScopeType = StructType({
    label: UIComponentType,
    filter: FunctionType([StringType], BooleanType), // command.id → included
});

export const CommandPaletteStyleType = StructType({
    size: OptionType(SizeType),
    // Colour slots
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    inputBackground: OptionType(StringType),
    inputColor: OptionType(StringType),
    itemColor: OptionType(StringType),
    selectedBackground: OptionType(StringType),
    selectedColor: OptionType(StringType),
    groupLabelColor: OptionType(StringType),
});

export const CommandPaletteType = StructType({
    // Content / config
    commands: ArrayType(CommandType),
    placeholder: OptionType(StringType),
    recents: OptionType(ArrayType(StringType)),     // command ids
    scopes: OptionType(ArrayType(CommandScopeType)),
    triggerKey: OptionType(StringType),             // default "mod+k"
    // State
    open: OptionType(BooleanType),                  // controlled
    // Behaviour
    onOpenChange: OptionType(FunctionType([BooleanType], NullType)),
    // Visual
    style: OptionType(CommandPaletteStyleType),

```

**Factory.** `CommandPalette.Root({ commands, placeholder?, recents?, scopes?, triggerKey? })`. `CommandPalette.Command({...})` helper for ergonomic item authoring.

**Renderer.** Wraps `cmdk`'s `<Command.Dialog>` (dynamic import). **Examples:**
- `commandPaletteBasic` — 10 commands, no groups.
- `commandPaletteGrouped` — "Navigate / Actions / Settings" groups.
- `commandPaletteWithScopes` — "All / Scenarios / Data" scope chips filter commands.
- `commandPaletteWithRecents` — last-used commands surface at top.

### 3.10 `InfoAffordance` (new — richness-dispatch recipe-as-primitive)

```ts
export const InfoRichnessType = VariantType({
    label: NullType,        // short text → Tooltip
    brief: NullType,        // richer explainer → ToggleTip
    structured: NullType,   // layout / image → HoverCard
    interactive: NullType,  // form / chart → Popover
});

export const InfoAffordanceStyleType = StructType({
    placement: OptionType(PlacementType),
    // Colour slots — passthrough subset; renderer forwards only keys the chosen overlay supports
    color: OptionType(StringType),
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    arrowColor: OptionType(StringType),
});

export const InfoAffordanceType = StructType({
    // Content / richness classification
    trigger: UIComponentType,
    content: UIComponentType,
    richness: InfoRichnessType,
    // Visual
    style: OptionType(InfoAffordanceStyleType),
});
```

**Factory.** `InfoAffordance.Root({ trigger, content, richness, ... })`. IR factory **inlines** the choice — returns the appropriate overlay variant (`Tooltip`/`ToggleTip`/`HoverCard`/`Popover`) directly, forwarding trigger/content/placement/style. No new variant in `UIComponentType` — it's a factory-only construct. Downside: loses `richness` from serialised IR, but simplifies the renderer (no dispatch needed) and keeps bundle size down.

**Tests.** Each richness value produces an IR with the matching root variant tag.

**Examples:**
- `infoAffordanceRichnessLabel` — "Units: hL" on a table column header.
- `infoAffordanceRichnessBrief` — "What is rotation plan?" explainer.
- `infoAffordanceRichnessStructured` — Lineage / source / last updated card.
- `infoAffordanceRichnessInteractive` — Mini form "Edit threshold".

### 3.11 `Tour` (new)

```ts
export const TourStepType = StructType({
    target: StringType,                  // CSS selector or data-tour-target="id"
    title: UIComponentType,
    body: UIComponentType,
    skippable: OptionType(BooleanType),  // default true
    placement: OptionType(PlacementType), // per-step visual placement — kept on the step for flexibility
});

export const TourStyleType = StructType({
    // Colour slots
    background: OptionType(StringType),
    borderColor: OptionType(StringType),
    highlightColor: OptionType(StringType),      // ring around target
    overlayColor: OptionType(StringType),        // dim rest of screen
});

export const TourType = StructType({
    // Content / config
    steps: ArrayType(TourStepType),
    triggerKey: OptionType(StringType),          // "mod+shift+?"; optional auto-start key
    // State
    open: OptionType(BooleanType),               // controlled
    stepIndex: OptionType(IntegerType),          // controlled step
    // Behaviour
    onStepChange: OptionType(FunctionType([IntegerType], NullType)),
    onComplete: OptionType(FunctionType([], NullType)),
    onSkip: OptionType(FunctionType([], NullType)),
    // Visual
    style: OptionType(TourStyleType),

```

**Renderer.** Fullscreen dimmed `<Portal>` overlay with a cutout ring drawn around `document.querySelector(step.target)`. Step popover anchored to same target via floating-ui. Buttons: "Back" / "Next" / "Skip" / "Finish". Keyboard: Arrow-left/right step; Esc = skip. A11y: each step is a `role="dialog"` with `aria-labelledby` pointing at `title`. `prefers-reduced-motion` disables the highlight-ring pulse animation.

**Examples:** `tourFirstRun` — 4-step intro to a scenario workspace (click the editor → run a scenario → view result → commit).

## 4. Contract compliance

- **§0.1 States** — `Dialog`/`Drawer`/`Popover`/`Menu` consume their body's state contract; if the body is a Card with `state: "loading"`, overlay shows skeleton.
- **§0.2 A11y** — Focus trap enforced in renderer for Dialog/Drawer; ESC always closes unless `closeOnEsc: false`; focus returns to trigger by default. `CommandPalette` keyboard: Up/Down navigate, Enter selects, Esc closes. `Tour` / `CoachMark` dismissable by keyboard alone. `IconButton` triggers must carry `label` (enforced by §1.4).
- **§0.3 Colour / dichromacy** — Status-tinted dialogs (compliance warning) must pair colour with `Status` (§1.6) icon in header, not colour alone.
- **§0.4 Responsive** — Dialog default max-width `sm`; `Drawer` default width `md`; both collapse to fullscreen on `< 480px`.
- **§0.5 Hover intent** — `Tooltip`, `ToggleTip`, `HoverCard` default to `HoverIntentType.standard` (400/200ms) per §1.1.
- **§0.8 Patches** — N/A for this section (overlays are UI shell, not commit surfaces).

## 7. Open questions

1. **`InfoAffordance` — IR-level variant or factory-only?** Factory-only. Keeps the variant count low and makes renderer dispatch unnecessary. Trade-off: richness is lost from serialised IR, so tooling can't later introspect "which affordances are `structured`". Revisit if analytics needs it.
2. **`Tour` target resolution** — CSS selector vs a registry of `data-tour-target="id"`. Prefer the latter in docs (stable across refactors) but accept arbitrary selectors to cover app-owned DOM.
3. **`CommandPalette` fuzzy weighting** — cmdk's default is lexical; we can tune via `keywords` arrays but not override the algorithm. Accept the default; revisit if users report missed matches.
4. **`CoachMark` stacking** — if multiple CoachMarks target distinct elements and all are un-dismissed, which shows? Policy: show the first one whose `showOnce` key is absent from `State.bind`; others wait. Document.
