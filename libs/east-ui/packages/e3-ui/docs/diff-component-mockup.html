Diff — visual mock

Three flow-states for sign-off: staged-only (no conflicts), conflict mode (server moved underneath), and resolved-and-ready-to-apply. Tokens mirror east-ui-showcase/theme/index.ts; brand mid is Elara teal #488e97.

Developer DX

Bind once, write to staging, surface for review. Single-line at each step. 

// Inside Reactive.Root in the host:
const policy   = $.let(Data.bindStaged([PolicyType],   policyInput.path));
const schedule = $.let(Data.bindStaged([ScheduleType], scheduleInput.path));

// Inputs use the staged handles like Data.bind:
Slider.Root($.let(policy.read().maxWeeklyHours), {
    onChange: hrs => $(policy.write({ ...current, maxWeeklyHours: hrs })),
});

// Surface for review:
Diff.Root({
    staged: [policy, schedule],
    onCommitted: $ => $(Toast.emit({ title: "Saved" })),
});

Notes for the reviewer

  • Card border becomes orange in conflict mode — single visual signal that "this needs attention before you can apply".
  • Conflict-row primitive is its own visual primitive, not just a tinted regular row. Three-column chooser layout (yours / theirs / manual). Selected option highlighted with brand teal.
  • Auto-merged rows are marked ("auto-merged" annotation on the path) so the user sees the system did work without their input.
  • Apply is disabled while conflicts pending — explicit "(resolve conflicts first)" hint keeps the user oriented.
  • Discard works in any state — including conflict mode. Clicking Discard drops the staged buffer regardless of server drift.
  • Buffer is localStorage-backed — reload survives the same scene; conflict detection re-runs on every Apply attempt.
  • Manual resolution UI — clicking "Manual" in the chooser pops an inline editor matched to the leaf type (Number input for IntegerType, etc.). Out of scope for this mock pass.
