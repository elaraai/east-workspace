Frame

Who this is for

The user is a frontline business decision-maker — demand planner, store ops lead, buyer, scheduler, category manager, pricing analyst, brand manager, account lead.

User · context 5–15 min/decision · queue dozens-to-hundreds/wk
  • 5–15 minutes per decision · queue of dozens-to-hundreds per week
  • Carries private information the model can't have
  • Accountable for outcomes
  • Has a boss, peers, downstream consumers
  • Years of domain judgement
Job: commit a defensible decision quickly that combines what the model knows with what they know.

Configuration surface
mode · timeseries · scatter · ranked-bars · range · area. Picks the geometry; everything else overlays onto it.
series[] · 1–N data series, each with a role (primary · comparison · baseline · target) and a visual (line · bar · band · point). Role drives colour token + z-order; visual drives geometry.
overlays[] · decorations layered onto the geometry: forecast-band · p-envelope · target-line · threshold-band · divergence-shade · residual-band · y-equals-x · now-marker · end-marker · annotation.
anchors[] · named reference points used by range mode (likely · plausible · extreme) or arbitrary ({at: 0.95, label: 'SLA'}).
emphasis · which role carries the lede; others render in muted ink. Default primary.
legend · slot for Slice.Legend; rendered below the frame, never inside the plot.
Behaviour · invariants
Single colour vocabulary across all modes — primary uses var(--brand-d), comparison uses var(--ink-3) dashed, baseline uses var(--ink-4), bands use var(--brand-tint). Never invent palette per chart.
Axis ticks are var(--font-mono); gridlines are dashed var(--rule); no top or right axis line.
No internal legend. Legend is always external — composes with Slice.Legend if needed.
Brushable / scrubbable when mode: timeseries; selection emits a range that other patterns (e.g. Cause.WhyThis) consume.
Click on any series or annotation opens its own drilldown — common pairing: overlay: residual-band drills to Trust.AuditTrail; overlay: forecast-band drills to Cause.WhyThis.
No standalone "chart" patterns elsewhere in the spec. Attention.Forecast, Predict.BaselineVsAction, Predict.OutcomeRange, Track.ActualVsPredicted, the bar visual in Cause.DriverList are all instances of Signal.Chart, configured per use.

§ 2.4

Compare

Anchor · Scenario.Diff · Diff.View

Two states, side by side. Pending vs current. Yours vs theirs. This run vs last. Nothing commits silently — the diff is the receipt.

Compare-mode contract

  1. Every commit shows its diff first. No write-through. The user sees the leaf-level before/after before Apply runs.
  2. Server moves during your edit. If state changed under you, the diff becomes a conflict — three-up resolver, apply blocks until resolved.
  3. Numbers are always old → new. Red strike on the left, green on the right. Direction never flips by context.
  4. Discard is one click; apply is two for irreversible. See Stakes.Tag.
Diff.View Anchor

The staged-changes tree. Every pending edit, indented by path, with the leaf showing old → new. This is the canonical pre-commit surface — used by Commit.Bar, Recommendation.WhatChanged, and any batched edit panel.

§ 2.6

Frame & trust

Anchor · Trust.Journal

The connective tissue. Every decision the operator takes, every model output that gets cited, every roster that gets published — they all carry provenance. Frame & trust is where the system answers who, when, on what basis, with what assumptions. Without it, every other mode is just opinion.

Frame-and-trust contract

  1. Every output is stamped. A Trust.Stamp shows model version, run time, input hash, and confidence band. No headless numbers.
  2. Every change is journaled. A Trust.Journal entry captures the actor, the rationale, the diff, and the run it was made against. Append-only.
  3. Staleness, partiality, and drift are surfaced — not hidden. Banners fire when a source goes stale, a feed drops, or the world has changed since the operator last looked.
  4. Communication is part of the system. Handoffs, message-stubs, and reviewer comments live in the same surface as the decision.
  5. Permission is positive. If an operator can't take an action, the gate explains why and routes to whomever can.
Trust.Journal Anchor

Append-only log of every consequential change. Each entry is timestamped, attributed, and linked to the run, diff, and rationale. The system's memory of what happened, who decided it, and why.

Cross-cutting conventions

Rules that apply across every mode. The grammar that makes the system feel like one product instead of seven.

Conventions

  1. Numbers are tabular-nums. Every numeric column aligns. Use var(--font-mono) with font-variant-numeric: tabular-nums.
  2. Dirty state is brand-tint, never red. Red is reserved for negatives and constraint breaches.
  3. Every chart caption. No naked axis. Caption format: [metric] · [unit] · [scope] · [time].
  4. Hairline rules separate, cards group. Don't nest cards. Use .rule-hairline within a card.
  5. Every output stamps. A model number without a Trust.Chip nearby is a bug.
  6. Every consequential action commits. No silent writes. Commit.Bar at the bottom; rationale captured.
  7. Every banner names the route. "Forecast stale" with no refresh → action is half a banner.
  8. Diff before apply. No write surface bypasses Diff.View. The operator sees what's about to change.
  9. Eyebrow rows orient. Every frame's first row is an .eyebrow-row: label left, meta right.
