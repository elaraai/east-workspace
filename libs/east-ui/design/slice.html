§ 2.2

Slice

Anchors · Slice.Frame · Slice.Edit

The data-narrowing primitive. One SliceHandle<T> per data domain, bound once at the surface boundary; affordances around it write, consumers around it read narrowed data through Slice.apply.where. Slice doesn't render anything that shows the data — that's the consumer's job (Table, Chart, Stat). The architectural rules live in §1.5c · Slice composition; this document specifies each affordance, the container that holds them, and the shared edit overlay.

Slice.Frame Anchor

The card that holds a slice-bound visual. A frame role specialised for slice consumption — same chassis as §1.5b · Frame, but with a fixed three-zone anatomy and an opinionated derived-count footer. Every slice consumer (Table, Chart, Stat) is wrapped in one; if there is more than one slice on a page, there is more than one Slice.Frame. The author fills the body slot with the visual; the eyebrow and footer take care of slice chrome.

Zone rules: Eyebrow — a reflowing affordance bar. Each listed affordance is an icon-led, labelled block (Filter · Split · Cohort · Range · Search), in the order given — no placement-by-kind. When the blocks fit, they sit in one inline row (min height 44 px); when they don't, the bar reflows to stacked labelled rows (a fixed mono-label gutter + the affordance's controls) — nothing is hidden behind a menu, every affordance stays visible and one click from editing. Derived meta (freshness chip, count) and the collapse toggle pin to the right. The bar is collapsible (collapsible, default on): the chevron folds the eyebrow to a one-line summary of the active narrowing and back. The only per-affordance overflow is within a block — a Filter with too many clauses collapses its tail to +M more (its own list). Padding 8 / 12 px. Body — the consumer renders here. The frame supplies no padding; the consumer manages its own gutters. Body content may wrap to multiple rows; a body wrap never re-flows the chrome. Footer — derived count by default, supplied by the frame from Slice.apply.where(...).length. Author can override with a custom node (Slice.Summary, Provenance, paging). Hide with footer={none}; never display "0 rows" without context. Footer height 38 px · paper-2 background.

Invariants: One Slice.Frame per slice. If two slices share a page, they get two frames. The page Header (page-wide Scope.*) is not part of the frame chassis. The frame never grows or shrinks when an affordance opens an editor. Editing happens in a Slice.Edit popover over the body; the chassis stays the same height. This is non-negotiable — see the next pattern. The body reads slice; the body doesn't author slice. A Table inside a Slice.Frame may render sort arrows that write to slice.setSort, but it never opens a filter editor on its own — that's the eyebrow's job. The body produces clicks; the eyebrow houses the affordances that consume them. Variants: Slice.Frame.Compare — two side-by-side frames sharing one slice with different ranges (see Stat.Comparison). Slice.Frame.Embed — chrome-less variant for embedding inside another container (no eyebrow, no footer; only the body slot survives). Used when the parent owns the slice affordances.

Slice.Edit Anchor

The single overlay shape used everywhere a compact slice affordance needs more room to edit. Anchored to its trigger, fixed width, scrolls internally, dismisses on Apply / Cancel / Esc / click-outside. Replaces every "expanding inline panel" pattern — the eyebrow never expands to host the editor and the body never shifts. One overlay shape across six interactions: edit a filter predicate · open the filter +M more list · edit a breakdown dimension · open the breakdown +M more list · edit a cohort predicate · pick a custom range.

Anatomy: Head — one row, mono label naming the edit target, close × right. Body — the editor. Max-height 50vh; only the body scrolls (head + foot stay pinned). Padding 12 / 14 px; gap 10 px between clauses. Foot — left slot for the contextual link (Save as cohort → for Filter/Breakdown, Remove cohort for Cohort edit, omitted for Search/Range/+M more lists). Right cluster is the action grammar — see the table below. Anchoring — popover sits directly below the trigger by default; flips above if the trigger is near the viewport bottom. Arrow points at the trigger. Width 320 px default · 360 – 480 px for predicate editors; never auto-fits. Dismissal — Esc · click outside · Apply · Cancel. Apply commits the edit through the slice handle; Cancel discards. The body underneath the popover does not redraw until Apply.

Invariants: One popover shape. Every Slice.Edit case uses the same head + body + foot anatomy. Only the foot's action grammar varies — listed above. Never resizes the parent. The popover floats over content; opening it does not push the body down. If the popover is taller than the viewport, the body scrolls internally; the chassis below stays in place. Body underneath is non-interactive while open. Click outside dismisses. We do not scrim or grey the body — the operator can still see what they're narrowing — but pointer events on the body are gated until dismissal (or Apply commits). Apply is the only commit path. Edits aren't persisted to the slice handle on every keystroke. Esc / Cancel / click-outside discards. This avoids a half-edited filter writing intermediate states to the consumer. Save as cohort is the only escape hatch for "this filter set is becoming a cohort." It appears in the Filter foot when ≥ 2 clauses are active; clicking opens a small overlay-on-overlay to name and save.

Slice.Filter

Faceted filters that compose into a Patch over the slice handle. Active clauses render as brand-tinted chips; dashed "+ filter" chip opens the field/op/value builder in a Slice.Edit popover. Two densities: compact for use in a Slice.Frame eyebrow, focused for the standalone configuration surface.

Compact · in a frame eyebrow
One row, never wraps. 4-chip inline cap with overflow → +M more opening Slice.Edit. The eyebrow's right zone owns the search.

Overflow: inline cap 4 chips; 5th+ collapses to one +M more chip → Slice.Edit popover with the full list, per-row × and edit, footer Save as cohort → + Clear all. Collapsed clauses stay semantically active. In a half-width column the cap drops to 2 (compress ladder, see §1.5c). Editing: chip click opens Slice.Edit anchored to that chip; the editor lets the user change op or value (not field — that needs a new chip). Apply commits; Cancel discards.

Slice.Cohort

Saved-segment pill. The compact form is the only thing that appears inline — a single brand-tinted pill in the Header (Scope.Cohort role) or the eyebrow. The focused form — predicate editor with clauses + Apply/Remove — lives entirely inside Slice.Edit, never inline. This is the headline shift: cohort edits no longer push the body down.

Slice.Legend

Inline rail of swatch + label + value + visibility toggle for a chart. Single density — Legend is always a horizontal row beneath its chart; it has no compact pill form. Overflow aggregates excess series into a single "Others" line.

enterprise42.1% pro28.4% growth14.8% team6.3% solo3.2% trial1.6% Others 3.6% · 44 series

Overflow: cap 6 series inline. Series 7+ collapse into one "Others" entry — and the chart aggregates those series into one dashed ink-4 line. Click Others to expand the legend; the chart un-aggregates. This is the only Slice.* that aggregates data on overflow. No compact density. Legend is always inline beneath the chart it labels. The body wrapping rule applies — legend rows may wrap to multiple lines when narrow.

Slice.Summary Recipe

A one-line recipe composing the slice's active narrowings into a single inline summary. Used as a footer in a Slice.Frame, or as page-context in a Header. Not a primitive — a composition of count + filter chips + clear-all link.
