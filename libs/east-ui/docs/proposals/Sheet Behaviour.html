Sheet — a declarative planning sheet

A generalised spreadsheet component. The host supplies a data source (rows), a declarative column schema, and registers (lookup tables); the component supplies typed parsing, inline autocomplete, directed link cells, a copilot that fills and proposes rows, search with context bands, saved-view tabs, and Excel round-tripping. Nothing in the component knows about the plant. Every plant value in this document is an example of what the schema has to be able to express, taken from the BX2 · C26 configuration the prototype runs.

Source of truth: Sheet Spec.html (the interactive prototype) · 8 Sep 2026 · every rule below is implemented there unless marked host-supplied (still hard-coded in the prototype, to become configuration). The east-ui mapping — IR, factories, JSX, renderer — is Sheet Spec.md.

1 · Contract

The prototype is a controlled React component. It renders from rows and reports every mutation; persistence, sync and the upstream system (example the plant MES) are the host's.

PropMeaning
rowsArray of records keyed by column key, plus a stable id. Empty strings mean empty. The component pads the sheet with blank rows (§7) but reports only real rows back.
columnsOrdered column declarations (§2). Each names a type from the type registry and parameterises it.
typesOptional overrides/extensions of the built-in type registry (§3). A type declares how a cell parses, displays, ghosts, how long it waits before suggesting, and whether it can be edited.
registersNamed lookup tables: { name: rows[] }. A register row is an object with a display key and any extra fields declarations may point at. example activities, vessels, farms, groups, sites, statuses.
driverThe lookup column whose register row parameterises the rest of the row — units, durations, direction. Other declarations reference it by path (driver.days, driver.uom, driver.sides). example Activity.
suggestCopilot configuration (§5): fill providers per column, row patterns, learning on/off, lookahead. ghostEnabled and suggestAhead are surfaced as tweaks.
ownedPredicate marking rows the host system owns (no copilot, stamped columns read-only). example row.orderCode || row.status === 'CANCELLED'.
onChange · onCommitonChange(rows) after every mutation; onCommit(rowId, key, value, source) per cell with source ∈ typed · pasted · fill · row · pattern so the host can measure copilot uptake.
views · onViewsChangeSaved-view tabs (§8) as data, so they persist with the plan.
autosave · onAutosaveToggleControlled state for the rail toggle; the component only shows it and stamps the last-saved time.
chromeTitle, breadcrumb and sync status for the app bar — display strings only.

Types are the unit of behaviour. Adding a column never adds code; adding a type does. Latency is how long after the last keystroke a suggestion is rebuilt: instant 150 ms for deterministic lookups, idle 1 100 ms for anything derived from history.

3.1 Candidate scoring (lookup · reference · enum)

Whole-string prefix (0) → every typed word prefixes some word, or any word prefix (1) → initials in order, ≥2 chars (2) → substring (3); ties broken by how often the value already appears in this sheet. Only a prefix match ghosts inline as a grey suffix after the caret. A non-prefix match (alias, fuzzy, range) previews on the right of the editor as a replacement (→ Transfer - Annex) and is taken with Tab. With an empty buffer nothing is armed: the strip lists what the field accepts — for the driver column ranked by what usually follows the row above, then by sheet frequency — and Tab cannot write a value the planner never chose. ⌥] ⌥[ ⌥↓ ⌥↑ cycle the armed candidate.

4 · Link type

A link is a directed hyperedge: two sets with a direction. Each half is a set of members drawn from the column's register; the direction is optional because the driver may declare only one side. The cell always draws both halves once the row has a driver value, so direction is visible without opening anything.

4.1 Member grammar

Typed exampleKind · rule
T2140 · t2140 · 2140identified — register code, case-insensitive; bare digits try the register's prefix. Meta from the register (140 kL).
T2140-45 · 2140-2145range — expands to every register member in the numeric span, short upper bound completed from the lower. A hyphen is a range only between two unspaced bare numbers; spaced, or beside a name, it is an arrow.
2000s · the 2000s · annexcountable by name/alias — leading “the” dropped. Meta farm · 96.
140kL · 140 kl · 140000Lcountable by attribute — a size that exists in the register, not a member. Litres ≥1 000 read as kL.
4 x 140kL · 2000s × 3 · 3*annexcounted member — N x kind / kind x N with the declared ops, countable kinds only. Label 4 × 140 kL, meta unassigned, carries n and of. A trailing qualifier (“… tanks south”) becomes its own text token. Multiplying an identified member is kept as text with the reason.
TBCplaceholder — dashed chip.
anything elsetext — kept as typed, dashed. Entry is never blocked.
, · > -> => → “ - ”Comma separates members in a half; any arrow form separates From from To.

4.2 Sides, locks and storage

  • Storage is the typed string: a > b both halves · b destination only · a > source only. A single set with no arrow is always the destination, so existing single-set data migrates without edits.
  • The driver row's sides value selects the live halves: both · from (To locked) · to (From locked) · in (From locked, divider drawn as a minus). No driver, or a driver without sides: both live. Lock labels come from sides.locks — example “external”, “in place”.
  • A locked half is never predicted into and Tab skips it, but typing into it is allowed: the content is kept and the lock tag turns warn — a flag, not a block.

4.3 Display

  • Grid minmax(0,1fr) 16px minmax(0,1fr) inside the cell's 10px padding. Halves stretch to one height and top-align; the arrow sits on the first 20px line. Blank rows show nothing; rows with a driver value always show the structure.
  • Chips: mono 10.5px, paper-3 fill, 1px rule, radius 4, padding 1px 4px, 4px gaps, wrapping. Register meta appears only when a half holds a single chip. Dashed = text, placeholder, or a copilot proposal.
  • Empty live half: faint mono label FROM / TO (8.5px 600 ink-5), From right-aligned against the arrow. Locked half: the same label as a paper-3 tag, warn-tinted (8% wash) when it holds content.
  • Proposals render as dashed chips in the correct halves over the proposal hatch; hover shows the ✓ take button.

4.4 Editor

The editor overlays the cell at the cell's height (grows if chips wrap), 2px brand ring, no fill. Both halves are drawn; the active half carries a 1.5px brand underline and the only input. The caret opens in the first live half that is still empty, else the destination. Existing content becomes chips; typing a first character from the grid replaces the content (spreadsheet convention).

KeyBehaviour
,Resolves the buffer to chips in the active half; keeps typing.
> (any arrow form)In From: resolves the buffer and hops the caret to To (flagged in the footer if To is locked). In To: dropped.

4.5 Autocomplete and prediction

  • Candidates: exact identified code → identified codes by prefix when the input looks like a code → countable names/aliases, each followed by an enumerate alternative listing its free identified members → identified codes by prefix otherwise → other countables → placeholder. Members already in the cell are never offered twice. A range shows one candidate: its expansion.
  • Inline ghost is the top prefix candidate's suffix (t2140). No candidates: the strip states the grammar and keeps the text.
  • Prediction runs only while the buffer is empty, per half, never into a locked half: the last row with the same driver value → its members normalised through the register; else the counted form n × unit where n = ⌈arity.from ÷ per⌉ (example ⌈vol ÷ 140 000⌉ · Tk drivers n = vol · Drm none · cap 12). Dashed after the input; the strip lists them with an enumerate alternative naming that many free members. Once a half has named members the count proposal is withdrawn. For from-only drivers the proposal lands in From.

4.6 Arity

While the arity.of half is being edited the strip meta reads 4 × 140 kL implied · 3 named so far — never inside the cell. Named = each identified member once, a counted member by its count; text and placeholders do not count. Fewer than implied: named so far; more: more than the volume needs; equal: named.

5 · Copilot

Suggestions are rebuilt against the row as it would be if the open editor committed, after the type's latency. Rows matching owned are never touched; nothing is proposed into an occupied slot.

5.1 Fill providers

Each column may name a provider; the first that yields wins, and its provenance is shown in the strip. Fills render as grey ghosts over a brand hatch (135°, 7% brand, 6px period). Exactly one cell is the next Tab target (1.5px dotted brand underline). Hover shows an 18px ✓ take button; the anchor row's gutter shows → fill this row (⌘⏎).

5.2 Suggested rows

  • Patterns (host-supplied): { when(row), rows(row) → [{ activity, start, end, vol, notes, … }] }. example Bulk Blenders → media add + packdown at end +3…+7 d; Xflow with “annex” → transfer to the annex, then back a week later.
  • Learned followers (built in): the driver value that most often followed this one in the sheet (rows sorted by start, gap 0–60 d), placed at the average gap with that follower's last quantity and notes · Transfer followed Xflow 3× in this plan · +7d. Used when no pattern matches.
  • At most suggestAhead rows (default 2), rendered as dashed-topped hatched rows under the anchor with real row numbers. Gutter: ✓ adds (⏎ when selected), × rejects (⌫) and remembers the pairing so it is not offered after that driver again. Click selects (3px brand bar); esc deselects, esc again dismisses all. Taking a row re-anchors and looks forward so the next is already waiting.
  • Rejected fills are remembered per row and key; ⌫ on the armed target rejects just that cell.

7 · Sheet model

  • Eighteen blank rows are always kept below the last real row (blanks, tweakable) and never removed from under the cursor. Blank rows are padding: not reported, not counted, not searchable.
  • Footer counts are host expressions over rows — example planned = non-blank, ready = driver + start + qty and not owned, cancelled = status.
  • Row numbers are real sheet positions, also under filters and for suggested rows.

8 · Search, context bands, tabs

  • Search: case-insensitive substring over every column's display text. Hits keep their row number in brand; the count reads 4 matches · 6 context.
  • Context ±0 / ±1 / ±3 shows rows either side of each hit. Everything else collapses into a band: 22px, dashed rule, n hidden pill. Hover opens ⌃ +1 · n hidden · +1 ⌄ · all; each click reaches further (1, 3, 10, all) from the top, bottom, or both. Reveals are a set of row indices, so overlapping bands merge and the counter keeps its anchor. Changing the query resets reveals.
  • Tabs are lenses, never copies: a tab saves the search definition (query, context, reveals) and is evaluated live, so new matching rows join it and edits anywhere write to the sheet. The first tab is the whole sheet, pinned, with the planned count. + TAB saves the current view (named from the query, 16 chars, or view n when empty — search inside it and ⏎ scopes it). Active tab: 2px ink underline; live mono match count on each. Editing the query in a tab marks it dirty (brand dot): ⏎ updates, esc reverts; esc on a clean tab returns to the sheet. × (hover neg) or middle-click closes; double-click renames; drag reorders; closing the active tab falls back to the sheet. Leaving a tab persists its context and reveals and discards an unsaved query.

10 · Clipboard and autosave

  • Copy: tab-separated; dates d/m/yyyy, numbers bare, a link cell as two columns (From, To) — destination-only leaves From empty.
  • Paste: lands at the selection, appending rows as needed; each cell parsed by its type (unparseable kept as typed); stamped columns skipped; a link column consumes two clipboard cells and joins them (a > b · b · a >; a lone cell as typed). The block is left selected; suggestions cleared.
  • Autosave: 30px icon toggle — on = pos cloud-arrow-up, every mutation stamps a save time; off = ink-5 cloud, changes held locally. Tooltip carries state; the footer confirms each toggle.

13 · Still hard-coded in the prototype

  • Fill providers sequence, default, phrase and the four row patterns are functions in the component — to move behind suggest. (In the east-ui design these become East-function providers: see Sheet Spec.md §4.)
  • The count unit for capacity predictions (140 kL) and the per-uom arity rules (Tk = count, Drm = none, cap 12) — to become arity.per resolution against the register plus a per-uom map on the driver.
  • Register shapes are static arrays; registers should accept the same shapes from the data source. Footer counts and the sync status are strings the host will own.
  • Declared but not evaluated: check entries other than exists; store:'canonical'; showRegisterMeta.
