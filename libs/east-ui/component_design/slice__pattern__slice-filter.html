Slice.Filter

Faceted filters that compose into a Patch over the slice handle. Active clauses render as brand-tinted chips; dashed "+ filter" chip opens the field/op/value builder in a Slice.Edit popover. Two densities: compact for use in a Slice.Frame eyebrow, focused for the standalone configuration surface.

Compact · in a frame eyebrow
One row, never wraps. 4-chip inline cap with overflow → +M more opening Slice.Edit. The eyebrow's right zone owns the search.
event=checkout basket≥£50 +13 more filter
Search events… /
At this width the compress ladder kicks in: chip labels truncate (full → field/value only), and the inline cap drops to 2. Same compact pattern at full Slice.Frame width would show 4 chips before +M more.
Focused · standalone
Same chip rail, plus a summary footer with the resolved count and a Save view link. Use only when filters are the surface, not a control on top of one.
scenario = procurement v3 × region in EU,NA × date = last 30d + add filter
Showing 1,284 events Save view →

Overflow: inline cap 4 chips; 5th+ collapses to one +M more chip → Slice.Edit popover with the full list, per-row × and edit, footer Save as cohort → + Clear all. Collapsed clauses stay semantically active. In a half-width column the cap drops to 2 (compress ladder, see §1.5c). Editing: chip click opens Slice.Edit anchored to that chip; the editor lets the user change op or value (not field — that needs a new chip). Apply commits; Cancel discards.
