WiringStory is state. The rail is a writer; everything else may read.

Same idiom as Stat.Layout: the narrative position is one ordinary state binding — an IntegerType index, usually from State.bind, but anything exposing read/write closures works. There is no bespoke handle and nothing to bind when you don't need it: omit the prop and Story keeps the state internal. Pass it only when something outside the story must read or drive the position — then it behaves like any other state: readable in any <Reactive>, writable from a Button three components away, snapshot-able, deep-linkable.

// One legal program: $.const / $.let exist only inside an East.function
// builder (orderRows / uplift: raw row data).
const QuarterReview = East.function([], UIComponentType, ($) => {

  // 0 · Rows are typed once. Every field reference below — chart accessors,
  //     Table column keys — is checked against this struct, exactly as in
  //     Table / Chart today. Story adds no stringly-typed data surface.
  const Order  = StructType({ week: IntegerType, actual: FloatType, forecast: FloatType });
  const orders = $.const(orderRows, ArrayType(Order));

  // 1 · OPTIONAL — plain State bindings. Omit the props and Story manages its
  //     position internally; bind only when other surfaces must read or drive
  //     it (same idiom as Stat.Layout's selection).
  const active = $.let(State.bind([IntegerType], "q4-review.step", 0n));
  const scrub  = $.let(State.bind([FloatType],   "q4-review.progress", 0.0));

  // 2 · Shared layers are plain build-time values — declare once, reference
  //     from several keyframes. The renderer tweens series matched by name.
  const actual   = Chart.Line(orders, { x: d => d.week, y: d => d.actual },   { name: "actual",   color: "teal.solid" });
  const forecast = Chart.Line(orders, { x: d => d.week, y: d => d.forecast }, { name: "forecast", color: "gray.solid", dash: "4 3" });

  // 3 · Steps are children. <Story.Step> is a real component — its children
  //     are the rail body, its stage prop is the keyframe (a UIComponent
  //     prop, same shape as Dialog's trigger). The renderer routes bodies →
  //     rail and the active stage → the sticky slot, like Tabs shows one panel.
  // 4 · Anything can read or drive the position — it's just State. A write
  //     from outside is navigation: the rail smooth-scrolls to that step.
  return (
    <VStack gap="6">
      <Story active={active} progress={scrub} layout="rail-left" stageHeight={420} stepLength="default"
             onStepEnter={East.function([StringType], NullType, ($, id) => { … })}>
        <Story.Step id="demand" eyebrow="Demand" title="Demand ran hot"
                    stage={<Chart layers={[actual]} grid />}>
          <Text>Orders climbed from week 6 and never gave the gain back…</Text>
          <MetricChip sentiment="pos">▲ +34% vs start of Q4</MetricChip>
        </Story.Step>
        <Story.Step id="forecast" eyebrow="Forecast" title="The plan missed the turn"
                    stage={<Chart layers={[actual, forecast]} grid legend />}>
          …
        </Story.Step>
        <Story.Step id="promo" eyebrow="Cause" title="One event explains the spike"
                    stage={<Chart layers={[actual, Chart.refDot({ x: 8n, y: 1010, label: "promo live" })]} grid />}>
          …
        </Story.Step>
        <Story.Step id="regions" eyebrow="Where" title="The gap wasn't uniform"
                    stage={<Chart layers={Chart.Bar(uplift, { x: d => d.region, y: d => d.orders, by: d => d.half })} grid legend />}>
          …
        </Story.Step>
      </Story>
      <Reactive>{$ => {
        const i = $.let(active.read());
        const next = $.const(East.function([], NullType, $ => { $(active.write(active.read().add(1n))); }));
        return <HStack gap="3">
          <Text>{East.str`Reviewing beat ${i.add(1n)} of 4`}</Text>
          <Button onClick={next}>Skip ahead →</Button>
        </HStack>;
      }}</Reactive>
      <Story.Progress active={active} count={4} />
    </VStack>
  );
});
Binding contract: active — IntegerType read/write closures. The scroll driver writes it as steps cross the trigger line; an external write is treated as navigation — the rail smooth-scrolls that step to the trigger line, then resumes observing. Reads track dependencies inside <Reactive> like any other state. progress — optional FloatType binding, 0–1 through the active step. Written by the scroll driver only; consumers read it for scrub effects and never write it. Defaults — omit both and Story manages internal state; the component is fully usable with zero wiring. No Story.bind, no handle type — there is nothing to learn beyond State.bind.
DX rules: Steps are children. <Story> is a children-taking container like ChipRail / Stack, and <Story.Step> is a real component — a UIComponentType variant arm carrying id / eyebrow / title, its children as the rail body, and its keyframe on the stage prop (a UIComponent prop, the established Dialog.trigger shape). The contract "children must be Story.Steps" is soft, exactly like ChipRail's chip-shaped children — the renderer skips non-step children with a dev warning. Routing and branching live in the renderer. Children are runtime values, so Story's renderer — not the IR builder — walks them: bodies render in document order in the rail, the active step's stage renders in the sticky slot, and the switch on the active index happens at render time, the way Tabs' renderer shows one panel. Authors never write the switch; and because steps are values, a conditional step (cond.ifElse(<Story.Step…/>, <Story.Step…/>)) is legal. Inference is inherited, not reinvented. Keyframes are plain <Chart> / <Table> values, so the existing typed surfaces apply unchanged: chart encodings are typed accessors (d => d.week) checked against the row struct, Table columns are keyed by the row's fields (ColumnSpec generic), and shared layers are ordinary build-time consts reused across keyframes. The only strings Story itself introduces are the per-step ids, used for deep links and snapshot names; because steps are runtime children, activeStep is a plain StringType (no static key union — the accepted price of the children form). East-function handlers — onStepEnter / onStepExit(id) fire on transitions in either direction; use for analytics, prefetching a heavy keyframe's data, or pinging a sibling surface. Scrub is just Reactive. A keyframe that wants scroll-locked effects wraps its subtree in <Reactive> and reads the progress binding — no new mechanism. Standalone chrome — <Story.Progress active={active} /> mounts anywhere (a page header, a Drawer foot) because it shares nothing with the Story but the binding.
Static & pipeline: activeStep="promo" — overrides scroll, renders one deterministic keyframe; the snapshot pipeline emits one PNG per step (story/q4-review/demand.png, …). Deep link — #story=q4-review/promo writes the active binding on mount and scrolls the step to the trigger line. Print — linearizes: each step renders full-ink with its keyframe inline below it; the spine becomes the left margin rule.
