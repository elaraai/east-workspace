Wiring · in code
const events = Slice.bind<Event>("events.q4", eventsConfig);

// All affordances share one handle — no callbacks wired by hand.
<Slice.Range slice={events} />                // header
<Slice.Cohort slice={events} saved={[...]} />   // header / sidebar
<Slice.Filter slice={events} />               // table-frame eyebrow
<Slice.Search slice={events} matches={...} />   // table-frame eyebrow
<Slice.Breakdown slice={events} />            // chart-frame eyebrow
<Slice.Legend slice={events} series={...} />    // inside chart body

// Two consumers, one handle. Both call Slice.apply.where internally.
<Collections.Table slice={events} data={allEvents} columns={[...]} />
<Chart.Line        slice={events} data={allEvents} y={count} x={day} />
Reading the example: Header carries page-wide narrowing — a 90-day Range and the power-users cohort. Both narrow every frame below. Table-frame eyebrow carries per-table narrowing — chips for event_name = checkout_complete and basket_total ≥ £50, plus a search. These narrow this one Table. Chart-frame eyebrow carries per-chart narrowing — Slice.Breakdown splits the series by device. Same handle, a different per-frame slice on top. Both consumers share the slice — Table renders Slice.apply.where(...) as rows; Chart.Line renders the same call as a series. Edit a header chip and both frames redraw. The chart's android series is dimmed because the Slice.Legend visibility toggle is off — a per-visual override that doesn't mutate the slice. Column-header filter glyphs on event_name and basket_total reflect the active filter set — visible because the slice has predicates on those fields, not because the Table authored them. Row count is derived — "4,218 of 12,840" is Slice.apply.where(...).length, not a host-tracked number.
