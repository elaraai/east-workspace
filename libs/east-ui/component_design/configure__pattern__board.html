Collections.Board

The single-day assignment board — the transposed sibling question to Roster: not "what is each person's week?" but "who is in each area, on each shift, today?" rows = areas, columns = the day's shifts, and each cell holds multiple people as chips in the shared event-state grammar (committed / proposed / rejected — see Planner). A DnD target pairing with Library via sources. Optional requirements add per-cell coverage: n/required numerals with under / over tones, and dashed ⊕ open-slot placeholders (drop hints doubling as onAddAt targets). maxVisible collapses long cells behind a +N overflow popover. Grips appear on proposed chips only — committed chips are pointer-immutable; published mode renders committed-only. Every gesture funnels through onDrag; no drop writes directly. The component bakes in no user-facing copy — every string it shows is data (labels / sublabels) or a prop (summary, areaHeader); what it renders itself is numerals, glyphs and tones only. Toolbar chrome (edit toggles, add buttons, captions) is page composition — host-authored, deliberately not part of the component.

Drag & drop Supports add (from a sibling Library) · move (between cells; from.event names the assignment) · remove (drag to trash or back to the Library). No resize — assignments are point events. Dropping a person onto a cell that already holds them — or one a host canAssign(person, area, shift) predicate vetoes — is an invalid target: red outline + ⊘ while dragging, and the drop is a no-op (same-person-in-different-cells stays legal — host policy). Cross-area moves are plain move events; swap policy is host-derived → Communicate.Swap. Cells the requirement leaves open render dashed ⊕ open placeholders that highlight as drop hints.
