Composition rulesHow Decide relates to Configure, Slice, Scenario, and Trust.
  • Decide owns the canvas during a decision. The decision context — case-id, current scenario, judgement state, alternatives — lives on the Scenario.Briefing surface and never leaves it. The operator can probe, compare, even open a sub-popover, but the briefing chassis stays put.
  • Configure provides primitives, never owns the canvas during a decision. Lever.Slider, Input.Assumptions, Cause.SupplyDemand, planner cells — all designed to be embeddable in compact density inside Scenario.Probe. Configure as a destination mode still exists, but only for global policies and defaults that aren't tied to a single decision.
  • Modify in Commit.Bar opens Probe in place. Never navigates to Configure mode. Re-flowing the briefing to expose 2-3 load-bearing controls is the right shape — the operator's muscle memory for the case stays intact, and the re-solve happens against the same DecisionHandle.
  • Back-edges are first-class, not undo paths. Returning from Probe to Understand is a deliberate operation that snaps the briefing to its post-tweak state, not a navigation-back. Compare → Commit skips re-judgement only when the operator has already attested to the load-bearing inputs in step 5. The renderer enforces these transitions through the DecisionHandle's state.
  • One DecisionHandle per case. The handle carries the case-id, the active scenario (which is itself a ScenarioHandle), the judgement-prompt answer, and the commit state (clean / dirty / applied / overridden). Every step reads it; only certain steps write specific fields. Like SliceHandle and ScenarioHandle, it binds once at the surface boundary.
  • Slice and Scenario compose underneath. A Decision.Queue uses a SliceHandle to narrow which cases the operator sees. A Scenario.Briefing uses a ScenarioHandle to choose which proposed future is in play. Decide doesn't replace these — it sits on top of them. Editing a slice doesn't dirty the decision; switching the scenario does.
  • Trust journal entries record back-edges. Every Probe edit, every Compare swap, every Override is journalled with the case-id. The audit trail captures not just the final commit but the path through the loop — what was probed, what was rejected, why the operator chose what they did. This is what makes the back-edges first-class rather than disposable.
