Multi-slice pagesWhen one page narrows more than one data domain.

The single-slice case in §1.5c is a degenerate case of the general rule. A page commonly narrows more than one domain — events & errors on a reliability surface; users & events in an explorer; multiple cohorts of the same domain in a comparison. The architecture extends with one new primitive (Scope) and one wiring convention (linked-selection).

Affordance home Scope.* lives in the Header (Range, Cohort, environment, tenant — cross-cutting narrowings). Slice.* lives in its frame's eyebrow (Filter, Search, Breakdown — domain-specific narrowings). An affordance binds to exactly one of Scope or Slice. Never both. Never inferred.

Wiring · in code
// Scope-shared (example A) — one scope, two slices subscribing.
const scope  = Scope.bind("q4.prod", scopeConfig);
const events = Slice.bind<Event>("events", eventsConfig, { scope });
const errors = Slice.bind<Error>("errors", errorsConfig, { scope });

<Scope.Range  scope={scope} />       // header
<Scope.Cohort scope={scope} />       // header
<Slice.Filter slice={events} />      // events-frame eyebrow
<Slice.Filter slice={errors} />      // errors-frame eyebrow

// Linked (example B) — selection bridges two slices.
const selection = State.bind<UserId>("users.selected");
const users  = Slice.bind<User>("users",  usersConfig);
const events = Slice.bind<Event>("events", eventsConfig, {
  linked: [{ from: selection, as: "user" }]   // implicit filter
});
Rules: Scope is one level above Slice. It holds cross-cutting narrowing that every slice on the page subscribes to (range, cohort, environment, tenant). A slice's effective predicate is scope ∩ slice. Affordances bind to exactly one of Scope or Slice. Never both, never inferred. The header carries Scope.*; each frame's eyebrow carries its own frame's Slice.*. If you want to know which handle an affordance writes to, look at its surrounding region. Linked slices share a selection handle, not a slice handle. The master writes a State<Id>; the detail subscribes to it via linked: [{ from, as }]. The detail renders the selection as an implicit chip — non-removable, brand-tinted, fa-link glyph — so the operator can see where the narrowing came from. No silent narrowing across domains. A scope can't filter on a field that doesn't exist in a slice's domain; the renderer warns at bind time. If two slices share a field by name only (e.g. both have user_id), the scope filter applies to both — that's the feature. Multi-slice without scope is fine. If two frames truly don't share any narrowing, omit the scope and put their affordances in their own eyebrows. The header carries no Slice.* in that case — only navigation.
