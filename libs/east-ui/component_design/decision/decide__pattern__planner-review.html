Future — the Collections.Planner has no native approve / reject / approve-all; this is the review chrome that wraps a machine-written roster.

Per-row Approve / Reject at the end of each line — the call sits beside the full week it governs — over a Commit.BatchBar approve-all / reject-all foot.

The optimiser writes the whole plan — the operator approves it, they don’t key in lines. Every line carries its own Approve / Reject at the end of the row, so the decision is made next to the shifts it governs — never in a second list below, which would force the approver to re-find each line. The foot approves or rejects the lot in one gesture. status steers attention — clean lines rest pre-approved, flagged lines (OT threshold, coverage gap, model swing) wait on an explicit call — carried as a quiet dot beside the resource, not a per-cell ring, which reads too busy across a week.
